# keylang

Мова опису архітектури в Markdown, прив'язана до коду репозиторію: згенерована карта, ручні правила та потоки, перевірка відповідності коду. Терміни нижче — канонічні для коду, документації, діагностик і тікетів.

## Language

### Документи

**Map (карта)**:
Згенероване представлення знімка у `keylang/map/*.md`: шари, модулі, функції, залежності. Не є сховищем фактів для перевірки.
_Avoid_: індекс, схема, документація коду

**Explained map (карта з поясненнями)**:
Друге згенероване представлення знімка: те саме дерево, що й карта, але кожен вузол має коротке пояснення з видимим походженням. Не є специфікацією, тож перевірка його не читає.
_Avoid_: анотована карта, документація

**Представлення (view)**:
Вигляд знімка, обчислений для людини чи агента: карта, карта з поясненнями, екран зуму, експорт C4, панель контексту. Ті самі входи дають той самий текст. Представлення не є фактом, тож `check` його не читає; модель воно питає лише за явною командою (ADR 0014).
_Avoid_: вид (у цьому глосарії «вид» — kind: вид вузла, вид ребра), діаграма

**Specification (специфікація)**:
Ручний Markdown-документ, який стверджує щось про код: rules, flows, wiring. Посилається на сутності коду за ID.
_Avoid_: спека як синонім карти, конфіг

**Text IR**:
Розбір Markdown-файлу зі збереженням написаного, токенів і spans; служить парсеру, `fmt` і редактору.
_Avoid_: AST (зарезервовано за деревом вихідного коду)

**SpecIR**:
Специфікації, скомпільовані з Text IR у перевірювані твердження.

**Format version (версія формату)**:
Редакція мови в `keylang.json`, за якою читаються специфікації цього репозиторію. Відсутнє поле — редакція 1.
_Avoid_: формат звіту `check --format`, версія пакета

### Знімок

**Snapshot (знімок, AnalysisSnapshot)**:
Факти про код на певний момент: вузли, експорти, ребра, невизначеність і покриття, з manifest джерел та `snapshotId`. Єдине джерело фактів для карти й перевірки.
_Avoid_: граф (це лише частина знімка), індекс (`.keylang/index.json` — його серіалізація)

**Layer (шар)**:
Названа група модулів, задана глобами у `keylang.json`. Може мати порядок відносно інших шарів.

**Module (модуль)**:
Одиниця коду, що має ID у карті: файл або тека за режимом `module` конфігурації.

**Member (член модуля)**:
Оголошена в модулі сутність: `fn`, `type`, `event`, або alias залежності.

**Opaque module (непрозорий модуль)**:
Модуль, вміст якого знімку невідомий; посилання на його члена не підтверджується і не спростовується.
_Avoid_: порожній модуль (це модуль із відомо порожнім списком членів)

**ID**:
Крапковий шлях сутності від кореня карти, наприклад `application.purchase.buy`, у формі Unicode NFC. Стабільний до змін рядків; посилання зі специфікацій записуються лише через ID.
_Avoid_: символ (це термін SCIP), шлях

**Edge (ребро)**:
Спостережена в коді залежність між двома сутностями з видом (`import`, `call`, `type`, `re-export`), позицією, станом резолвінгу та походженням.
_Avoid_: залежність без уточнення виду

**Coverage (покриття)**:
Облік того, які файли, області та види ребер знімок проаналізував повністю, а які пропустив і чому.

### Твердження та наміри

**Planned (запланований вузол)**:
Явна декларація наміру в специфікації: ID, вид і очікуваний контракт сутності, якої ще немає в коді. Не є фактом знімка.
_Avoid_: TODO, майбутній ID

**Feature (фіча)**:
Рукописний файл `keylang/features/<slug>.md`: `planned`-вузли, потоки й правила однієї зміни, яку має реалізувати людина чи агент. Реалізована, коли файл щось стверджує й читається без помилок специфікації, відкритих питань (`- ? …`) немає, усі її `planned` закрито, кроки потоків мають static `ok` і нових порушень немає. Стадія (`idea`, `behavior`, `structure`, `ready`, `done`) лише обчислюється й показує, як далеко файл зайшов від ідеї до специфікації для агента. Після реалізації лишається як специфікація.
_Avoid_: епік, задача, change set

**Baseline (базові правила)**:
Згенеровані `init` правила `keylang/rules.baseline.md`, що забороняють залежності між шарами, яких у графі ще немає. Людина розширює їх явно; агент — лише через пропозицію.
_Avoid_: snapshot правил, whitelist

**Stale (застаріла проза)**:
Опис, пояснення від моделі або поведінкове твердження, під яким змінився fingerprint описаного коду. Причина перегляду, не доказ хибності.

**Explanation (пояснення)**:
Текст простою мовою про те, що робить вузол, із видимим походженням: коментар документації в коді або модель із датою. Довідка для людини, яка ніколи не впливає на вердикт.
_Avoid_: опис (це рукописний текст під вузлом у специфікації), коментар

**Brief (коротке пояснення)**:
Пояснення в одне-два речення, яке показує карта з поясненнями. Окреме від пояснення на запит (`short` чи `full`).
_Avoid_: summary, анотація

### Інтерфейс

**Gutter (жолоб)**:
Колонка позначок біля рядка специфікації в TUI: `✓` лише коли всі звітовані критерії рядка `ok`, `✗`, `◌`, `!`, `◇` для `planned`, `?` для відкритого питання `- ? …` (не вердикт: питання не твердження, на нього відповідає людина). Окремі види доказів видно в розгорнутому рядку, не в позначці.
_Avoid_: статус рядка як синонім одного вердикту

**Proposal (пропозиція)**:
Повний запропонований текст специфікації або файла коду від зовнішнього джерела (агент, `draft`, MCP; код і тест — `spec-to-code`) у `.keylang/proposals/<шлях>`. Стає змінами файла лише рішенням людини: MERGE у TUI або `keylang proposals accept` (чи явний `--apply`). Ціль специфікації — рукописний `.md` під каталогом специфікацій; ціль коду — вихідний файл мови, яку keylang читає, у межах репозиторію. Згенероване (карта, карта з поясненнями, збережені пояснення моделі, baseline, wiring), файли поза цими межами й шляхи з `..` чи через посилання назовні ігноруються з причиною, однаковою для кожного входу.
_Avoid_: патч, чернетка (чернетка — результат `draft`, M7)

**Harness (харнес)**:
Зовнішній агентний інструмент, що сам редагує файли репозиторію: Claude Code, Codex, opencode, Cursor. Бере контекст із keylang через `AGENTS.md`, MCP і CLI. Не плутати з вбудованим агентом keylang (`agent` у `keylang.json`); той самий харнес може служити йому моделлю — див. «агент-CLI».
_Avoid_: IDE, агент як синонім вбудованого агента

**Агент-CLI (провайдер моделі)**:
Харнес, якого keylang запускає як модель вбудованого агента (`agent: "cli:claude"`, `KEYLANG_AGENT`, `~/.config/keylang/agents.json`): один запит — один запуск у режимі «лише відповідь», без запису файлів, хуків і MCP проєкту. Відповідь перевіряється й записується лише keylang (ADR 0012).
_Avoid_: харнес як синонім (харнес пише код сам), агент-CLI як оркестратор

**Managed block (керований блок)**:
Фрагмент, який keylang пише в чужий файл (`AGENTS.md`, `CLAUDE.md`, конфіг харнеса) між своїми маркерами. Оновлюється ідемпотентно; текст поза маркерами keylang не змінює.

**Hunk (шматок)**:
Суцільна змінена ділянка між файлом і пропозицією; одиниця рішення `a` / `r` у MERGE. Невирішений шматок не застосовується.
