# 31: TUI-редактор і режим MERGE по шматках

**Етап:** M4 · **Джерело:** design §7.1 «Генерація … як злиття», §7.3 «Співавторство»

**What to build:** Редагування специфікацій у TUI з детермінованим автодоповненням (той самий шар, що LSP), помилки під час набору, `Ctrl+G` text→spec для виділеного тексту. Будь-яка зміна від зовнішнього джерела (майбутні `draft`, агент) показується як diff по шматках у тому ж редакторі: `a`/`r` на кожен шматок, `u` відкочує; нічого не записується без підтвердження.

**Blocked by:** 29

**Status:** resolved

- [x] правка рядка `step` з невідомим ID одразу показує K001 і підказку
- [x] MERGE-diff із двох шматків: прийняти один, відхилити другий → на диску лише перший
- [x] `fmt` результату ідемпотентний

## Answer

Редагування (`i`), доповнення через той самий `completions()`, що в LSP, над поточним буфером (`Ctrl+Space`, автоматично після пробілу чи `.`), K001 з «did you mean» і `planned` після аналізу overlay до запису, `Ctrl+S`, `Ctrl+Z`. `Ctrl+G` — детермінований text → spec (`src/tui/text-to-spec.ts`: `when`/`then`, `invariant`, `emits`, `step` за відомим ID), результат — MERGE для буфера. Зовнішні зміни — пропозиції `.keylang/proposals/<шлях>`; `m` відкриває diff по шматках (`src/tui/merge.ts`), `a`/`r`/`u`/`w`/`Esc`; записується лише прийняте, `u` у перегляді відкочує злиття. Тести `tests/tui.test.ts`: два шматки → на диску перший, пропозиція видалена, `fmt(fmt(x)) == fmt(x)`; `Esc` нічого не пише. Статуси `=`/`+?`/`!` — разом із `draft` (M7).
