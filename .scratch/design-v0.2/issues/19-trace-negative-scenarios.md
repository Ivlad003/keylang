# 19: Негативні сценарії trace: видалений крок, повтор, паралельність, неповний trace

**Етап:** M2 · **Джерело:** design §4.3, §9 критерій M2

**What to build:** На фікстурі з 18 перевіряються межі доказу: обов'язковий крок, відсутній у завершеному й достатньо інструментованому trace, дає `fail` (absence); неповний або обірваний trace дає `unverified`, не `ok`; додаткові виклики поза кроками дозволені підпослідовністю; паралельні sibling-кроки без каузальних зв'язків не отримують підтвердження порядку; гілка `when`, що не виконувалася в цьому тесті, лишається `unverified`. Кількісні й негативні властивості («не більше 3 retry») не виводяться з підпослідовності — для них у звіті явна позначка «потребує окремого предиката/тесту».

**Blocked by:** 18

**Status:** resolved

- [x] видалений крок за повного trace → `fail`, за trace із `dropped > 0` → `unverified`
- [x] зайвий виклик між кроками не змінює `ok`
- [x] два кроки з однаковими `ts` різних `clockId` і без `links` → порядок `unverified`
- [x] `when`-гілка без виконання в тесті → `unverified` «branch not exercised»
- [x] кожен сценарій — окремий CLI-тест із мінімальним trace-файлом

## Answer

Окремі CLI-тести в `tests/flows.test.ts`: відсутній крок (`fail` / `dropped` і відкритий span → `unverified`), зайвий виклик, різні годинники без `links`, перекриття, async без link, повтор кроку, невиконана `when`-гілка (її кроки не обов'язкові), кількісна властивість — «needs a separate predicate or test».
