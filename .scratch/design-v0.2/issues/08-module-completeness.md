# 08: Повнота модуля: `complete` vs `opaque`, видалена остання функція дає K001

**Етап:** M1.1 · **Джерело:** design §3.1 «Повнота модуля», §3.5, review RV03

**What to build:** Резолвінг ID зі специфікацій розрізняє повністю проіндексований модуль з порожнім списком членів і модуль із невідомим вмістом. Посилання на неіснуючого члена `complete`-модуля — K001 з підказкою; на члена `opaque`-модуля (зовнішній пакет, файл із помилкою розбору, явно виключений) — `unverified` із причиною, без K001. У ручній карті (слайдова форма без коду) модуль без членів і далі непрозорий, як Р13, але це видно в результаті.

**Blocked by:** 04 (знімок), 07 (словник `unverified`)

**Status:** resolved

- [x] відтворення RV03: flow посилається на `main.order.create`; замінити функцію на `export const marker = 1`, `map`, `check` → K001 з `did you mean`, код 1
- [x] посилання на `external.node.readFile`-подібного члена зовнішнього модуля → `unverified` з причиною «opaque module», не K001
- [x] `parse`/`check` на слайдовій фікстурі (без коду) зберігають поточну поведінку для `infrastructure.config.log`
- [x] правило Р13 у `docs/semantics.md` §6 переписане з поділом complete/opaque

## Answer

Посилання на члена `complete`-модуля без нього — K001 з `did you mean` і підказкою `planned`, навіть без `map` (свіжа карта). `opaque`: зовнішній модуль, помилка розбору, файл з `exclude` (модуль `<!-- excluded -->`) — `unverified`, один рядок на посилання.
