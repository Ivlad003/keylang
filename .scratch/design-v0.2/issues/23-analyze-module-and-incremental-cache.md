# 23: Глибокий модуль `analyze()` та інкрементальний кеш

**Етап:** M3 · **Джерело:** design §7 «Глибокий модуль аналізу», «Інкрементальність», §7.5 «Швидкість»

**What to build:** Єдиний вхід для CLI/LSP/TUI/MCP: `analyze(repo, specSources) → {snapshot, specs, findings, coverage}`; оркестрація свіжості й I/O відокремлена від чистих парсера й правил (ядро незалежне від tree-sitter). Кеш фактів ключується вмістом файла, версіями frontend/граматики та релевантною конфігурацією; зміна імпортів/експортів/шарів інвалідує залежні резолвінги. Повторний `check` після зміни одного файла перераховує лише залежне. Довга побудова публікує узгоджений знімок; застарілі результати скасовуються (потрібно для LSP/TUI).

**Blocked by:** 22

**Status:** resolved

- [x] CLI-команди `map`, `check` викликають `analyze()`; поведінка й вивід не змінилися (наявні тести зелені)
- [x] бенчмарк: повторний `check` після зміни одного файла на storefront-репозиторії істотно швидший за повний; числа в `bench/results.md`
- [x] кеш із несумісною версією перебудовується; `keylang.json` перевіряє межу шарів: ядро мови не імпортує tree-sitter (`check` на самому keylang)
- [x] юніт-тест інвалідації: зміна експорту в B перераховує резолвінг A

## Answer

`analyze()` (`src/analyze.ts`) — єдиний вхід для `map`, `check`, `lsp`: конфіг, свіжий знімок (з overlay буферів), специфікації зі свіжою картою, звіти й trace, оцінка. Кеш фактів `.keylang/cache/facts.json` ключується вмістом, версією екстрактора й граматик; пише лише `map`. storefront: `check` 4.8 с → 1.8 с після зміни одного файла (`bench/results.md` M3). Межа tree-sitter — `deny lang|check|base external.web-tree-sitter` (перевірено пробою). Інвалідація — `tests/analyze.test.ts`. LSP скасовує застарілі покоління (25). Відхилення: граф і знімок щоразу будуються з усіх фактів (tree-sitter лише для змінених файлів) — це тримає резолвінг імпортерів узгодженим.
