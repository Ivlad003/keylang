# 21: Стейлнес прози: fingerprint тіла й транзитивна інвалідація

**Етап:** M2 · **Джерело:** design §4.4, review RV17

**What to build:** Для кожного вузла знімок зберігає fingerprint нормалізованого AST тіла, сигнатури, публічного контракту та релевантних залежностей (консервативний хеш тексту, якщо нормалізація недоступна). Описи вузлів, `when`/`then`/`invariant` у специфікаціях отримують baseline fingerprint, що зберігається під версійним контролем поряд зі специфікацією й оновлюється лише за явного прийняття (`check --stale --accept`?), а не при кожному `map`. `check --stale` показує описи, під якими код змінився, з транзитивною інвалідацією за залежностями, включно з циклами; невідома залежність робить перевірку неповною (позначка). `stale` — попередження для перегляду, не `fail`.

**Рішення для людини:** формат і місце baseline (окремий JSON поряд зі spec, HTML-коментар у рядку, чи `.keylang/baseline.json` у git). Пропозиція: один `keylang/baseline.json` під git, ключ — файл спеки + ID вузла.

**Blocked by:** 04 (знімок), 16 (SpecIR)

**Status:** ready-for-agent

## Comments

- 2026-10-04 — рішення людини: baseline — один `keylang/baseline.json` під git; ключ — шлях файла специфікації, далі ID вузла (або `invariant:<текст>` / `when:`/`then:`), значення — fingerprint. Оновлюється лише явною дією `check --stale --accept`, `map` його не чіпає. До реалізації `check --stale` має давати код 2 з повідомленням «not implemented yet (design-v0.2/21)» замість мовчазного звичайного `check`.
- 2026-10-04 — зроблено (`src/stale.ts`, `check --stale [paths…] [--accept]`, `tests/stale.test.ts`; норма — `docs/format.md`, «Стейлнес прози»). Fingerprint твердження — SHA-256 від `closure` предметів зі знімка (нормалізований AST тіла й сигнатури + транзитивні виклики, цикл — одне ціле), для модуля/шару — `snapshotBaseline`, як у пояснень. Припущення, які варто переглянути:
  - **Код виходу:** `check --stale` — завжди 0 (stale/new/incomplete — попередження), 2 — помилка виклику, конфігу, невалідний baseline. `--stale` не поєднується з `--format`/`--strict`/`--static`/`--changed`/`--explain-edge` (код 2); машинного формату поки немає.
  - **Твердження:** описи вузлів лише в секціях map і flow рукописних файлів (rules, wiring і згенеровані файли — ні); `when`/`then`/`invariant` — лише у flow. Предмет `when`/`then`/`invariant` — посилання найближчого `step`/`trigger` над ним і всі посилання під ним; текстовий без них — усі посилання потоку.
  - **Ключі:** опис — ID оголошення, інакше перше посилання елемента; `then <id>` — `then:<id>`; повторний ключ у файлі — суфікс ` #2`, ` #3`.
  - **Неповнота** (`incomplete`) — предмета немає у знімку (хешується як `?`) або `closure.complete: false`; рядок друкується й для незмінного твердження.
  - **Fallback-хеш тексту** окремо не додано: усі фронтенди дають нормалізований fingerprint для fn і типів; fn без нього лишає closure неповним (позначка `incomplete`), а не мовчазно свіжим. Код верхнього рівня модуля в fingerprint модуля не входить (як і для пояснень).
  - **`--accept` з paths** замінює записи лише цих файлів; без paths baseline перебудовується цілком: записи зниклих тверджень і файлів (`obsolete`) прибираються. Baseline для самого keylang не закомічено: `check --stale` на репозиторії зараз дає 5 new / 5 incomplete.
  - Стан `stale` у hover/TUI лишається дорожньою картою.
