# 10: Резолвінг викликів враховує локальні bindings і затінення

**Етап:** M1.1 · **Джерело:** design §7 «Резолвінг», review RV07

**What to build:** Синтаксичний backend будує ланцюжок областей видимості для тіла функції: параметри, локальні `const/let/var`, деструктуризація, вкладені функції затіняють імпорти й оголошення модуля. Виклик через затінене ім'я, параметр-колбек або локальну змінну не стає підтвердженим ребром; він зберігається як `resolution: unresolved` (або `ambiguous` з кандидатами) із причиною й позицією і входить у покриття, тож правила на цій області дають `unverified`, а не `ok`.

**Blocked by:** 04 (ребра зі станом резолвінгу), 07 (вердикти)

**Status:** resolved

- [x] відтворення RV07 (`run(target) { target(); }` поруч з `export function target()`): у знімку немає ребра `run → target`, є unresolved із причиною «shadowed by parameter»
- [x] `const save = pick(); save()` не резолвиться в однойменну функцію модуля
- [x] прямий виклик імпортованої функції та `this.method()` резолвляться, як раніше; статистика на бенчмарку не деградує більш ніж на задокументовану величину (оновити `bench/results.md`)
- [x] ~~`deny`, що покривався б лише затіненим викликом, тепер `unverified`, а не `ok`~~ — замінено рішенням 07, див. Answer

## Answer

Ланцюжок областей від місця виклику: деструктуровані параметри, блоки, вкладені функції, `for…of`, `catch`. «shadowed» — лише коли локальне ім'я ховає імпорт/оголошення модуля, інакше `dynamic`. Чекбокс 4 змінено рішенням 07: затінений виклик не робить `deny` `unverified` (він не створює міжмодульного ребра); тест `calls through local values do not make deny unverified`. Статистика — `bench/results.md` M1.1.
