## What to build

Сторінка `/diagrams` у `keylang web`.

- Ліва панель: пошук за назвою флоу, бізнес-назвою (12), ID, міткою точки входу; групи за доменом/процесом.
- Полотно: рендер моделі 20 (BPMN-подібні фігури, доріжки шарів), zoom/pan, мінікарта; колір/значок вузла — вердикт (`✓ ✗ ◌ !`), дірки помітні.
- Клік по вузлу → бічна панель: сигнатура, файл:рядок, brief, вердикти й докази, «відкрити в TUI/редакторі».
- Пошук «де використовується ID» підсвічує всі флоу з ним.
- Живе оновлення після `map`/збереження специфікації (через наявний канал web).

## Comments

### 2026-10-08 — зроблено

- **Сторінка `/diagrams`** (`web/src/diagrams.ts`, `list.ts`, `canvas.ts`, `diagrams.css`) на каркасі 33. Ліворуч — віртуалізований список (фіксована висота рядка, у DOM лише видимі ± 8): флоу за шаром тригера, знайдені флоу з `keylang/flows-discovered/` за шаром, точки входу за видом, вид шарів; групи згортаються; пошук за назвою, файлом, міткою, ID точки входу і всіма ID кроків флоу. Полотно — BPMN-подібні фігури за видом вузла, доріжки шарів, колір і значок вердикту (`✓ ✗ ◌ ! ◇`) з легендою, zoom коліщатком довкола курсора, перетягування фону, «вмістити», мінікарта (`Outline` maxGraph). Клік по фігурі — панель: мітка, вид, ID, шар, `файл:рядок` коду й специфікації текстом і `vscode://file/…`, вердикт, результати `check` з критерієм і повідомленням, причина дірки.
- **«Де використовується ID»** — `GET /api/usages?id=…` (той самий Bearer, Host/Origin): флоу, знайдені флоу й точки входу (сама точка або її флоу за тригером); `a.b` охоплює `a.b.c`. Кнопка в панелі й «де ID?» біля пошуку; список лишає лише ці види, на полотні фігури з ID обведені, клік відкриває вид. Чиста `usagesOf` і `flowListing` — у `src/diagram.ts`.
- **Сервер:** `/api/views` додатково віддає `root`, `flowList` (файл, рядок, тригер, шар, ID) і `discovered` (з представлення, з міткою точки входу); `view=discovered&name=` малює знайдений флоу без вердиктів (кеш розбору за mtime/size); вузли `flow`/`entry` несуть `results` (до 20) для панелі — `diagramOf` не змінено, тести 20 ті самі.
- **Живе оновлення:** опитування `/api/views` і відкритої діаграми кожні 5 с, поки вкладка видима (наступне — після відповіді), перемальовування без втрати масштабу й вибору. Найпростіше й без нового каналу: WebSocket сесій несе ANSI-кадри TUI, а не події аналізу, а кожен запит API і так робить свіжий `analyze()`.
- **Фрагмент URL** — `#view=…&name|id=…&node=…`, синхронізований з вибором; `t=` при відкритті, як і раніше, переходить у `sessionStorage` і зникає з адресного рядка (решта фрагмента лишається) — тож посилання з видом можна копіювати без токена.
- **Бандл:** `BaseGraph` + `PanningHandler`, лише потрібні фігури/периметри/маркери; `Outline` тягнув усі типові плагіни — плагін esbuild `lean-outline` прибирає цей імпорт (змінене джерело зупиняє збірку). 397 → 267 КіБ (110 → 81 КіБ gzip).
- **e2e:** `npm run test:web` (`tests/web-e2e/diagrams.test.ts`, поза `npm test`) — `playwright-core` (devDependency) і наявний Chromium (`KEYLANG_CHROMIUM`, `/opt/pw-browsers/chromium`, системний, або `PLAYWRIGHT_BROWSERS_PATH`; інакше skip). Сценарій: пошук → флоу → клік по кроку → `src/application/purchase.ts:3` і `vscode://` → «де ID?» → знайдений флоу → перезавантаження → новий флоу без перезавантаження, без помилок консолі й CSP. Другий — 800 точок входу: < 80 рядків у DOM, пошук < 1,5 с (замість бенча Magento, якого в робочій зміні немає). Скриншот — `docs/course/images/diagrams-flow.png`; docs/tui.md і README оновлено.
- **Поза обсягом / припущення:** «відкрити в TUI» — не робилось (за постановкою зміни); бізнес-назви й групи за доменом/процесом чекають 12 (зараз групи — шар/вид); підсвітка по пошуку ID — фільтр списку + обведення на полотні. Знайдені флоу малюються без вердиктів і без дір: `check` їх не читає. «Мови»: сторінка мовно-незалежна — працює на тому, що дають знімок і специфікації (TS/JS, Python, Rust, PHP).
