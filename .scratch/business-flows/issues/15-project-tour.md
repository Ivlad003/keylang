## What to build

Одна сторінка для нової людини (і для агента через MCP `project_tour`):

1. Що це за система (з README і brief-ів шарів).
2. Шари й модулі з розміром і зв'язністю (з карти).
3. **Бізнес-процеси** (12): домен → процеси → флоу з описом і посиланням на діаграму (21).
4. Точки входу за видами (09/10) і події з підписниками (08).
5. Інтеграції (14).
6. Сліпі зони й «логіка в даних» (13) — що треба дочитати руками.
7. «З чого почати читати»: 5–10 найважливіших fn за центральністю й кількістю флоу, що через них проходять.

- Вивід: `keylang tour` → Markdown у stdout або `--out keylang/tour.md` (згенерований файл з маркером), web — сторінка «Огляд» (20/21).
- Детермінований без моделі; з моделлю — лише описи з походженням.


**Мови:** реалізація мовно-незалежна — однаково для TS/JS, Python, Rust і PHP (і їх суміші в одному репо); тести — щонайменше на двох мовах, з яких одна не PHP.
