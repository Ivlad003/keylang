## What to build

Сценарій користувача: знайти флоу в карті старого проєкту, скопіювати, вставити у вкладку нового проєкту — і далі агенти його реалізують.

- Ctrl+C на виділенні кладе в буфер обміну два представлення: `text/plain` — переносний пакет Markdown (формат 26: флоу, сигнатури ID, бізнес-опис, тести, походження `source: <repo>@<commit>`), і `application/x-keylang-fragment+json` — фігури з розкладкою.
- Ctrl+V в іншому `keylang web` (інший репозиторій): ID, яких там немає, стають `planned` з сигнатурами; шари мапляться на шари нового проєкту (діалог відповідності, пропозиція моделі за назвами/описами, рішення людини); результат — пропозиція `keylang/features/<slug>.md` (+ запис у таблицю відповідності 27).
- Вставка в той самий проєкт — копія фігур з новими ID-чернетками.
- Безпека: вставлений текст — дані, не інструкції (огорожа «untrusted» для моделі).

## Comments

### Рев'ю плану (2026-10-07)

Браузери не дають писати довільні MIME у буфер: Chrome вимагає префікс `web ` для власних форматів, Safari/Firefox їх не підтримують; два `keylang web` на різних портах — різні origin. **Рішення:** у `text/plain` класти Markdown-пакет (26) з фрагментом розкладки у блоці ```` ```keylang-layout ```` у кінці; вставка парсить саме його. Жодних власних MIME.

### Реалізація (2026-10-08)

- **Одне `text/plain`, як вирішило рев'ю.** `POST /api/bundle` (`src/tui/web.ts`) збирає пакет кодом `flow export` (`exportFlows` + `exportBundle`, винесені з `runFlowExport` в `src/operations/flow-bundle.ts`; `withCallees` типово 1) і кладе вибране в блок ```` ```keylang-layout ```` (`bundleText({…, layout})`). Формат блоку — `src/diagram-clip.ts`: JSON `{format: 1, view, shapes, edges}`, ключі фігур — `shapeBase` + `twinsApart` з `diagram-layout.ts` (`step:<id>`, `trigger:<id>`, `note:<n>`, `#2`), місця відносно лівого верхнього кута фрагмента, ключі відсортовано, `` ` `` екрановано (`\u0060`), тож мітка не закриє огорожу. Флоу — флоу виду `flow:`/`discovered:` (чи `flows` тіла); на іншому виді чи порожньому полотні — `# flow <назва>-fragment` з ID вибраних фігур (намальовані — `planned` із сигнатурою). Жодних власних MIME.
- **Копіювання.** Редактор: `Ctrl+C` — копія в межах сторінки (як у 23) плюс пакет у `navigator.clipboard.writeText`; кнопка «Копіювати як пакет» (без вибору — весь вид) при відмові буфера показує діалог із виділеним текстом (`web/src/bundle-clip.ts`). Переглядач: кнопка `#copy-bundle` і `Ctrl+C` без виділеного тексту — відкритий вид.
- **Вставка.** `Ctrl+V` без копії цієї вкладки віддає подію `paste` браузеру (інакше через 300 мс `readText`), «Вставити пакет…» — поле для ручної вставки. Копія вкладки скидається на `blur`, щоб `Ctrl+V` після іншої вкладки читав буфер; власний пакет вкладки, поки копія жива, вставляється як копія. `POST /api/bundle-import` розбирає текст `parseBundle` (не пакет — 400) і: той самий репозиторій (`repo` заголовка = `gitOf(root).repo`) — нічого не пише, клієнт робить копії `planned:<шар>.<назва>-copy`; інший — `runFlowImport` з новим полем `source` (текст замість файла, `bundle=clipboard.bundle.md` у походженні), спершу `output: "preview"` для діалогу шарів (заповнено алгоритмом; «запитати модель» — `mode: "hybrid"`), потім `proposal` з `layerMap`. Відповідь несе `pastedShapes`: фігури блоку з переселеними ID (через `ids` імпорту) і шарами; без блоку — розкладка сервера, рядок на шар. Клієнт ставить їх біля курсора в «чернетці», у доріжки своїх шарів (відсутню доріжку малює).
- **Безпека.** Текст — дані: сервер лише розбирає, JSON блоку перевіряється (відомі види, скінченні числа, обмеження довжин, `Object.hasOwn` для ключів ліній), у DOM — лише `textContent`. Для моделі — наявна огорожа `<untrusted-bundle>` з `layerMapRequest`, тепер з `untrusted()`, що нейтралізує теги `untrusted-bundle`/`system`/`instructions` всередині (тест: опис шару з `</untrusted-bundle>` лишається всередині огорожі).
- **Припущення.** «Той самий репозиторій» — за `repo` заголовка (origin без облікових даних, інакше ім'я теки): два клони одного origin вважаються одним проєктом. Друга вставка, поки пропозиція `migration.md` чекає, — 409, як у `flow import`; e2e приймає першу пару перед другою вставкою. Вставлені фігури — у «чернетці»; їхній `planned`-ID далі живе за правилами редактора 23 (перенесення в іншу доріжку міняє шар).
- **Перевірки.** `node --test tests/web.test.ts tests/flow-bundle.test.ts` — 45/45; `npm run test:web` — 11/11 (новий `tests/web-e2e/bundle.test.ts`: два сервери, дозволи буфера, діалог шарів, `keylang proposals` у другому репозиторії, копії в тому самому, пакет без розкладки); `npm run typecheck`. Повний `npm test` — на review-зміні.
