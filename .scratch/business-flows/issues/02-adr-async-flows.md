## What to build

Сьогодні флоу — синхронне дерево викликів: sibling-кроки означають строгий порядок, події лише проза (`emits event`), таймерів і вебхуків немає. Для магазину з інтеграціями більшість логіки асинхронна, а при міграції губляться саме observers, cron і вебхуки (рев'ю §1, відповідь про BPMN).

Вирішити й записати в `docs/adr/0023-async-flows.md`:

1. **Події.** `- emits event checkout_submit_all_after` під кроком перевіряється статично проти фактів адаптера (є `dispatch` з цим літералом у піддереві кроку). Новий тригер `- trigger event <name>` — флоу підписника. Вердикти: `ok` — dispatch знайдено / підписник зареєстрований; `fail` — у повністю прочитаній області dispatch немає; `unverified` — назва події не літерал.
2. **Паралельні групи.** Синтаксис (`- parallel` з вкладеними `step`), значення: усі кроки мають відбутися, порядок між ними не перевіряється; trace — усі span під батьком, без вимоги порядку. Design §3.4 обіцяв це до v1.
3. **Асинхронні тригери.** `- trigger cron <id>`, `- trigger consumer <id>`, `- trigger route <METHOD path>`, `- trigger webhook <id>`; зв'язок флоу: `- continues <flow>` (вебхук оплати продовжує `place-order`). Перевіряється лише існування точки входу й зв'язку; наскрізного trace між запитами немає — `unverified` з причиною.
4. **Таймери.** `- after 30m` / `- every 1h` — твердження, яке перевіряє лише `test` під ним; статично — існування cron/scheduler-запису для fn (якщо адаптер його бачить).
5. **Сумісність:** контекстні слова лише всередині `# flow`, сьогодні вони дають K004 → додавальна зміна без нової редакції (ADR 0007). Порядок відносно тікетів pl-theory 45–47.
6. **BPMN-відображення:** яка конструкція стає яким елементом BPMN у тікеті 28.

## Comments

### Рішення автора (2026-10-07)

- **Асинхронні продовження:** кожна точка входу (вебхук, cron, consumer) — окремий флоу, зв'язок `- continues <flow>`; наскрізний trace між запитами — `unverified` з причиною. Форму `wait` всередині одного флоу не вводити.
- Усі форми — для всіх мов проєкту (тригери беруться з `entries` будь-якого адаптера).
