# 06: Пам'ять скрепки: tui.json і .keylang/chat

**Status:** resolved

**Type:** code

**Blocked by:** 02, 03

**Verify:** `node --test tests/tui-clip-memory.test.ts` · `npm run typecheck` · `npm test` · `node bin/keylang.js map --check` · `node bin/keylang.js check --strict`

**Джерело:** spec §3, §4.7, П7; [ADR 0021](../../../docs/adr/0021-tui-clip-chat.md) п. 6

**What to build:** Наступний запуск keylang ставить скрепку й вікно туди, де людина їх лишила, і продовжує сьогоднішню розмову.

- **Геометрія.** `~/.config/keylang/tui.json` (каталог той самий, що для `agents.json`; `home` — з опцій сесії, як у `src/agent-cli.ts`) зберігає місце скрепки, місце й розмір вікна. Файл пишеться атомарно, коли перетягування чи зміна розміру скінчилися, і читається на старті. Невалідний файл ігнорується з одним повідомленням. Інші поля файла зберігаються. На старті геометрія затискається в розмір термінала.
- **Розмова.** `.keylang/chat/<YYYY-MM-DD>.md` за локальною датою, формат зі spec §4.7. Обмін дописується після кожної відповіді чи команди. `/new` починає новий розділ `## <час>`. На старті сесії історія відновлюється з останнього розділу сьогоднішнього файла.
- **Коли лог не пишеться:** режим перегляду; шлях не ігнорує git (`git check-ignore -q`, git масивом аргументів), і тоді чат один раз пояснює, що `.keylang/` має бути в `.gitignore` і що `keylang init` це робить; скасований запит.

### Notes

- 2026-10-06 (тікет написано): лог — хронологія за днем, а не стан, тож його не читають ні `check`, ні знімок (П7 спеки).
- 2026-10-06 (реалізація): код — `src/tui/clip-memory.ts`. Місце: чисті `parsePlace`, `withPlace`, `placeOf`, `placeClip`; I/O — `readPlace` і `writePlace` (`writeAtomic` у `landing` файла, тож посилання лишається посиланням). Лог: клас `ChatLog`, чисті `withExchange`, `withSection`, `withAgent`, `lastConversation`, і `logBlocked`. У `clip.ts` — гачок `ClipHost.placed()`: кінець перетягування скрепки, верхньої рамки чи кута (`up` з рухом, не на вузькому терміналі), `nudge()` і `reset()`; `CHAT_MIN_COLS`/`CHAT_MIN_ROWS` експортовано для перевірки файла. У `clip-chat.ts` — `ChatLog` у `ClipChat`, `restore()`, поле `sent` і `answer(text, ending)`. У `app.ts` — опція `home` (за замовчуванням `homedir()`), `restorePlace` і `keepPlace`.
- 2026-10-06 (припущення): розділ `## <час>` — одна розмова, а після часу через ` · ` — моделі, що в ній відповідали (`payload.agent`, як у записі `F6`). `/new` пише `## <час>` одразу, тож сесія після нього починає з порожньої історії. Розділ, який почали `/new` чи команда, дізнається модель з першої відповіді: дописується заголовок останнього розділу. Друга модель у тій самій розмові додається через кому.
- 2026-10-06 (припущення): обмін — повідомлення людини й відповідь на нього. Відповідь, дана поки виконується `said`, бере повідомлення з поля `sent`; пізня (модель, `/explain`, `/feature`) несе його з собою (`Asked.said`, замикання в `operation`). Повідомлення скрепки без повідомлення людини — наприклад, список питань тікета 05 при відкритті чату, якщо він іде через `answer()` поза `said` — у лог не йде.
- 2026-10-06 (припущення): помилка моделі, «немає моделі», «вже працює інша операція» і відмова пропозиції — відповіді, тож лог їх пише. Не пише він лише скасований запит: статус `cancelled` або запис без результату (`cancelled()` у `clip-chat.ts`). Тести 03–04, що перевіряли «нічого не записано» після таких відповідей, тепер не рахують `.keylang/chat/` (`withoutChatLog` у `tests/tui-helpers.ts`), як і дозволяє інваріант spec §3. Тести скасування й Browse лишилися строгими.
- 2026-10-06 (припущення): у лог відповідь іде без рядка `пропозиція: <p> · m — MERGE`, а шлях — блоком `**пропозиція:**`. Відновлена історія показує `пропозиція: <p>` без підказки MERGE: пропозиції тоді вже може не бути. Наступні рядки повідомлення мають відступ у два пробіли, порожні лишаються порожніми. З краю стоять лише заголовки й мітки, тож рядок `## …` чи `**ти:**` у відповіді моделі розділу не ламає.
- 2026-10-06 (припущення): коли git не ігнорує шлях, чат один раз за сесію каже `NOT_IGNORED`. Коли git не відповів (немає git, відмова, чужий власник), а над коренем є `.git`, лог теж не пишеться, і чат один раз називає причину. Без `.git` над коренем писати можна. Перевірка йде на кожен обмін, тож `.gitignore`, змінений під час сесії (`keylang init`), діє з наступного обміну.
- 2026-10-06 (припущення): місце в стані зберігається як є, як у тікеті 02. Старт його не затискає, а кадр показує скрепку й вікно всередині термінала, і більший термінал повертає їх на збережене місце. Кожна `Alt+стрілка` пише файл одразу, без debounce: файл крихітний, а перетягування пише один раз, при відпусканні. Режим перегляду tui.json пише: це файл користувача, а не репозиторію.
- 2026-10-06 (припущення): `null` в `assistant`, `clip` чи `window` — те саме, що поля немає. Невідоме поле всередині `clip` чи `window` — помилка, а інші поля `assistant` і файла зберігаються. Невалідний JSON перше перетягування замінює цілком: зберегти з нього нічого не можна. Повідомлення про невалідний файл — англійською, у рядку знахідки, як інші повідомлення сесії; пояснення про git — українською, у чаті.
- 2026-10-06 (реалізація, тести): `session()` бере свій тимчасовий `home` (`tempHome()` у `tests/tui-fixture.ts`). Той самий модуль ставить процесу тимчасовий `HOME`, тож сесії без `home`, `keylang web` і CLI в тестах не читають `~/.config/keylang/tui.json` розробника. Web-тест скрепки дає сесії в процесі свій `home`, щоб її перетягування не потрапило в сервер, який стартує після неї.
- 2026-10-06 (реалізація): `CONTEXT.md` не змінено: окремий термін для логу не знадобився. Речення «Скрепка нічого не пише» в першому абзаці розділу «Скрепка» `docs/tui.md` стосується самої фігури; що й де пишеться, каже абзац «Пам'ять».
