# 03: Rust: виклики, `impl`-методи та явна неповнота

**Етап:** M5 · **Джерело:** design §4.2, §10.7; батьківський 32

**What to build:** Виклики з тіл функцій і методів `impl` резолвляться через `use`-bindings і локальні оголошення; `Type::f()` — до методу `impl`. Виклик методу через значення, trait-диспетчеризація й макроси (`foo!()`) не вигадують ребер: вони потрапляють у покриття як unresolved/unsupported з фрагментом коду. Flow-крок на такий виклик лишається `unverified`.

**Blocked by:** 02

**Status:** resolved

- [x] `a::b()` після `use crate::a` → call-ребро; `x.method()` без відомого типу → unresolved у покритті
- [x] макрос і `dyn Trait`-виклик видно в покритті з причиною
- [x] статичний доказ flow-кроку працює для Rust-ребра так само, як для TS

## Answer

Виклики з тіл fn і методів `impl`: `f()`, `a::f()` через `use`, `Self::f()`, `self.m()`, шлях від `crate`/`super`/`self`/невідомого імені з малої літери як власний імпорт. `x.m()` через значення (включно з `dyn Trait`) — `dynamic-call`; невідомий макрос — `unsupported`. Тест: flow із Rust-ребрами дає `static ok`, крок через метод значення — `static unverified` з причиною.
