# 70: Пояснення модуля чи класу не стає stale, коли змінюється значення, яке не читає жодна fn

**Status:** resolved

**Type:** code

**Blocked by:** None (can start immediately)

**Verify:** `node --test tests/stale.test.ts tests/explained-map.test.ts` · `npm run typecheck`

**Джерело:** залишок тікета 31 (2026-10-08): fingerprint fn тепер хешує значення свого файла, які вона читає; baseline модуля/класу (`snapshotBaseline`, `src/explanations.ts`) досі не бачить верхньорівневих значень, які не читає жодна fn.

## Що не так

Зміна константи, поля класу, об'єктної таблиці чи значення, присвоєного в конструкторі (`self.x = …` у `__init__`, параметр-властивість TS), яке не читає жодна fn модуля, не робить пояснення модуля чи класу `stale`.

## Що зробити

- Екстрактори (`src/extract/{ts,python,php,rust}.ts`) записують fingerprint верхньорівневого не-fn коду модуля і тіла класу поза методами (поля, константи, присвоєння в конструкторі).
- `snapshotBaseline` модуля/класу включає цей fingerprint.
- Пояснення, записані до зміни, мають стати `stale` лише там, де значення справді змінилось (тест з незміненим модулем лишається `fresh`).

## Критерії готовності

- [x] тести на TS, Python і PHP: зміна непрочитаної константи → пояснення модуля `stale`; зміна коментаря поза кодом — `fresh`
- [x] `docs/semantics.md` «Стейлнес прози» оновлено

- `valuesFingerprint` (`src/extract/treesitter.ts`) хешує код значень області: верхньорівневі інструкції файла чи тіла класу, крім оголошень із `decls` (fn, клас, тип — у них свої fingerprint-и; `const a = 1, f = () => …` лишає `a`), імпортів, `use`, коментарів, docstring-ів, `pass`, Rust-атрибутів і `mod x;`. Синтаксис — той самий `hashSyntax`, що й у `fingerprint`, тож коментар, docstring і розкладка хешу не змінюють. Нема такого коду — нема й факту.
- Факти: `FileFacts.values`, `DeclFact.values` класу (`src/extract/facts.ts`); їх пишуть `ts`, `python`, `php`, `rust`. Граф (`Module.values`, по рядку `<файл> <хеш>` на файл модуля) → знімок (`SnapshotNode.values`, sha256) → `snapshotBaseline` (`src/explanations.ts`) додає `values ...` вузла й кожного вузла під ним. Вузол без `values` хешується як раніше, тож baseline-и модулів без коду значень не змінились.
- Поля, які задає конструктор: у `values` класу не входять, бо їх уже покриває fingerprint конструктора, що лежить під класом (зміна → клас `stale`, тест це перевіряє). Для fn їх тепер бачить `fingerprint` (залишок тікета 31): `constructorFields` додає до області тіла класу `this.x = …`/`self.x = …`/`$this->x = …` конструктора та параметри-властивості TS і promoted-властивості PHP; метод, що читає `x`, хешує їх. Інструкції всередині самого вузла до його значень не додаються, тож fingerprint конструктора не змінився.
- Абсолютні імпорти (залишок тікета 31): `fingerprintFacts` повертає `readsImports` — імена, прочитані як значення, які зв'язав імпорт без синтаксичної ознаки репозиторію (Python `import a.b`/`from a.b import X`, PHP `use` крім `use function`, голий TS-специфікатор, Rust `use` іншого crate). `src/graph.ts` після розв'язання імпортів додає до fingerprint fn `+`, коли таке ім'я веде в інший файл репозиторію; далі — як для відносних (`closure.complete: false`). `Limits::double()` і `new Limits()` — виклики, неповноти не дають; імпорт stdlib чи пакета — теж.
