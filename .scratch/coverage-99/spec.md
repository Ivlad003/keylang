## 1. Метрики

Кожна метрика рахується на кожному репо еталону окремо, ціль — **≥ 99 %** на кожному.

| # | Метрика | Формула | Звідки |
|---|---|---|---|
| M1 | Повнота точок входу | знайдені ∩ еталонні / еталонні | `.keylang/index.json` `entries` проти `bench/truth/<repo>.md` (список, перевірений людиною) |
| M2 | Покриття flows | entries з чернеткою flow / entries | `flows discover --print`: рядки «no fn to draft from» — непокриті |
| M3 | Досяжність живого коду | reachable / (fns − пояснені мертві) | `coverage --json` `reach`; мертвий код — fn без викликачів, без експорту назовні й без «escape», кожна у списку `orphans` з причиною |
| M4 | Покриття пошуком | сутності в індексі / сутності | `keylang search --stats` (тікет 09) |

**Чесна межа M3.** 99 % від *усіх* fn недосяжні на коді з мертвим кодом: знаменник — fn мінус ті, що keylang явно називає мертвими з причиною. Мертва fn не ховається: вона лишається в `coverage` і в M3-звіті окремим рядком. Здогад не стає ребром (AGENTS.md: «Синтаксичний аналіз не дає підстав вигадувати підтверджені ребра»).

## 4. Рішення (обрані за кодом; переглядаються на рев'ю)

| # | Рішення |
|---|---|
| Р1 | Точка входу з'являється лише з того, що виконує рантайм: маніфест, конфіг, файлова конвенція фреймворку, HTML `<script>`. Ім'я файла саме по собі — не доказ. |
| Р2 | Модуль, верхній рівень якого виконується (скрипт, `bin` без `main`), — корінь flow: його виклики верхнього рівня стають кроками, як у fn. |
| Р3 | Fn, передана як значення у виклик (колбек, `createX(fn)`), — досяжна через «escape», якщо досяжний виклик, що її отримує; це окремий вид досяжності у звіті (`via value`), не ребро `call`. |
| Р4 | Пошук — Orama (`@orama/orama`, вибір автора 2026-10-11): BM25 + typo tolerance, без native, у Node і web worker; шлях до гібридного пошуку пізніше. |
| Р5 | Метрики — скрипт `bench/coverage.ts`, звіт у `bench/results.md`; локальні перевірки тікетів — фікстури й тести, офлайн; bench — підтвердження в `## Comments`. |
