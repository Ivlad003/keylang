# 06: CI цього репозиторію і рецепт CI для користувачів

**Status:** ready-for-agent

**Type:** code

**Blocked by:** None (can start immediately)

**Verify:** `node --input-type=module -e "import { parse } from 'yaml'; import { readFileSync } from 'node:fs'; parse(readFileSync('.github/workflows/ci.yml', 'utf8'))"` · `npm run typecheck` · `npm test`

**Джерело:** [рев'ю 2026-11-19](../../../docs/review-2026-11-19.md) §3 рядок 11, §4 «Різна база для `--changed`», §5 рядок 1; рев'ю 2026-10-06 §3 ризик 3.

**What to build:**

**1. CI репозиторію.** Теки `.github/` немає. Typecheck, тести, `map --check` і `check` запускає лише людина, повний `npm test` триває ≈ 15 хв. Створити `.github/workflows/ci.yml` на `push` у `master` і на `pull_request`:

- `actions/checkout` з `fetch-depth: 0` (тестам `--changed`/`feature` потрібна історія);
- `actions/setup-node` з кешем npm, далі `npm ci --ignore-scripts`, як у `.pi/shiftwork.json`;
- кроки по черзі: `npm run typecheck`, `npx oxlint`, `npm test`, `node bin/keylang.js map --check`, `node bin/keylang.js check`.

Матриця:

| ОС | Node | Статус |
|---|---|---|
| `ubuntu-latest` | `22.18.0` (мінімум з `engines`) і `24.x` | обов'язково |
| `macos-latest` | `24.x` | `continue-on-error: true`, доки не закрито macos-paths/01 |
| `windows-latest` | `24.x` | `continue-on-error: true`; стан тестів на Windows невідомий |

`npm run test:web` (headless Chromium) — не в цьому workflow.

**2. Рецепт для користувачів.** У `docs/cli.md` (новий підрозділ «CI» поруч із «Агенти, baseline і фічі») і в `docs/course/08-use-cases.md` дати готовий workflow на ~15 рядків:

- `npx -y keylang@<version> check`;
- `npx -y keylang@<version> map --check`;
- за бажанням `check --strict` з поясненням ціни (кожен `unverified` стає помилкою);
- `--format github` для анотацій у PR, `--format sarif` для code scanning.

Окремо пояснити базу `--changed`:
- `check --changed` без `--since` порівнює з `HEAD`, тож на чистому дереві CI порівнювати нема з чим і результат порожній;
- у CI — повний `check` або `check --changed --since origin/<main>` з `fetch-depth: 0`;
- `feature` сам бере merge-base (`src/git-changes.ts:327-331`), але у shallow-клоні йому теж потрібна історія.
