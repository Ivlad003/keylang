# Системний дизайн у keylang: `# system`, діаграми системи, ER і sequence, виявлення з коду

**Status:** resolved

**Джерело:** запит автора 2026-10-11: «розширити палітру в діаграмах, щоб було все необхідне для побудови систем, баз даних і архітектур… щоб пройти інтерв'ю»; рішення — шлях B (нове поняття мови, звірене з кодом), а не лише малювання. Доповнення того ж дня: «в готових проєктах — алгоритмічна детекція діаграм з коду, модулів, флоу». Попередні спеки: [c4-zoom](../c4-zoom/spec.md) (рівень «система» — лише вузол представлення), [business-flows](../business-flows/spec.md) (діаграми, редактор, layout-файли), ADR 0014 (одна модель — багато представлень).

## 1. Мета

Два сценарії:

- **A. Дизайн з нуля (інтерв'ю, greenfield).** Описати систему в Markdown: вимоги, оцінки, компоненти (клієнт, LB, сервіси, БД, кеш, черги…), зв'язки з протоколом і навантаженням, зони (регіон, VPC), схему БД, послідовності запитів, компроміси. Побачити це діаграмами на сторінці `keylang web` і малювати палітрою редактора, яка пише той самий Markdown.
- **B. Наявний проєкт.** Ті самі діаграми **виводяться алгоритмічно з коду**: компоненти — з точок входу, шарів і зовнішніх пакетів; ER — зі схем (Prisma, SQL); sequence — з дерева викликів точки входу. А рукописний `# system`, прив'язаний до коду (`- code <id>`), `check` звіряє зі знімком: «сервіс api читає postgres» підтверджує імпорт драйвера в коді api.

## 2. Що вже є і чого бракує (перевірено за кодом 2026-10-11)

| Потрібно | Є | Бракує |
|---|---|---|
| Компоненти системи | шар, модуль, fn, `external.<pkg>` (пакет) | клієнт, LB, gateway, сервіс як одиниця деплою, БД, кеш, черга, сховище, пошук, CDN… |
| Зв'язки | `dependency`, `call`, `allow`/`deny`, `emits` | sync-запит із протоколом, read/write, publish/consume, реплікація, підпис (QPS) |
| Межі | доріжка = шар | зона: регіон, VPC, публічна/приватна |
| Дані | — | таблиці, колонки, PK/FK, індекси, кардинальність |
| Час | BPMN-потік (кроки коду) | sequence: повідомлення між компонентами |
| Інтерв'ю | проза, `- ?` у потоці | вимоги, NFR, оцінки, компроміси як елементи |
| З коду | шари, модулі, потоки (`flows discover`) | компоненти, БД зі схем, sequence з викликів |

## 3. Рішення (2026-10-11, обрані за кодом; переглядаються на рев'ю)

| # | Рішення |
|---|---|
| Р1 | Нова секція `# system <name>`, ім'я обов'язкове, простір імен — свій (як у потоків); два однакові імена — K002. Типовий файл — `keylang/system/<name>.md`. Зміна додавальна (досі K006), нова редакція формату не потрібна |
| Р2 | Компонент — `- <вид> <ім'я> [технологія…]`; вид — одне з `client`, `cdn`, `dns`, `lb`, `gateway`, `service`, `worker`, `function`, `db`, `cache`, `queue`, `storage`, `search`, `warehouse`, `auth`, `external`. Ім'я — сегмент, локальне для системи (не глобальний ID мови); на нього посилаються лише рядки цієї ж системи |
| Р3 | `- zone <ім'я> [підпис…]` групує компоненти (вкладені зони дозволено): регіон, AZ, VPC, межа довіри |
| Р4 | Під компонентом: `code <id>[, <id>]` (прив'язка до карти, резолвиться як будь-яке посилання — K001), зв'язки `calls`, `reads`, `writes`, `publishes`, `consumes`, `replicates`, `uses` у формі `<дієслово> <компонент> [підпис…]`, `scale <текст>`, `table <ім'я>` (лише під `db`, `warehouse`, `search`, `storage`, `cache`; інакше K005) |
| Р5 | Під `table`: `index <колонки…> [unique]`, решта рядків — колонки: `<ім'я> <тип> [pk] [unique] [null] [fk <таблиця>.<колонка>]` |
| Р6 | `- sequence <ім'я>` з повідомленнями `<від> → <до> [текст…]` (`->` теж); `⇢` або `-->` — асинхронне. Учасники — компоненти системи |
| Р7 | Інтерв'ю — елементи верху секції з вільним текстом: `requirement`, `nfr`, `estimate`, `tradeoff`, `?` (як у потоці: відкрите питання) |
| Р8 | Нові коди: **K401** — невідомий компонент (у зв'язку, у sequence; з «did you mean»); **K402** — `fk` на невідому таблицю чи колонку; **K403** (попередження) — прив'язаний код імпортує пакет сховища (БД, кеш, черга, пошук, сховище файлів), а в компонента немає зв'язку з компонентом цієї технології. Дублікат компонента, зони, таблиці, колонки, sequence — K002 |
| Р9 | Вердикт `system` для зв'язку від компонента з `code`: до компонента з технологією з каталогу (§4) — `ok`, коли з коду джерела імпортами досяжний модуль, що імпортує драйвер цієї технології; інакше `unverified` (бракує доказу: доступ може йти через HTTP). До компонента з `code` — `ok`, коли з коду джерела досяжний його код; інакше `unverified` («мережевий виклик статичний граф не бачить»). Без `code` у джерела або без технології з каталогу вердикту немає: це задум. `fail` система не дає: синтаксичний граф не доводить відсутності мережевого виклику |
| Р10 | Виявлення з коду — **чиста функція знімка** (плюс прочитані файли схем для ER), без моделі; та сама логіка для CLI, web і `app.html`. Вивід — звичайний Markdown `# system`, тож його можна прийняти як специфікацію |
| Р11 | Представлення: `view=system&name=`, `view=er&name=`, `view=sequence&name=&seq=`. Ім'я `@code` — система, виведена з коду. Вони йдуть у read-API, статичний експорт і `app.html`, як інші діаграми |
| Р12 | Палітра редактора на представленні системи — компоненти, зона, примітка, зв'язки; «Пропозиція» пише секцію `# system` у `<dir>/system/<name>.md` тим самим механізмом пропозицій, що й для потоків |
| Р13 | CLI: `keylang system list`, `system show <name>` (дерево з вердиктами в терміналі), `system discover [--json]` (Markdown системи з коду в stdout), `system new <name> [--interview]` (каркас файлу; наявний файл не перезаписується, код 2) |
| Р14 | Парсери схем — перевіреними пакетами (AGENTS.md): `@mrleebo/prisma-ast` для `*.prisma`, `pgsql-ast-parser` для `CREATE TABLE`/`CREATE INDEX` у `*.sql` (уточнено 2026-10-11: `node-sql-parser` займає 89 МБ у `node_modules` з усіма діалектами; граматика PostgreSQL читає стандартний SQL, MySQL-синтаксис — рядок «not read»). Файл, що не розібрався, — рядок у `reason` діаграми й коментар у `system discover`, не помилка |

## 4. Каталог технологій

`src/system-catalog.ts`: технологія → вид компонента й пакети драйверів для npm, PyPI, Composer, crates (ID знімка — `external.<сегмент>`). Наприклад: `postgres` → `db`: `pg`, `postgres`, `pg-promise`, `@prisma/client`, `typeorm`, `knex`, `sequelize`, `drizzle-orm`, `psycopg2`, `psycopg`, `asyncpg`, `sqlalchemy`, `sqlx`, `tokio-postgres`, `diesel`; `redis` → `cache`: `redis`, `ioredis`, `@upstash/redis`; `kafka` → `queue`: `kafkajs`, `@confluentinc/kafka-javascript`, `confluent-kafka`, `rdkafka`; `s3` → `storage`: `@aws-sdk/client-s3`, `aws-sdk`, `boto3`; `elasticsearch` → `search`. ORM без однозначної БД (`@prisma/client`, `typeorm`, `knex`, `sqlalchemy`) підтверджує будь-яку SQL-технологію. Порівняння технології — без регістру й за синонімами (`postgresql`, `pg`, `postgres`).

## 5. Виявлення з коду (Р10)

- **Компоненти.** Шар з точками входу `route`/`rest`/`graphql`/`controller`/`webhook` — `service <шар>`, лише з `cron`/`consumer`/`observer` — `worker <шар>`, з `cli`/`main` — `service <шар>` (технологія — фреймворк точок входу або `cli`); `code <шар>`. Без точок входу — один `service <ім'я репозиторію>` з усіма шарами. Пакет з каталогу, який імпортує код, — компонент свого виду з ім'ям технології (`db postgres`); пакет зовнішнього сервісу (Stripe, OpenAI, Anthropic, Twilio…) — `external <ім'я>`. Для HTTP-точок входу — `client client HTTP` (розпізнавання фронтенду як окремого клієнта — поза обсягом, див. 06).
- **Зв'язки.** Сервіс → сховище: `uses`, коли з коду сервісу імпортами досяжний модуль, що імпортує драйвер; `consumes`, коли в шарі є `consumer`. Сервіс → сервіс: `calls`, коли код одного імпортує код іншого. Підпис — кількість імпортів.
- **ER.** Таблиці зі `schema.prisma` (model, поле, `@id`, `@unique`, `?`, `@relation(fields, references)`) і з `CREATE TABLE` у `*.sql` (колонки, `PRIMARY KEY`, `UNIQUE`, `NOT NULL`, `REFERENCES`, `FOREIGN KEY`) під компонентом `db` (технологія — з `provider` Prisma чи діалекту; інакше `db database`).
- **Sequence.** Для кожної точки входу (до 20): обхід дерева викликів знімка від її fn у порядку рядків, глибина до 6; повідомлення з'являється там, де виклик переходить у код іншого компонента або в пакет з каталогу. Виклик через значення (`pool.query`) знімок не розв'язує: у fn модуля, що імпортує драйвер одного сховища, він — повідомлення цьому сховищу (евристика за модулем, у документації названа так). Для HTTP-точки входу перше повідомлення — `client → <сервіс> <мітка маршруту>`.
