# 11: Self-host і перевірка на GitHub

**Джерело:** spec «Мета»; ADR 0004 «Наслідки»

**What to build:** Увімкнути `explain.map` для самого keylang. Прогнати `keylang explain --missing --llm --dry-run`, оцінити витрати, потім згенерувати brief-и й переглянути вибірку на правдивість: люди пропускають ~40 % хибних тверджень LLM (design §5.4). Хибні виправити або замінити коментарем документації в коді. Закомітити `keylang/map-explained/` і `keylang/explain/`. На GitHub перевірити, що працюють якорі, лінки `calls`, посилання на код і зміст `README.md`, і що позначки `llm`/`stale` видно. У VS Code перевірити `Ctrl+T`.

**Blocked by:** 05, 07, 08

**Status:** ready-for-human

- [x] висновок: чи варто згенерувати коментарі документації в код для вузлів без них (окремий тікет, якщо так)
