# 03: Карта з поясненнями з коментарів коду

**Джерело:** spec «Контракт»; ADR 0004 п. 1, 4

**What to build:** Опція `explain.map` у `keylang.json` (boolean, типово `false`, валідується з назвою поля). З увімкненою опцією `keylang map` пише, крім канонічної карти, `<dir>/map-explained/<layer>.md` і `README.md`. Дерево, порядок, посилання на код, сигнатури, залежності й `calls` ті самі. Під рядком вузла — рядок опису (grammar.md §3) з поясненням. У цьому тікеті є лише походження «коментар коду», brief від моделі додає 04. Текст екранується: не починається з `- `, `#`, `>`, `N.`, не містить `<!--`/`-->` і перенесень. Отже файл лишається валідним keylang. Маркер `keylang:generated` той самий. Ручний файл на місці цілі — конфлікт, як для карти. `map --check` перевіряє обидві карти. З вимкненою опцією `map` видаляє згенеровані файли `map-explained/`, а `map --check` вважає їх застарілими. `analyze()` ніколи не бере `map-explained/` в оцінку. Файл, названий у `check` явно, пропускається з приміткою в stderr. Точки доступу для 04 і 08–10 — одна чиста функція «пояснення вузла»: `{ text, origin, stale } | null`.
