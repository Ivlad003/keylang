# 05: Пакетна генерація brief-ів

**Джерело:** spec «Припущення» (знизу вгору); design §5.4 «Актуальність»

**What to build:** `keylang explain --missing --llm` створює brief для кожного вузла карти без коментаря документації й без свіжого brief. `keylang explain --stale --llm` перегенеровує застарілі brief-и. Порядок знизу вгору: fn/тип → клас/модуль → шар. Промпт батька містить brief-и дітей, тому шар пояснюється через свої модулі. `--dry-run` друкує кількість вузлів за рівнями й оцінку токенів і нічого не викликає. `--limit N` обмежує кількість вузлів. `--jobs N` задає паралельність (типово невелика). Прогрес іде в stderr. Кожен brief записується одразу: переривання чи помилка провайдера не губить готових, повторний запуск продовжує з місця зупинки. Код виходу 0, якщо все зроблено, 1, якщо частину вузлів не вдалося пояснити (їх перелічено), 2 для помилки виклику чи відсутнього ключа.
