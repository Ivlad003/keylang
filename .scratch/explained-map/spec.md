# Карта з поясненнями

**Джерело:** запит користувача 2026-09-28, [ADR 0004](../../docs/adr/0004-explained-map.md), design §5.4, grammar.md §3 «Опис вузла», §4–5, §11, §12. Терміни — `CONTEXT.md` («Explained map», «Explanation», «Brief»).

## Мета

Поруч із поточною картою можна тримати **карту з поясненнями**: те саме дерево шарів, модулів, класів, fn і типів із посиланнями на код, але під кожним вузлом стоїть пояснення в одне-два речення про те, що він робить. Вмикається опцією. По ній працюють навігація й пошук: у Markdown на GitHub, у TUI та `keylang web`, через MCP `search` і LSP-символи workspace.

## Рішення користувача (2026-09-28)

1. **Джерело пояснення:** спершу коментар документації в коді, для решти — brief від моделі.
2. **Зберігання:** у git поруч із картою. Пояснення переїжджають із `.keylang/explain/` у закомічену теку.
3. **Навігація й пошук:** TUI/web, Markdown у GitHub/редакторі, MCP `search`, LSP workspace symbols.
4. **Граматика:** посилання можна писати як `[id](href)`, щоб `calls` і залежності були клікабельні.

## Контракт (ескіз; точну форму фіксують тікети у format.md)

**Опція.** `keylang.json`: `"explain": { "map": true }`. Типово `false`. Значення не типу boolean дає код 2 з назвою поля `explain.map`.

**Файли.**

| Шлях | Що | У git |
|---|---|---|
| `<dir>/map/<layer>.md` | канонічна карта, без змін | так |
| `<dir>/map-explained/<layer>.md` | карта з поясненнями | так |
| `<dir>/map-explained/README.md` | зміст: шари з поясненнями, лічильники, посилання | так |
| `<dir>/explain/<id>.md` | пояснення на запит (`short`/`full`), раніше `.keylang/explain/` | так |
| `<dir>/explain/brief/<id>.md` | brief від моделі для карти з поясненнями | так |

**Вигляд вузла** (приклад; остаточну форму задає тікет 03, якорі й лінки — тікет 07):

```
  - module [assess](../../src/assess.ts#L1)
    Combines resolver, rule, flow and wiring checks into one assessment of the specs.
    - fn [assess](../../src/assess.ts#L29) (…) → Assessment
      Runs every check over the docs and snapshot and merges their verdicts. _(llm · claude-sonnet-5 · 2026-09-28)_
      - calls [check.resolve.check](check.md#check.resolve.check), …
```

- Текст із коментаря документації йде без позначки: це слова автора з коду, а посилання на код уже стоїть на вузлі.
- Текст від моделі має видиму позначку `_(llm · <model> · <date>)_`. Застарілий додає `· stale`.
- Вузол без пояснення йде без рядка тексту. Лічильник у `README.md` показує, скільки таких вузлів.

**Пріоритет джерел для вузла:** коментар документації → brief від моделі (свіжий чи `stale`) → нічого. `short`/`full` у карту не йдуть.

**Детермінованість.** Карта з поясненнями — функція джерел і закомічених файлів `<dir>/explain/`. `keylang map` моделі не викликає. `map --check` перевіряє обидві карти й нічого не пише.

**Не специфікація.** Файли `map-explained/` і `explain/` ніколи не потрапляють в оцінку `check`. Результат `check` з увімкненою опцією і без неї однаковий. Карта з поясненнями — валідний keylang: `parse` дає нуль діагностик, `fmt --check` проходить.

## Припущення (зафіксовані без окремого питання)

- Рівні: шар, модуль (зокрема модуль-тека), клас, fn, тип. Шар коду не має, тож його пояснює лише модель.
- Модуль-тека бере коментар документації з файла-індексу мови (`index.ts`, `mod.rs`, `__init__.py`).
- Коментарі документації беруться дослівно, без перекладу. Brief пишеться мовою `explain.lang`.
- Для TS/JS декларацію документує лише `/** … */`. Звичайний `//` над fn — це нотатка, а не документація. Для модуля годиться перший блок коментарів файла, відокремлений від першої декларації (точне правило — тікет 01).
- Brief-и генеруються знизу вгору: fn/тип → клас/модуль → шар. Промпт батька отримує brief-и дітей.
- Стара тека `.keylang/explain/` не читається. `explain` і `doctor` підказують, як перенести файли.
- `stale` для модуля й шару рахується, як зараз у `currentBaseline`: за всіма членами.

## Несумісні зміни

- `explain <id> --llm` пише в `<dir>/explain/` замість `.keylang/explain/`.
- Граматика: у позиціях посилань дозволено `[id](href)`. Старі файли лишаються валідними.

## Поза обсягом

- Пояснення потоків і правил у карті з поясненнями: у карті їх немає.
- Переклад коментарів документації.
- Генерація коментарів документації в код (можна окремою пропозицією через `.keylang/proposals/`).
