# 34: Кожне рішення Р1…Рn має виконуваний приклад

**Джерело:** research-pl §5 Р-6 («Готово, коли: кожне рішення Р1…Р14 у format.md має щонайменше один виконуваний приклад»); знахідка 9

**What to build:** Кожне рішення **Рn** у format.md отримує щонайменше одну групу-приклад у форматі 32. Групу позначає токен в info-рядку: `keylang Р7 path=…`. Літера Р кирилична (U+0420), як у тексті рішень. Тест збирає всі `**Рn.` у format.md і для кожного вимагає позначену групу. Рішення без прикладу тест перелічує в повідомленні.

Зараз шаблон `**Рn.` знаходить 13 рішень: Р1–Р12 і Р14. Р9 стоїть у §8, :365. Р13 записано в дужках усередині пункту §6 (:213: `(**Р13**, слайди: …)`), тому тікет виносить його окремим пунктом `**Р13. …**` у §6. Це правка лише документації, зміст рішення не змінюється.

Харнес 32 отримує блок `fmt`, що стоїть одразу після огорожі `keylang`. Блок задає одне з двох:
- очікуваний текст після `keylang fmt` цього файла. Харнес додатково перевіряє, що другий `fmt` нічого не змінює;
- відмову, якщо кожен непорожній рядок блоку — діагностика `<файл>:<рядок>:<колонка>: K003 …`. Тоді очікуються код 1, ці рядки в stderr і файл, байт у байт такий самий. Так `fmt` поводиться зараз (перевірено на `   - module b`).

Приклади:
- Р1: колонка K001 для другого ID у `calls a, b`;
- Р2: файл у `keylang/flows/` з `# rules` — це правила; файл без заголовка — карта;
- Р3: дві секції `# flow` в одному файлі; два потоки з однаковим ім'ям дають K002;
- Р4: `fmt` відмовляє на K003;
- Р5: `fmt` вставляє порожній рядок перед прозою з відступом 0;
- Р6: `fmt` переносить опис під рядок вузла;
- Р7: `test foo.bar` під модулем — залежність;
- Р8: `allow` на верху карти;
- Р9: огорожа закриває список. Якщо 03 злито раніше, блок `fmt` показує огорожу з колонки 0;
- Р10: `then` з ID проти текстового `then`;
- Р11: подію в `emits` не резолвимо;
- Р12: `trigger` на аліас залежності;
- Р13: без знімка модуль без членів непрозорий і K001 немає; з keylang.json і src/*.ts, де модуль `complete`, невідомий член дає K001;
- Р14: продовження шару у двох файлах не дає K002; повторний модуль дає K002 з позицією першого оголошення.

Рішення, які додають інші тікети, тест вимагає автоматично. Р15 з 02 (Q3): якщо 02 злито раніше, приклад Р15 додає цей тікет; якщо пізніше — його додає 02, бо без прикладу тест падатиме. Правило «кожен K-код має приклад» у цей тікет не входить: `explain` уже покриває кожен код (tests/cli.test.ts:1232).
