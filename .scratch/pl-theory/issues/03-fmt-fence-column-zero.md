# 03: `fmt` пише огорожу коду з колонки 0 (Р9)

**Джерело:** research-pl §5 Р-2; знахідка 5; рішення Q4 (spec)

**What to build:** Огорожа з відступом одразу під елементом списку для keylang закриває список (Р9), а для CommonMark лишається всередині елемента. fmt вставляє перед нею порожній рядок, але відступ лишає, бо код виводиться дослівно (§8, src/fmt.ts:32). Тож розбіжність лишається й після fmt: на виводі fmt `fmt --check` дає 0, а GitHub показує блок усередині елемента.

Відтворення: `# map`, порожній, `- layer a`, `  - module b`, огорожа з відступом 4 з рядком `x`. fmt дає порожній рядок після `  - module b` і ту саму огорожу з відступом 4.

fmt знімає з рядків огорожі, відкривної й закривної, увесь їхній відступ. З кожного рядка вмісту він знімає стільки пробілів, скільки мала відкривна огорожа, але не більше, ніж є в рядку: так CommonMark читає вміст огорожі з відступом. Значення для keylang не змінюється — вузли, діагностики й вердикти ті самі, — а GitHub після fmt показує блок поза списком, як його читає keylang. Блок, у відступі огорожі якого є таб, fmt лишає як є (§3: таб у відступі блоку коду — текст).

Рекомендовано зливати після 02: обидва тікети правлять огорожі, але кожен працює без іншого.

**Blocked by:** None (can start immediately)

**Status:** resolved
