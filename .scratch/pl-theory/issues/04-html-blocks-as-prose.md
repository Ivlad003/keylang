# 04: Сирі HTML-блоки типів 1–5 — проза: закоментований рядок специфікації не перевіряється

**Джерело:** research-pl §5 Р-2; знахідка 5; рішення Q5 (spec)

**What to build:** Зараз рядок `- deny a b` між рядками `<!--` і `-->` — вузол `deny`, і `check` його перевіряє, хоча GitHub цей рядок ховає. `# flow x` усередині такого коментаря відкриває нову секцію. Так само з блоками `<pre>`, `<script>`, `<style>`, `<textarea>`, `<?…?>`, `<!X…>` і `<![CDATA[…]]>`: GitHub не показує їхній вміст як список. fmt не допомагає: HTML-блоки типів 1–5 CommonMark не закриваються порожнім рядком, а fmt ще й зводить порожні рядки всередині `<pre>` до одного.

Мінімальне відтворення: `keylang/rules.md` нижче, `check` → K001 на 4:8 і 4:10, код 1.

~~~~markdown
# rules

<!--
- deny a b
-->
~~~~

Рядки HTML-блоку типів 1–5, від рядка з маркером початку до рядка з кінцевим маркером, стають прозою в наявному Item `prose` дослівно, разом із порожніми рядками. Рядок усередині блоку не стає ні заголовком, ні огорожею, ні елементом. Маркери — як у CommonMark: `<!--` … `-->`, `<?` … `?>`, `<!` з літерою … `>`, `<![CDATA[` … `]]>`, `<pre`, `<script`, `<style` чи `<textarea` без урахування регістру … відповідний закривний тег. Рядок початку має відступ 0–3 на верхньому рівні або не більше 3 понад колонку вмісту елемента. Блок, що почався з відступом ≥ 2 під відкритим елементом, дає описи цього елемента за правилом §3 «Опис вузла». Такий блок закінчується й разом з елементом: на першому непорожньому рядку з відступом, меншим за колонку вмісту елемента. Незакритий блок верхнього рівня триває до кінця файла, як у CommonMark.

Не змінюються:
- однорядкові коментарі (початок і кінець в одному рядку): маркер генерації, `keylang:llm`, `keylang:algo`; коментар елемента чи заголовка HTML-блоку не відкриває взагалі;
- HTML-блоки типів 6–7, зокрема `<details>`: їх уже виправляє порожній рядок, який вставляє fmt.

fmt лишає блок дослівно, разом із порожніми рядками всередині (src/fmt.ts:32 уже виводить рядки `prose` як є). Відтак `<!-- -->` стає задокументованим способом вимкнути рядок специфікації. Багаторядкових блоків типів 1–5 у корпусі репозиторію немає (grep по `keylang/`, `examples/`, `tests/fixtures/`), тож карта й наявні фікстури не змінюються.

**Контракт:** семантика: рядки всередині багаторядкових HTML-блоків типів 1–5 перестають бути вузлами, заголовками й огорожами. Для текстів, де так закоментовано рядки специфікації, це несумісно: зараз вони перевіряються, хоча GitHub не показує їх як список. Канонічна форма: fmt зберігає порожні рядки всередині такого блоку. IR і форма `parse --json` не змінюються (наявні `prose` і `Node.description`), нового коду діагностики немає.
