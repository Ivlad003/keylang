# 47: `never <b> before <a>`: виклик лише після передумови

**Джерело:** research-pl §5 Р-13; знахідка 3; рішення Q23 і Q15 (spec)

**What to build:** `- never <b> before <a>` стоїть у тих самих позиціях, що `never` (45). Він означає, що в межах кожного виклику області жоден виклик `<b>` не починається, доки не завершився виклик `<a>` (шаблон precedence, ¬b W a). Парсер розрізняє дві форми `never` за токеном `before`, який є ключовим лише в цій формі.

Відношення порядку те саме, що для сусідніх кроків після 13: `<b>` іде після `<a>`, коли почався після завершення `<a>` на тому самому годиннику або має `links` на `<a>`. `links` підтверджують порядок лише для `<b>` поза піддеревом `<a>`, а `<b>`, вкладений в `<a>`, — порушення.

Вердикти рядка `trace`:
- `fail` — надійно спостережене порушення, тобто `<a>` є в `instrumented` і `dropped: 0`. Порушенням вважається `<b>`, що почався до завершення першого `<a>` на тому самому годиннику без підтвердження `links`, зокрема вкладений в `<a>`. Порушення — і `<b>` без жодного `<a>` перед ним, якщо `<a>` немає й в інших деревах викликів (правило 11). Повідомлення називає обидва символи й тест;
- `ok` — запуск завершений, `dropped: 0`, обидва символи є в `instrumented`, і кожен `<b>` іде після `<a>`. Без жодного `<b>` теж `ok`;
- `unverified` — в інших випадках: `<b>` на іншому годиннику без `links`, неповний запуск без спостереженого порушення, символ поза `instrumented`.

Обидва ID потрапляють у `flowSymbols` так само, як у 45.

Нова форма має потрапити в EBNF-блок format.md, інакше тест 33 впаде.

**Status:** needs-triage

**Контракт:** нова граматика (форма `never … before …`). JSON-вивід `check` отримує нові результати `trace` з `area` `never <b> before <a>`. Сумісно: жоден валідний текст не змінює значення.

## Що має вирішити тріаж

- Коли брати: після 45 і заморожування v1 (Q23).

- [ ] `never a.b before` і `never before a.b` дають K005 з позицією. Висяче ID у будь-якому з двох місць дає K001 на своєму span. Коректна форма ідемпотентна у `fmt`.
- [ ] CLI-тест на одному годиннику:
  - `charge` після завершення `authorize` — `ok`;
  - `charge` до `authorize` — `fail` з обома символами;
  - `charge`, вкладений в `authorize`, — `fail`;
  - `charge` без `authorize` — `fail`;
  - без обох — `ok`.
- [ ] `charge` на іншому годиннику без `links` дає `unverified`. `charge` поза піддеревом `authorize` з `links` на нього дає `ok`.
- [ ] EBNF-блок оновлено, тест 33 зелений. grammar.md §5 і «Flows: докази кроку» описують форму.
- [ ] `npm run typecheck`, `npm test`; `node bin/keylang.js map` (diff переглянуто, разом із картою з поясненнями: `explain.map` увімкнено), `node bin/keylang.js map --check` = 0, `node bin/keylang.js check` на репозиторії — 0 fail.
