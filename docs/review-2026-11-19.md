# keylang — рев'ю 2026-11-19: поріг входу, потрібність, складність

Дата: 2026-11-19. Охоплення: `master` на `f57d9a7` (0.8.0), README, `llm.txt`, `docs/`, курс, `src/`, `.scratch/`, бенчі й попередні рев'ю. Питання рев'ю: що заважає людині почати користуватися keylang, чому він ще не потрібен ширшому колу користувачів і які технічні проблеми та проблеми складності є зараз.

Метод: три незалежні проходи (онбординг; технічний стан; позиціювання й поверхні), потім звірка кожного висновку з файлами й тікетами. Репозиторій не змінювали, крім цього файла, рядка в `docs/README.md` і тікетів у `.scratch/first-five-minutes/`.

**Не перевірено.** `npm test`, `npm run typecheck`, `keylang check` і `map --check` не запускались: у чекауті немає `node_modules` (`node bin/keylang.js --help` → `ERR_MODULE_NOT_FOUND: smol-toml`). Останні відомі результати — у [HANDOFF-2026-10-04](../.scratch/HANDOFF-2026-10-04.md) (616 тестів, 0 fail) і [рев'ю 2026-10-05](review-2026-10-05.md) (738 тестів, 1 fail через паралельну сесію). Оцінки «поріг», «шум», «потрібність» нижче — висновки з коду й документів, а не з даних від людей.

## Головне

1. **Ядро якісне; проблема не в ньому.** У `src/` 0 `any`, 0 `as unknown as`, 0 `@ts-ignore`. 115 тест-файлів через справжній CLI, три рев'ю з відтворенням знахідок, 342 закриті тікети. Шлях `init → check` займає дві команди.
2. **Під однією назвою три продукти, і README продає найдорожчий.** Перший абзац `README.md:7` обіцяє spec-first розробку («an agent generates the code from that spec»). Це шлях із 10+ понять, і на людях його не перевіряли. Найзавершеніша й унікальна частина — паркан для агентів і CI: агент не може ні зламати шар, ні тихо послабити специфікацію (K108, пропозиції).
3. **Поверхня більша за ядро.**
   - CLI: 36 команд, 49 прапорців, `--help` на ~385 рядків, що починається з п'яти форм `web`.
   - Ще 17 інструментів MCP і 27 кодів діагностик.
   - TUI, web і діаграми — близько 35 тис. рядків зі 98 тис. у `src/`, тобто більше за ядро.
   - Останні 60 комітів — UI й адаптери, а не цикл `init → check`.
4. **Перші п'ять хвилин не ведуть до результату.**
   - Перша команда в README — на рядку 69.
   - `init` не каже, що робити далі.
   - Порушення правила не містить виправлення.
   - Приклади без коду, тож нічого не доводять.
   - Готового CI-рецепта немає, довідкові документи — лише українською.
5. **Немає зовнішньої перевірки людьми.** Проба зручності (design-v0.2/28) пройшла лише як AI-пілот. Наскрізний прогін харнеса (harness-integration/11) теж робили headless-агенти. Стороннього користувача немає, 0.8.0 не опубліковано.
6. **Технічний борг інфраструктури, а не коду.**
   - Немає CI.
   - У git лежать 860 файлів недетермінованого виводу моделі.
   - P1-кандидати з рев'ю 2026-10-11 не відтворено й не заведено тікетами.
   - 111 файлів лежать пласко в `src/`, а власний `keylang.json` перелічує ~150 шляхів вручну.

**Рішення людини 2026-11-19:**
- головна роль — **паркан для агентів і CI**;
- периферію позначити **experimental** і сховати з короткої довідки та README, код не чіпати;
- перший крок — цей документ і тікети траншу 1 ([`.scratch/first-five-minutes/`](../.scratch/first-five-minutes/spec.md)).

## 1. Позиціювання

| Робота | Команди | Поріг | Стан |
|---|---|---|---|
| A. Розібратися в чужому репо | `tour`, `entries`, `coverage`, `flows discover`, `web --read-only` | нуль конфігурації, нічого не писати | працює без `keylang.json` (`src/config.ts` вгадує шари) |
| B. Паркан для агентів і CI | `init` → `rules.baseline.md` → `check`, `map --check`, `hook stop`, K108, пропозиції | 2 команди | найзавершеніше; прогнано headless-агентами (harness-integration/11) |
| C. Spec-first: людина пише spec, агент — код | flows, `planned`, `feature`, `spec-to-code`, `scaffold`, wiring | 10+ понять | AI-пілот, людей не було |

Розбіжність між документами:
- `README.md:7` і курс описують C.
- `docs/design.md` §1 описує A, B і окремо економію токенів.
- `CONTEXT.md` — словник, користувача він не називає.
- `llm.txt` (302 рядки) звертається до агента й найчесніше каже, для чого інструмент не годиться.

Аналоги — dependency-cruiser, import-linter, ArchUnit, Structurizr ([research-pl](archive/research-pl.md)). Усі вони вміють «заборони імпорт A → B». Чого вони не вміють і що вже є в keylang:
- агент не може тихо послабити правило: K108, `apply_diff` лише як пропозиція, deny-правила харнеса;
- Stop-hook блокує хід агента лише на новому порушенні;
- готовність фічі визначає `feature`, а не тести;
- один і той самий паркан працює для Claude Code, Codex, Cursor і opencode (ADR 0005).

Тому роль B — найкращий кандидат на перший план. Роль A — безкоштовний вхід у B: «спершу подивись, що keylang бачить у твоєму репо». Роль C — просунутий трек курсу.

## 4. Довіра до результату

- **Багато чесних `unverified`.** Без типів найбільша група викликів — `dynamic`: Python має 1026 resolved проти 1927 dynamic, Magento — 47–72 % розв'язаних ([bench/results.md](../bench/results.md)). Семантичний бекенд TS (M10, ts-semantic-backend) стоїть на паузі.
- **Ризики з [рев'ю 2026-10-06](review-2026-10-06.md) §3:**
  - `--strict` шумить, і команди його вимикають;
  - «N ok» читають як «сценарій працює»;
  - звіти tests/trace можна підробити;
  - trace надійний лише в одному процесі.
- **Різна база для `--changed`.** `feature` бере merge-base з основною гілкою (`src/git-changes.ts:327-331`). `check --changed` порівнює з HEAD, тож на чистому дереві CI порівнювати нема з чим. CI-рецепт має запускати повний `check` або передавати `--since`. Без готового рецепта люди помилятимуться (ризик 3 рев'ю 2026-10-06).

Що в порядку:
- типізація чиста;
- немає native-збірки (tree-sitter працює як WASM);
- рядок оголошення дає детерміновану карту;
- коди виходу і розділення stdout/stderr тримаються;
- MCP швидкий (7–25 мс на виклик за рев'ю 2026-10-05).

## 6. Зовнішня перевірка

- **Проба з людьми.** [Протокол](usability-probe.md) готовий з 2026-09-29, але проведено лише [AI-пілот](archive/usability-probe-results-2026-10-04-ai-pilot.md). Тікет design-v0.2/28 — `ready-for-human`, і від нього залежить заморожування формату v1 (design-v0.2/40).
- **Харнес.** [harness-integration/11](../.scratch/harness-integration/issues/11-dogfood-harnesses.md) прогнав `claude -p` і `codex exec` на NestJS і FastAPI RealWorld. Знайшов 7 дефектів (тікети 12–18, усі закриті), зокрема хибний `done` через переписаний файл фічі. Людина цей цикл ще не проходила.
- Ні стороннього користувача, ні звіту чи issue ззовні.

Поки цього немає, кожна нова поверхня лишається здогадом. Наступну поверхню варто додавати лише після того, як п'ятеро сторонніх людей пройдуть `init → check → перше порушення`.

### Транш 2 — менше складності (без тікетів, дорожня карта)

- Не комітити вивід моделі в цьому репозиторії (`keylang/explain/**`, `keylang/map-explained/`) або генерувати його лише на реліз.
- Розкласти `src/` по теках шарів, щоб `keylang.json` складався з кількох глобів. Це водночас приклад і перевірка моделі «шар = тека».
- Важкі залежності (`@anthropic-ai/sdk`, SQL і Prisma, MCP SDK) — лише через ледачий `import()` у тих командах, яким вони потрібні.
- Англомовна довідка команд, згенерована з таблиці тікета 01.
