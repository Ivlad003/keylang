# Формат keylang — специфікація v0.2

Точна граматика Markdown-форми keylang, як її читає поточний CLI. Загальні ідеї — у [`design.md`](design.md) §3; тут записано, як саме парсер (`src/parser.ts`) розбирає файл і які неоднозначності як вирішено. Рішення позначено **Р1…Рn**, щоб на них можна було посилатися в рев'ю. Формат v1 не заморожено: те, чого в цій специфікації немає в розділі «Дорожня карта», не є поточною поведінкою.

## 1. Модель файлу

Файл — послідовність рядків (`\n` або `\r\n`). Кожен рядок належить до одного з класів, які перевіряються в такому порядку:

| Клас | Умова | Що стає в IR |
|---|---|---|
| рядок у code fence | між відкривною і закривною огорожею | `Item::Code` (рядки дослівно) |
| порожній | лише пробіли | закриває абзац прози; список **не** закриває |
| маркер генерації | перший непорожній рядок файлу, починається з `<!--` і містить `keylang:generated` | `Document.generated` |
| заголовок секції | відступ 0, `#` і далі пробіл або кінець рядка | нова `Section` |
| огорожа коду | після відступу `` ``` `` або `~~~` | відкриває `Item::Code`, закриває список |
| елемент списку | після відступу `-`, `*` або `+`, далі пробіл або кінець рядка | `Node` |
| опис | інший текст, відступ ≥ 2, і є відкритий елемент списку | `Node.description` |
| проза | усе інше | `Item::Prose`, закриває список |

Заголовки `##` і глибші, таблиці, цитати, нумеровані списки — це проза: вони не мають семантики, але зберігаються й форматуються дослівно.

**Р1. Власний рядковий парсер замість pulldown-cmark/comrak.** keylang використовує вузьку підмножину Markdown. CommonMark-парсери дають вузли з діапазонами байтів, але для LSP нам потрібні позиції кожного *слова* всередині елемента (ключове слово, ім'я, кожне ID у `calls a, b`), а також власні правила для лінивих продовжень, табів і відступів — їх однаково довелося б дописувати поверх AST. Рядковий парсер займає ~600 рядків TypeScript, дає точні `offset/line/col` для кожного токена і власні діагностики (K003) замість мовчазної «перебудови» дерева, як це робить CommonMark. Ціна — ми не розуміємо вкладених у елементи списку code fence (див. Р9).

## 2. Секції та види файлів

```
heading  := "#" " " kind [" " name]
kind     := "map" | "rules" | "flow" | "wiring"
name     := segment
```

| Заголовок | Вид секції | Типовий файл |
|---|---|---|
| `# map` | map | `keylang/map/*.md` (генерується) |
| `# rules` | rules | `keylang/rules.md` |
| `# flow <name>` | flow, `name` обов'язковий | `keylang/flows/*.md` |
| `# wiring` | wiring | `keylang/wiring.md` |

- **Р2. Вид визначає заголовок, а не шлях файлу.** Тому `rules.md` може лежати будь-де, а файл без жодного заголовка (як на слайдах) — це секція **map**.
- **Р3. В одному файлі може бути кілька секцій**: кожен `# …` починає нову (наприклад, кілька `# flow` в одному файлі). Вміст до першого заголовка — неявна секція map.
- Невідомий заголовок першого рівня (`# Shop`) — попередження **K006**, секція вважається map.
- Зайві слова в заголовку — K005; `# flow` без імені — K005.
- Імена потоків — окремий простір імен: `# flow checkout` не конфліктує з ID карти, але два потоки з однаковим ім'ям — K002.

### Маркер генерації

```
<!-- keylang:generated — не редагувати, `keylang map` -->
```

Має бути першим непорожнім рядком. Текст після `keylang:generated` довільний. Парсер записує маркер в IR (`generated`), форматер зберігає його.

`keylang map` перевіряє **усі цільові файли** в `<dir>/map/` до будь-якого запису чи видалення. Файла ще немає — його буде створено. Перший непорожній рядок містить маркер — файл можна перезаписати. Інакше це конфлікт: повідомлення `manual file without keylang:generated marker` зі шляхом, код виходу 1, жоден файл карти й індекс не записуються і не видаляються. Зайвий файл видаляється лише тоді, коли він сам має маркер. `map --check` повідомляє той самий конфлікт окремо від застарілої карти (`stale`) і теж нічого не пише.

Коментар `<!-- keylang:llm … -->` (позначка, що фрагмент написав LLM) у M0 зарезервовано: парсер не надає йому семантики — як і будь-який інший HTML-коментар, він стає прозою, описом або коментарем елемента.

## 3. Відступи та ієрархія

- Глибина елемента = відступ / 2. Відступ — лише пробіли.
- Дочірній елемент може бути глибшим за батьківський рівно на один рівень.

| Помилка | Код | Відновлення |
|---|---|---|
| непарний відступ (`   - x`) | K003 | глибина = відступ / 2 з округленням вниз |
| стрибок більш ніж на рівень | K003 | елемент стає дитиною попереднього |
| таб у відступі | K003 | таб рахується як 2 пробіли |
| порожній елемент (`- `) | K003 | рядок пропускається |

**Р4. `keylang fmt` відмовляється форматувати файл з K003**: інакше форматер мовчки змінив би вкладеність. Семантичні помилки (K001, K002, K004, K005) форматуванню не заважають.

### Опис вузла

Текстовий рядок (не елемент списку) з відступом ≥ 2 стає описом найглибшого відкритого елемента, у якого колонка вмісту (`2·глибина + 2`) ≤ відступу рядка. Порожні рядки між елементом і описом дозволені.

```markdown
- deny domain infrastructure
  Домен чистий: жодного I/O.
```

- **Р5. Рядок з відступом 0 завжди проза і закриває список**, навіть без порожнього рядка перед ним. CommonMark у цьому разі вважає рядок «лінивим продовженням» останнього елемента; keylang — ні, а `fmt` вставляє порожній рядок, тому GitHub показує те саме, що бачить keylang.
- **Р6. Опис завжди належить вузлу, а не місцю.** Опис, записаний після дітей вузла, `fmt` переносить одразу під рядок вузла.
- HTML-коментар в окремому рядку — це звичайний текст: опис або проза.

## 4. Елемент списку

```
item     := indent bullet " " head [" " comment]
bullet   := "-" | "*" | "+"                ; fmt замінює на "-"
head     := token (sep token)*
token    := link | quoted | word | ","
link     := "[" text "](" target ")"       ; target без пробілів
quoted   := '"' <будь-що, крім '"'> '"'
word     := <символи до пробілу, табу або коми>
comment  := "<!--" <до кінця рядка>
```

- Кома — окремий токен, тому `a,b` і `a , b` означають те саме, що `a, b` (канонічна форма).
- Незакрита лапка — K005, токен читається як слово. `[`, що не відкриває посилання, — звичайне слово (сигнатури на кшталт `(errs: [Span, string][])`); K005 «malformed link» буває лише там, де очікується ім'я-посилання (`fn [name](path#Lnn)`).
- `<!-- … -->` у кінці рядка — коментар до елемента (`Node.comment`), у семантиці не бере участі (приклад — `compose` у design.md §5).

### Ідентифікатори

```
segment  := (літера | "_") (літера | цифра | "_" | "-")*
id       := segment ("." segment)*
```

Літери — будь-які Unicode. Дефіс дозволено (`http-retry`, `order-store`).

### Прив'язка до коду

`[name](path#Lnn)` на місці імені оголошення: `name` стає іменем вузла, `path` і `nn` зберігаються в `Node.link` (підтримується і `#L12-L20`, береться початковий рядок). У M0 існування файлу не перевіряється. Спан імені вказує на текст усередині `[…]`.

Згенероване посилання рахується **від файла карти**, не від кореня репозиторію: для `keylang/map/domain.md` джерело `src/domain/order.ts` дає `../../src/domain/order.ts#L1`. Кожен сегмент шляху, крім `.` і `..`, кодується через `encodeURIComponent`, а `(` і `)` додатково стають `%28` і `%29`: `encodeURIComponent` їх залишає, але вони обривають Markdown-посилання. Приклад: `src/app/(shop)/page.ts` → `../../src/app/%28shop%29/page.ts#L1`. Пробіл і `#` кодуються як `%20` і `%23`. Парсер декодує шлях: `link.path` і `link.target` містять уже розкодований текст (`(shop)`, а не `%28shop%29`). Індекс зберігає POSIX-шлях від кореня репозиторію без кодування. Зіпсований escape лишається як написано.

Alias залежності не збігається з контекстним ключовим словом цієї позиції (`module`, `fn`, `type`, `event`, `calls`). Генератор додає числовий суфікс (`type` → `type2`), інакше рядок `- type main.type` читається як оголошення типу.

## 5. Ключові слова за позицією

Значення елемента залежить від **батька** (або виду секції на верхньому рівні). Перше слово є ключовим, тільки якщо воно дозволене в цій позиції; інакше спрацьовує правило «без ключового слова», а якщо його немає — K004 зі списком очікуваних слів.

**Р7. Ключові слова контекстні.** Наприклад, під модулем `test foo.bar` — це залежність з аліасом `test`, бо `test` — ключове слово тільки в потоках. І навпаки: під модулем не можна назвати залежність `fn`, `type`, `event` чи `module`.

| Позиція | Ключові слова | Без ключового слова |
|---|---|---|
| верх секції map | `layer`, `layers`, `allow`, `deny`, `entry`, `module`, `no-cycles` | `<name>` — шар (сумісність зі слайдами) |
| верх секції rules | `layers`, `allow`, `deny`, `entry`, `module`, `no-cycles` | K004 |
| верх секції flow | `kind`, `trigger`, `step`, `reads`, `emits`, `calls`, `invariant`, `when`, `test`, `planned` | K004 |
| верх секції wiring | `wire` | K004 |
| під `layer` | `module` | `<name>` — модуль |
| під `module` (map) | `module`, `fn`, `type`, `event` | `<alias> <id>` — залежність |
| під `fn` | `calls` | K004 |
| під `layers`, `entry` | — | `<id>` — посилання |
| під `module` (rules) | `exports`, `no-cycles` | K004 |
| під `step` | `step`, `reads`, `emits`, `calls`, `when`, `test` | K004 |
| під `when` (flow) | `then`, `step`, `test` | K004 |
| під `invariant`, `then` | `test` | K004 |
| під `wire` | — | `<alias> <id>` — перевизначення залежності |
| під залежністю в `wire` | `when`, `compose` | K004 |
| під будь-чим іншим | — | K004 «не може мати вкладених елементів» |

**Р8. Верхній рівень map приймає і правила** (`allow`, `entry`…), бо на слайді карта й правила записані в одному файлі. Верхній рівень rules шарів не оголошує: шари існують лише в карті.

`module` означає різне за позицією: під шаром — оголошення модуля, на верхньому рівні — посилання на модуль, до якого застосовуються правила (`exports`, `no-cycles`).

### Аргументи

| Форма | Аргументи | Семантика |
|---|---|---|
| `layer <name>` / `<name>` | рівно одне ім'я | оголошує `name` |
| `module <name\|link>` / `<name\|link>` | рівно одне | оголошує `parent.name` |
| `fn\|type\|event <name\|link> <signature…>` | ім'я + довільний текст | оголошує `module.name`; решта — `text` (сигнатура) |
| `<alias> <id>` під модулем | два токени | оголошує `module.alias`; `id` — посилання |
| `calls\|reads <id>[, <id>…]` | ≥ 1 ID | посилання |
| `layers <a> < <b> < …` | ID, розділені `<` | посилання на шари; вкладені `<id>` — шари без порядку |
| `allow\|deny <a> <b>…` | ≥ 2 ID | посилання; перший — хто, решта — на що |
| `entry` | нічого; точки старту — вкладеними `<id>` | посилання |
| `module <id>` (rules) | одне ID | посилання |
| `exports <name>[, <name>…]` | імена | публічні імена модуля (відносні); порівнюються з таблицею експортів знімка, K001 не дають |
| `no-cycles` | нічого | — |
| `kind business\|technical` | одне з двох слів | `text` |
| `trigger\|step <id>` | одне ID | посилання |
| `planned fn\|module\|type\|event <id> [signature]` | вид, ID, довільний підпис | намір; не оголошення в індексі і не ребро знімка |
| `emits [event] <name>` | ім'я події | `text`; у M0 не резолвиться |
| `invariant <текст>` | довільний текст | `text` |
| `when <текст>` (flow) | довільний текст | `text` |
| `then <id>` / `then <текст>` | один токен-ID з крапкою → посилання, інакше текст | |
| `test <file> ["<name>"]` | шлях + назва в лапках | `text` = файл, `label` = назва |
| `wire <id>`, `compose <id>` | одне ID | посилання |
| `when <умова> → <id>` (wiring) | текст, `→` або `->`, ID | `text` + посилання |

Порушення форми — K005. Приклад зі слайда: `- options infrastructure.config.server` на верхньому рівні — це шар `options` із зайвим аргументом, тож K005 з підказкою «залежність має бути вкладена в модуль».

**Р10. `then` вгадує форму**: `then application.purchase.OutOfStock` — посилання, `then retry ≤ 3, backoff …` — текст. Критерій — рівно один токен, який є ID і містить крапку.

**Р11. `emits event order.created`** — слово `event` необов'язкове, ім'я події в M0 не перевіряється: у design.md воно не є шляхом карти. Зв'язок з `event` у карті — питання M3.

## 6. ID та резолвінг

- ID оголошення — крапковий шлях від кореня: шар → модуль(і) → `fn`/`type`/`event`/аліас залежності. Приклад: `application.purchase.buy`, `presentation.terminal.checkout` (аліас).
- **Р12. Аліаси залежностей теж мають ID.** Так `trigger presentation.terminal.checkout` з design.md §3.4 резолвиться в залежність `checkout` модуля `terminal`, а `wire` може на них посилатися.
- Посилання всередині файлів завжди абсолютні, крім `exports` (відносно модуля).
- Резолвінг глобальний: `keylang check <dir>` збирає всі `*.md` під директорією (рекурсивно, крім прихованих директорій і `target`), будує один індекс і перевіряє всі посилання.

Правило пошуку ID:

1. Точний збіг з оголошенням — ok.
2. Інакше береться найдовший оголошений префікс. Без знімка модуль без членів непрозорий (**Р13**, слайди: `infrastructure.config.log`). Зі знімком `members: complete` і порожній список дають K001 на невідомого члена, а `members: opaque` (зовнішній модуль, помилка розбору, файл із `exclude`) дає `unverified`, не K001. K001 має підказку `did you mean` і `declare `planned``.
3. Інакше — **K001** висяче посилання з підказкою найближчого сусіда (`did you mean domain.orderAggregate?`). Префікс-шар непрозорим не буває, тому `domain.aggregate` — помилка.

Дублікати:

- **Р14. Шар можна продовжувати в кількох файлах** (`keylang/map/domain.md`, `keylang/map/app.md`) і повторювати в одному. Будь-яке інше повторне оголошення — **K002** з посиланням на перше.
- Посилання під `module <id>` у rules не перевіряються, якщо сам модуль не знайдено (щоб не дублювати помилку).

## 7. Діагностики

Формат виводу `keylang check`: `file:line:col: CODE message`, рядок і колонка з 1, колонка в символах Unicode.

| Код | Рівень | Значення |
|---|---|---|
| K001 | error | висяче посилання |
| K002 | error | дубльований ID (або ім'я потоку) |
| K003 | error | структура: відступ, таб, порожній елемент |
| K004 | error | ключове слово невідоме або недозволене в цій позиції |
| K005 | error | неправильні аргументи відомого ключового слова, невалідне ID/посилання/лапки |
| K006 | warning | невідомий заголовок секції |
| K101 | error | divergence: залежність проти порядку `layers` (вгору або з шару поза порядком) |
| K102 | error | divergence: залежність, заборонена `deny` |
| K103 | warning | absence: модуль недосяжний з жодного `entry` |
| K104 | error | divergence: зайвий публічний експорт або absence — заявлене ім'я, якого модуль не експортує |
| K105 | error | divergence: цикл залежностей там, де оголошено `no-cycles` |

**Правила (K101–K105)** рахуються на ребрах актуального знімка. `keylang check` перебудовує аналіз у пам'яті і не записує карту чи `.keylang/index.json`. Згенеровані файли `map/` замінюються картою, відрендереною з цього знімка, тож ID у flows і rules резолвляться за поточним кодом, навіть якщо закомічена карта застаріла. Корінь репозиторію — найближчий вгору каталог із `keylang.json`; шлях до специфікацій можна записати як завгодно (`keylang`, `./keylang`, абсолютний, `.` зсередини). Діагностика вказує на файл і рядок коду, де є ребро. Якщо в каталозі немає коду (examples, слайд), правила дають `unverified` з причиною `no snapshot`, а резолвінг ID лишається. Підсумок у stderr: `N fail, M unverified, K ok`. `--strict` повертає 1, коли є потрібний `unverified`. `--format human|json|sarif|github` не змінює вердикт. `--explain-edge <a> <b>` друкує ребра або дірку покриття і нічого не пише.

Уточнення:

- `layers a < b < c`: `a` найнижчий; залежність може йти лише вниз (`c` → `a` можна, `a` → `c` — K101). Вкладені під `layers` шари, а також `external` і `unassigned`, — без порядку: залежність *у* них вільна, якщо не заборонена `deny`.
- `allow`/`deny` приймають шари, модулі й їхні префікси. Перемагає найконкретніше правило (довші ID), при рівності — `deny`. `allow` знімає K101 для своєї пари. Кожне `deny` має власний вердикт: підтверджене заборонене ребро — `fail`; інакше `unverified`, якщо в області є прогалина рівня залежностей (нерозв'язаний чи обчислюваний імпорт, синтаксична помилка, виключений файл, `eval`), і `ok` без неї. Виклик через локальне значення залежності між модулями не створює: без імпорту код іншого модуля недосяжний.
- `entry`: досяжність іде лише ребрами `import` / `call` / `re-export` знімка. Ієрархія ID не робить сусідів досяжними. Нерозв'язане ребро з досяжного модуля перетворює недосяжність на `unverified`, а не на K103. Модулі шарів без порядку не перевіряються.
- `exports` порівнюється з таблицею публічних експортів знімка, не з fn без `<!-- internal -->`. Імена в `exports` — публічні імена модуля, а не ID карти, тож K001 вони не дають. `export { a as b }` порівнюється за `b`, `export default …` (включно з `export default function main`) — за `default`, `export * from "./x"` розкривається до імен `x` без `default`. Зайве ім'я — K104 із видом і формою (`alias`, `default`, звідки re-export); заявлене відсутнє ім'я — absence. `export *` із модуля з невідомим вмістом (зовнішній пакет, нерозв'язаний або виключений файл) робить правило `unverified`, а не absence.
- Цикли — це SCC графа `import` / `re-export`. `no-cycles` під модулем спрацьовує, якщо модуль входить у SCC; маршрут проходить через цей модуль. Self-loop теж цикл.
- `planned fn|module|type|event <id> [signature]` — намір. Посилання на нього не є K001; критерії лишаються `unverified`, ребер у знімок він не додає. Точна граматика — кандидат до v1, не заморожений формат.
- Крок flow досяжний від батьківського `step` або `trigger`. Сусідні кроки не потребують ребра між собою. Докази `ID`, `static`, `tests`, `trace` друкуються окремо. `keylang lsp` віддає ті самі коди, позиції й вердикти, що й `check`.

### Дорожня карта, не поточна поведінка

Цього в CLI і LSP ще немає, навіть якщо design.md це описує як ціль: пакет розширення VS Code і залежність `vscode-languageserver`; CodeLens; signature help; доповнення ключових слів за позицією; baseline стейлнесу прози, `--accept` і сценарій «тіло змінилося, сигнатура ні» (тікет 21); упорядкування trace за годинником (`traceOrderProblem`); TUI, web, wiring, Rust, Python, LLM, MCP, ghost і голос. Hover зараз показує вид, сигнатуру, `planned` або `opaque`, файл:рядок і рядки доказів, а не чотири рядки вихідного коду.

## 8. Канонічна форма (`keylang fmt`)

`fmt` рендерить файл з IR, тож `fmt(fmt(x)) == fmt(x)`:

- маркер генерації, заголовки, списки, абзаци прози й блоки коду розділені рівно одним порожнім рядком; усередині списку порожніх рядків немає;
- маркер списку `-`, відступ `2·глибина`, токени елемента через один пробіл, кома — `a, b`, коментар через один пробіл;
- заголовок `# kind name`;
- опис — під рядком вузла з відступом `2·глибина + 2`, текст без кінцевих пробілів;
- проза й код — дослівно (без кінцевих пробілів);
- файл закінчується одним `\n`.

Неявні ключові слова **не** додаються: `- orderAggregate` під шаром лишається як є (слайдова форма рівноправна з `- module orderAggregate`).

**Р9. Code fence всередині елемента списку не підтримується в M0**: огорожа з будь-яким відступом закриває список і стає блоком коду секції.

## 9. IR і позиції (для LSP)

`Document → Section → Item (Node | Prose | Code)`, `Node` рекурсивний. Кожен `Node` має `span` (рядок елемента від маркера до кінця), `keyword` (спан ключового слова або `None`, якщо воно неявне), `name.span`, `link.span`, `refs[*].span`, `text.span`, `description[*].span`, а також сирі `tokens` зі спанами. `Pos = {offset (індекс у рядку JS, UTF-16), line, col (кодові точки)}`. `Index` (`src/resolve.ts`) відображає `id → Decl {file, span імені, kind}` — це вже дає `definition` (посилання → оголошення) і `hover`; `spanContains(span, offset)` — пошук вузла під курсором.

## 11. Семантичний знімок (`.keylang/index.json`)

`keylang map` серіалізує `AnalysisSnapshot` (схема **4**) у `.keylang/index.json` і **рендерить Markdown-карту з цього знімка**. Індекс — кеш фактів, не текст для редагування. Шлях у вузлі знімка лишається POSIX-шляхом від кореня репозиторію; відносне кодоване посилання рахує emitter. Несумісна або зіпсована схема на диску не є помилкою: наступний `map` перезаписує файл без окремої діагностики.

`snapshotId` — SHA-256 канонічного JSON від схеми, версії екстрактора, версій граматик, конфігурації (`dir`, `languages`, `module`, `layers`, `exclude`, `guessed`) і SHA-256 вмісту кожного проіндексованого файла. Поле `generated` (час запису) у хеш не входить. Два запуски на тих самих джерелах дають той самий `snapshotId`; зміна файла або `keylang.json` змінює його.

| Частина | Зміст |
|---|---|
| `manifest` | екстрактор, версії `web-tree-sitter` і `@vscode/tree-sitter-wasm`, конфігурація, `{path, sha256}` файлів |
| `nodes` | ID → вид (`layer` / `module` / `fn` / `type`), шар, файл і діапазон (`line`, `col`, `endLine`, `endCol`: колонки з 1, кінець — позиція після фрагмента). У модуля й типу діапазон є так само, як у функції. У модуля `members`: `complete` або `opaque`. Похідні `deps` / `dependents` / `calls` / `callers` |
| `exports` | публічне ім'я файла → id символу, вид (`fn`, `class`, `type`, `value`) і `form` (`alias`, `default`, `reexport` із `from`). Рядок `*` з видом `reexport` і `reason` — `export *` з модуля з невідомим вмістом |
| `edges` | `kind` (`import`, `call`, `type`, `reexport`), `source`, `target` або `null`, `candidates` коли цілей кілька, `text` (фрагмент коду) і діапазон `line`/`col`/`endLine`/`endCol`, `resolution` (`resolved` / `ambiguous` / `unresolved`), `provenance` (`syntactic`). `ambiguous` означає кілька можливих цілей у `candidates` і порожній `target` |
| `coverage` | нерозв'язаний імпорт, динамічний виклик, нерозв'язаний виклик, `unsupported construct` (namespace, `eval`, `new Function`, виклик `obj[expr]`), обчислюваний specifier, синтаксична помилка, файл поза шаром і пропущений файл — кожен із діапазоном, `text` і `reason` |
| `stats` | лічильники проходу; вони не замінюють записи `coverage` |

Порожній проіндексований модуль має `members: "complete"` і жодного дочірнього символу. `opaque` не підтверджує існування довільного імені. Файл у шарі, виключений через `exclude` у `keylang.json`, стає модулем `members: "opaque"` з коментарем `<!-- excluded -->` у карті і записом `skipped-file` у `coverage`; посилання на його члена — `unverified`, не K001. Нерозв'язаний імпорт і виклик локального значення є і в `coverage`, і ребром з `resolution: "unresolved"`. Ребро `type` — це згадка типу в сигнатурі чи heritage; правила `allow` / `deny` / `layers` бачать його разом із `import`, `call` і `reexport`.

`provenance: semantic` і `provenance: trace`, а також fingerprint тіла без зміни сигнатури, лишаються дорожньою картою, не полями поточного знімка. Схема знімка — **4**.
