# 1. Форма

[Проєкт з нуля](README.md) · [English](../01-the-shape.md) · **Українською**

Розділіть програму на ті самі чотири роботи, що й у крамниці.

- **presentation** — край, з яким стикається людина або інша програма: оновлення бота, HTTP-маршрут, контролер.
- **application** — одне завдання, наприклад зберегти нотатку, створити задачу чи оформити замовлення.
- **domain** — правила, що лишаються правдивими навіть без мережі: у нотатки є текст, у задачі є назва.
- **infrastructure** — бібліотека, база, API бота. Цей шар стоїть поруч з іншими трьома, а не під domain.

Ні domain, ні край не імпортують infrastructure. Це дозволено лише завданню посередині. Сховище ж зберігає те, що створює домен, тож йому потрібні типи домену. Залежність із бічного шару в ланцюг дає K101, доки її не дозволить `allow`.

```markdown
# rules

- layers domain < application < presentation
  - infrastructure
- allow infrastructure domain
  Сховище зберігає об'єкти, які створює домен.
- deny domain infrastructure
- deny domain external
- deny presentation infrastructure
```

Цей файл ви пишете самі. У наступних частинах будуть назви функцій, але самі функції пише агент, а не ви.

Спершу створіть порожній застосунок інструментом його фреймворку. Потім запустіть:

```sh
npx keylang init .
```

Замініть угадані шари в `keylang.json` на шляхи з наступної частини. Поки фіча існує лише як намір, `keylang check` завершується з кодом 0, а кожен planned-рядок має статус `unverified`. `keylang feature` тим часом завершується з кодом 1 і перелічує, чого бракує. Для першого дня це нормально, інструмент не зламаний.

`keylang feature <slug>` вважає фічу готовою, коли кожен рядок `planned` у її файлі збігається з кодом, кожен крок має статичний шлях виклику і від цієї зміни не лишилося жодного fail. Тести і trace друкуються поруч, але на відповідь не впливають. Коли код виходу 0, команда друкує `done` у stderr.

Якщо новий проєкт переносить процес зі старого, першу фічу можна взяти звідти: `keylang flow export <потік> --out flow.bundle.md` у старому репозиторії, `keylang flow import flow.bundle.md` у новому. Без `--layer-map` кожен старий шар потрапляє в шар із тим самим ім'ям, а якщо такого немає — у ваш перший шар із приміткою. `--mode hybrid` просить модель зіставити шари за назвами й описами. Якщо модель назве шар, якого у вас немає, keylang повернеться до того самого правила. На виході ви отримуєте пропозицію фічі з рядками `planned` і старими сигнатурами. Це той самий початок, що й файл, написаний вручну.
