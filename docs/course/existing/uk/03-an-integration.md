# 3. Інтеграція

[Додавання до кодової бази](README.md) · [English](../03-an-integration.md) · **Українською**

Фіча викликає код, який згенерував агент, а інтеграція ще й чужий пакет. Крамниця збирається приймати оплату карткою через пакет `stripe`, і правила замовлення не повинні його імпортувати.

`keylang/features/pay.md`:

```markdown
# flow pay

- planned module external.stripe
- planned fn infrastructure.payments.charge (order: Order) → Receipt
- trigger application.purchase.buy
  - step infrastructure.payments.charge
```

Пакет, указаний у `package.json` (у `dependencies` чи іншому полі залежностей), keylang уже знає як `external.<ім'я>`. Ім'я займає один сегмент: `stripe` стає `external.stripe`, і ім'я з дефісом (`node-fetch`) теж лишається одним сегментом. Проте вказати пакет ще не означає його імпортувати. `planned module` перетворюється на K202 лише тоді, коли якийсь файл справді імпортує пакет і в знімку з'являється цей вузол.

Файлів залежностей Python keylang не читає. Тож пакет із pip лишається невідомим, доки keylang не побачить його імпорту, а імпорт, який він пропустив, так і лишається діркою.

У `keylang/rules.md` тримайте ядро подалі від пакета:

```markdown
- deny domain external.stripe
- deny domain infrastructure.payments
- deny presentation external.stripe
```

З цими правилами `application.purchase` може викликати `charge`, а domain не може, і екран не може сам імпортувати `stripe`.

```sh
npx keylang feature pay
```

Фіча готова, коли імпорт є, `charge` існує з цією сигнатурою, а тіло `buy` доходить до `charge` викликом, який keylang бачить. `charge` пише агент із рядка `planned`, а не ви. Якщо `charge` — це `planned fn` у TypeScript, `spec-to-code` може зробити для неї заготовку, але залежність `stripe` у `package.json` не додасть, тож пакет установлюєте ви.

Деякі виклики keylang не бачить. Виклик, записаний як `obj[k]()`, або крок на функції під незнайомим keylang Python-декоратором чи Rust-атрибутом лишається `unverified`. Фіча тоді лишається відкритою, доки агент не перенесе справжній виклик у звичайну функцію.

Щоб побачити, де код говорить із зовнішнім світом, запустіть:

```sh
npx keylang integrations
```

Команда групує за інтеграціями виклики відомих клієнтів: HTTP, SOAP, SDK на кшталт Stripe, черг. Для кожного виклику вона показує `файл:рядок`, функцію, хост літерального URL, а також точки входу й флоу, які до нього доходять. Після цього йдуть вхідні вебхуки, видавці й споживачі черг. Це лише представлення: команда ні з чим не з'єднується, і `check` її вивід не читає. Щойно агент напише `charge`, виклик Stripe з'явиться там у `infrastructure.payments`. Якщо ж він з'явиться в будь-якому іншому модулі, з цим варто розібратися.

Так само можна підключити будь-яку бібліотеку, хай то пошта, черга чи сховище: один `planned module external.<pkg>`, одна функція в `infrastructure`, яка його обгортає, і `deny` на пакет для кожного шару, якому не можна його імпортувати.
