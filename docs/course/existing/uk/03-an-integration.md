# 3. Інтеграція

[Додавання до кодової бази](README.md) · [English](../03-an-integration.md) · **Українською**

Фіча викликає код, який згенерував агент, а інтеграція викликає ще й чужий пакет. Тут крамниця збирається приймати картки через пакет `stripe`, і правила замовлення не повинні його імпортувати.

`keylang/features/pay.md`:

```markdown
# flow pay

- planned module external.stripe
- planned fn infrastructure.payments.charge (order: Order) → Receipt
- trigger application.purchase.buy
  - step infrastructure.payments.charge
```

Пакет, названий у `package.json` (у `dependencies` та інших полях залежностей), уже відомий як `external.<ім'я>`. Ім'я — це один сегмент: `stripe` стає `external.stripe`, і ім'я з дефісом (`node-fetch`) теж лишається одним сегментом. Проте назвати пакет — не те саме, що імпортувати його. `planned module` стає K202 лише тоді, коли якийсь файл справді імпортує пакет і в знімку є цей вузол.

Файли залежностей Python не читаються. Тож пакет із pip лишається невідомим, доки keylang не побачить його імпорту, а пропущений імпорт так і лишається діркою.

У `keylang/rules.md` тримайте ядро подалі від пакета:

```markdown
- deny domain external.stripe
- deny domain infrastructure.payments
- deny presentation external.stripe
```

З такими правилами `application.purchase` може викликати `charge`, а domain — ні, і екран не може сам імпортувати `stripe`.

```sh
npx keylang feature pay
```

«Готово» означає три речі: імпорт є, `charge` існує з цією сигнатурою, а тіло `buy` доходить до `charge` викликом, який keylang бачить. `charge` пише агент із рядка `planned`, а не ви. Якщо `charge` — це `planned fn` у TypeScript, `spec-to-code` може зробити для неї заготовку, але залежність `stripe` у `package.json` він не додасть, тож пакет установлюєте ви.

Виклик, записаний як `obj[k]()`, або крок на функції під Python-декоратором чи Rust-атрибутом, якого keylang не знає, лишається `unverified`, і фіча лишається відкритою, доки агент не перенесе справжній виклик у звичайну функцію.

Щоб побачити, де код говорить із зовнішнім світом, запустіть:

```sh
npx keylang integrations
```

Команда перелічує виклики відомих клієнтів (HTTP, SOAP, SDK на кшталт Stripe, черги) за інтеграцією: `файл:рядок`, функцію, хост літерального URL, а також точки входу й флоу, які до виклику доходять; далі — вхідні вебхуки, видавців і споживачів черг. Це представлення: ні з чим не з'єднується, і `check` його не читає. Щойно агент напише `charge`, виклик Stripe з'явиться там у `infrastructure.payments`, а виклик у будь-якому іншому модулі — привід для питання.

Та сама форма підходить для будь-якої бібліотеки, чи то пошта, черга або сховище: один `planned module external.<pkg>`, одна функція в `infrastructure`, яка його обгортає, і `deny` на пакет для кожного шару, якому не можна його імпортувати.
