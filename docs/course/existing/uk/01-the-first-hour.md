# 1. Перша година

[Додавання до кодової бази](README.md) · [English](../01-the-first-hour.md) · **Українською**

Не перебудовуйте репозиторій у перший день. Наведіть інструмент на нього, прочитайте, що він бачить, і запишіть кілька правил, які готові тримати.

```sh
npx keylang init .
npx keylang map
npx keylang check
```

`init` вгадує шар з кожної теки, де є код. Якщо є `src/` або `lib/`, здогад бере теки всередині неї. Він пише `keylang.json`, згенеровану карту і `keylang/rules.baseline.md`. Baseline забороняє залежності між шарами, яких у коді ще немає. Прочитайте його. `deny`, який забороняє виклик, що вам ще потрібен, — це розмова, не баг інструмента.

Відкрийте `keylang/map`. Id під функцією — це ім'я, яке ви потім наберете. Копіюйте його з карти. Не вигадуйте коротше.

Правте `keylang.json` лише там, де здогад хибний. Тека з назвою `external` перейменовується (`external_`), бо це слово зайняте. Нову назву видно під час init.

Далі напишіть правила, які ви справді маєте на увазі, у `keylang/rules.md`, окремо від baseline. Двох-трьох рядків досить:

```markdown
# rules

- layers domain < application < presentation
  - infrastructure
- deny domain infrastructure
- deny domain external
```

`infrastructure` стоїть поруч із ланцюгом, не під `domain`. Лівий бік `<` — внутрішній. Правила замовлення не імпортують базу і не імпортують пакет.

`keylang check` нічого не пише. Код виходу 0 означає: немає того, що блокує. `unverified` усе ще дозволений. Код 1 — справжній злам, або застаріла карта, якщо ви запустили `map --check`.

У CI запустіть обидва:

```sh
npx keylang check
npx keylang map --check
```

Зупиніться тут, якщо потрібна була лише огорожа. Наступна частина — для зміни, якої в коді ще немає.
