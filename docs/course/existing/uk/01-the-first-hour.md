# 1. Перша година

[Додавання до кодової бази](README.md) · [English](../01-the-first-hour.md) · **Українською**

Не перебудовуйте репозиторій у перший же день. Наведіть на нього інструмент, подивіться, що він бачить, і запишіть кілька правил, які ви справді готові тримати. Ці правила й будуть специфікацією. Функції, які з'являться пізніше, пише агент, а не ви, і keylang агента не запускає: він лише перевіряє результат.

```sh
npx keylang init .
npx keylang map
npx keylang check
```

`init` вгадує шар за кожною текою, де є код; якщо є `src/` або `lib/`, він натомість бере теки всередині неї. Потім він створює `keylang.json`, згенеровану карту і `keylang/rules.baseline.md`. Baseline забороняє залежності між шарами, яких у коді ще немає, тож нова така залежність, що з'явиться пізніше, буде помічена. Прочитайте його, перш ніж іти далі. Якщо `deny` забороняє виклик, який вам ще потрібен, — це привід для розмови, а не баг інструмента.

Відкрийте `keylang/map`. Id під кожною функцією — це ім'я, яке ви потім набиратимете, тож копіюйте його з карти, а не вигадуйте коротше.

Перш ніж писати правило, спитайте знімок, що він бачить. Жодна з цих команд не пише специфікацію, і `check` їхнього виводу не читає:

```sh
npx keylang flows discover
npx keylang tour
npx keylang entries
npx keylang coverage
```

`flows discover` іде першою: вона пише чернетку флоу для кожної точки входу в `keylang/flows-discovered/` — згенероване представлення, — тож кожен флоу в огляді має свій файл і посилання на діаграму. `tour` друкує одну сторінку для нової людини, без моделі: що система каже про себе, шари з розміром і зв'язністю, бізнес-процеси та їхні флоу, точки входу, інтеграції, сліпі зони й десять функцій, з яких почати читати. `tour --out keylang/tour.md` зберігає її як згенерований файл, а вкладка «Огляд» у `keylang web` показує ту саму сторінку. `entries` перелічує, звідки починається виконання: `bin` у `package.json`, `main`, маршрут із літеральним шляхом, а також маршрути, cron-задачі, споживачі й спостерігачі фреймворку, для якого в keylang є адаптер (Magento, Laravel, Symfony, NestJS, PWA Kit, SFCC, Django, FastAPI, Flask, Celery, Express, Fastify, Next.js). Адаптер вмикається сам, коли репозиторій показує свій фреймворк (маніфест, імпорт, файл конфігурації), а `frameworks` у `keylang.json` це перевизначає. `coverage` каже, де keylang не бачить: функції, до яких не доходить жодна точка входу, модулі з найбільшою кількістю дірок, точки входу без флоу й налаштування, що вирішують поведінку в даних.

Коли один зі знайдених флоу — той сценарій, про який питає новачок, `npx keylang flows adopt <назва>` пропонує його як `keylang/flows/<назва>.md`, а ви приймаєте його командою `npx keylang proposals accept keylang/flows/<назва>.md`. Відтоді `check` тримає його, як флоу, написаний вами.

Правте `keylang.json` лише там, де здогад хибний. Одна деталь: теку з назвою `external` буде перейменовано (`external_`), бо це слово зарезервоване. Нову назву init покаже під час запуску.

Далі запишіть у `keylang/rules.md` правила, які ви справді маєте на увазі, окремо від baseline. Для початку вистачить двох-трьох рядків:

```markdown
# rules

- layers domain < application < presentation
  - infrastructure
- deny domain infrastructure
- deny domain external
```

`infrastructure` стоїть поруч із ланцюгом, а не під `domain`. У ланцюгу лівий бік `<` — це внутрішній шар. Два рядки `deny` означають, що domain не може імпортувати ні базу, ні пакет. Залежність із бічного шару в ланцюг — K101, доки ви її не запишете: якщо сховище зберігає об'єкти домену, додайте `- allow infrastructure domain` з реченням, яке пояснює чому.

`keylang check` нічого не записує. Код виходу 0 означає, що немає нічого, що блокує, а рядки, які ще `unverified`, пропускаються. Код 1 означає справжній злам або, якщо ви запускали `map --check`, застарілу карту.

У CI запускайте обидві команди, щоб ловити і порушені правила, і застарілу карту:

```sh
npx keylang check
npx keylang map --check
```

## Чужий репозиторій

Щоб прочитати репозиторій до роботи в ньому, не треба клонувати його самому чи щось у нього писати. `keylang clone` робить неглибокий клон у кеші keylang (`~/.cache/keylang/repos/<host>/<шлях>`), запускає там `init` без файлів для агентів і будує карту:

```sh
npx keylang clone https://github.com/owner/repo
npx keylang clone https://github.com/owner/repo --explain map-and-ai --dry-run
npx keylang clone https://github.com/owner/repo --explain map-and-ai
npx keylang web https://github.com/owner/repo
```

Перший рядок виводу — де лежить клон; його `keylang/map` відкривайте як свій. Повторний запуск тієї самої команди забирає нові коміти. `--explain map-and-ai` ще й просить модель коротко описати кожен вузол і пише `keylang/map-explained/`; `--explain all` додає докладне пояснення кожного шару. Обом потрібна модель у середовищі, наприклад `KEYLANG_AGENT=cli:claude`, бо `keylang.json` клону належить keylang. `--dry-run` спершу друкує оцінку токенів і нічого не питає. `web` з URL робить клон і відкриває на ньому інтерфейс у браузері.

У клоні `keylang flows discover` і `keylang tour` працюють так само, як вище, і це найшвидший вхід.

Якщо вам потрібна була лише огорожа навколо коду, можна зупинитися тут. Наступна частина — для зміни, якої в коді ще немає.
