# 8. Сценарії

[Курс](README.md) · [English](../08-use-cases.md) · **Українською**

Чотири сесії, з цього репозиторію і з `examples/shop`. Кожна каже, що запустити, що показує знімок і яке рішення він підтримує.

Знімки інтерфейсу — `keylang web` 2026-09-28. Файли trace і тестів у `.keylang/` були старі. Підсумок CLI того самого дерева — `0 fail, 22 unverified, 43 ok`.

## 1. Перейменований модуль

Хтось пише `order domain.aggregate` під `application.purchase`. Модуль на карті — `orderAggregate`.

```sh
node bin/keylang.js check examples/shop
```

![K001, висяче посилання domain.aggregate](../images/cli-shop-k001.png)

Перший рядок — рішення: одрук або застаріле ім'я, і процес падає. Підказка — найближчий id. Другий рядок — інший факт. У прикладі немає TypeScript, тож потік оформлення довести не можна. Виправте id (див. `examples/shop-fixed`) або, якщо модуля справді ще немає, оголосіть `planned` і прийміть `unverified`, доки не прийде код.

```sh
node bin/keylang.js explain K001
```

![Що означає K001](../images/cli-explain-k001.png)

Інтерфейс показує той самий абзац, коли на діагностиці натиснути `?`.

Після виправлення процес виходить з 0, а потік усе одно не доведено:

![Вихід 0, один unverified, бо немає знімка](../images/cli-shop-fixed.png)

Не читайте це як «крамницю перевірено». Читайте як «імена, які можна розв'язати, розв'язуються, а коду, з яким звірити правила, немає».

## 2. Правило шару, яке CI має тримати

Правило цього репозиторію: парсер і перевірка не імпортують екстрактор tree-sitter і не імпортують `web-tree-sitter` напряму. TUI просить аналіз про факти. Сам джерело не розбирає.

![Файл правил із зеленим жолобом](../images/tui-rules.png)

- Жолоб на рядках правил — `✓`. Кожен критерій тримався.
- Кольори йдуть за порядком шарів у `keylang.json`.
- Дерево праворуч — знімок, не малюнок.
- Рядок статусу — `✗ 0  ◌ 22  ✓ 11`. Нуль провалених рядків. Двадцять два, чия найгірша позначка — unverified. Одинадцять повністю ok. Ті одинадцять — правила.

У CI запустіть обидві команди. Жодна не пише файлів:

```sh
node bin/keylang.js check
node bin/keylang.js map --check
```

`check` падає, якщо новий імпорт перетинає `deny`. `map --check` падає, якщо хтось змінив код і не перегенерував карту. Pull request, що додає `import web-tree-sitter` з `src/parser.ts`, падає з K102 на тому імпорті. Файл правил лишається поясненням.

`draft rules` може запропонувати рядок `layers` з того, що код робить сьогодні. Трактуйте це як опис теперішнього. Відредагуйте в правило, яке хочете, перш ніж зливати.

## 3. Потік, доведений частково

Відкрийте `keylang/flows/check.md` і поставте курсор на тригер.

![Рядок тригера: ID ok, trace unverified](../images/tui-flow.png)

| Позначка | Як читати |
|---|---|
| `ID ✓` | `cli.cli.main` є у свіжому знімку |
| `static —` | Не звітувалось. У тригера немає батьківського виклику |
| `tests —` | На цьому рядку не звітувалось |
| `trace ◌` | Звітувалось, і файл trace належить іншому знімку |

Один зелений значок сховав би застарілий trace. Жовтий рядок називає `.keylang/trace/check.jsonl` і старий id знімка.

![Наведення: id ok, trace unverified](../images/tui-hover.png)

`Enter` відкриває функцію. Переглядач лише для читання. `Esc` повертає. TypeScript він не редагує.

![main у src/cli.ts:114](../images/tui-code.png)

Щоб trace став `ok`, запустіть набір тестів, щоб репортер переписав `.keylang/` для поточного `snapshotId`, і знову `check`. Доки хеші не збіжаться, чесна позначка — `◌`. Передайте `--strict`, якщо пайплайн має це відхилити. Якщо trace ви не завели, приберіть `check.trace` з `keylang.json`, і вид перестане звітуватись.

Та сама форма в CLI, середину обрізано:

![CLI: ID ok, static ok, trace unverified](../images/cli-check-repo.png)

`static ok` на `cli.cli.run` — виклик від `main`. Нижче `generateMap` досяжний через типове значення хука `generate`. `--static=behavior` це рахує. `--static=shape` — ні. Підсумок `0 fail, 22 unverified, 43 ok` збігається з інтерфейсом, коли пам'ятаєте: інтерфейс рахує рядки, CLI рахує результати.

![explain cli.cli.cmdCheck](../images/cli-explain-id.png)

## 4. Прочитати репозиторій, перш ніж редагувати

1. `keylang web` або `keylang` у терміналі.
2. `:` і частина шляху.

   ![Палітра, відфільтрована словом rules](../images/tui-palette.png)

   Той самий рух, далі курсор іде вниз до `deny`. Знято після `npm test`, тож рядок стану зелений:

   ![Відкриття правил і рух вниз](../images/tui-rules.gif)

3. `F2` для списку. Специфікації сидять над згенерованою картою.

   ![Список файлів](../images/tui-files.png)

4. На згенерованій карті `Enter` на функції. Файл — `generated, read-only`. Змініть джерело, потім `keylang map`. Markdown руками не правте.

   ![Карта шару lang](../images/tui-map.png)

5. `v`, щоб читати прозу як документ. Жолоб лишається.

   ![Режим читання](../images/tui-read.png)

6. `?`, коли забули клавішу. Esc закриває список.

   ![Список клавіш, потім Esc](../images/tui-keys.gif)

Далі `i`, щоб змінити правило, `Ctrl+S`, щоб записати. `keylang init` на клоні, якого агент не бачив, пише baseline і, де харнес уже є, сервер MCP. keylang агента не запускає. Чернетки лягають у `.keylang/proposals/`. Зливаєте ви, клавішею `m`.

## 5. Слова на карті і фіча, якої ще немає

Знімка для цієї сесії немає.

Увімкніть `"explain": {"map": true}`, запустіть `keylang map`, відкрийте файл шару і натисніть `t`. Те саме дерево, з коментарем документації або збереженим brief під кожним вузлом. `s` шукає вузол за id або за тими словами. `check` не читає `keylang/map-explained/`. Зелений запуск — не твердження, що абзац правдивий.

Шматок роботи, якого ще немає в коді, — `keylang/features/<slug>.md`: id `planned` і потік. Інтеграція, якої ніхто не імпортує, — `planned module external.<pkg>` і крок від модуля, який її імпортуватиме. `keylang feature <slug>` готовий, коли ті оголошення реалізовано, кроки — static `ok` і жодне правило не падає. Тести й trace стоять поруч із відповіддю. Вони її не вирішують.

## Коли не братися

keylang виправдовує себе, коли люди вже сперечаються про шари і ви хочете, щоб та суперечка валила pull request. Він погано пасує, коли:

- Кодова база — один шар, або межі рухаються щотижня і id ніхто не оновлюватиме.
- Баги, які вам важливі, ніколи не видно як імпорт або виклик між модулями.
- Потрібна мова, яку фронтенди не розбирають. Проєкт із суцільних дірок вічно звітуватиме `unverified`.
- Ви хочете, щоб прозу звіряли з кодом. Такої перевірки немає. `check` читає пункти.
- Вам потрібен рантайм-інжектор для Rust. `keylang wire` випускає один корінь композиції на TypeScript.

Мале впровадження, яке все одно окупається: `keylang.json`, короткий `rules.md` з `layers` і двома-трьома `deny`, `check` і `map --check` у CI, і жодних потоків, доки сценарій не вартий trace.
