# 5. Правила

[Курс](README.md) · [English](../05-rules.md) · **Українською**

Правила — обіцянка. Вони живуть у `keylang/rules.md` або в будь-якому файлі із заголовком `# rules`. Вони називають id зі знімка. Модулів не оголошують. Це робить карта.

Цей репозиторій перевіряє сам себе. Жолоб зелений, бо кожен критерій на тих рядках тримався:

![keylang/rules.md в інтерфейсі](../images/tui-rules.png)

`:`, потім `rules`, потім Enter. Курсор іде вниз до `deny`. Ролик знято пізніше, після `npm test`, тож рядок стану зелений:

![Відкриття правил і рух вниз](../images/tui-rules.gif)

Проза зверху — для читача. Пункти — твердження. Тут вони кажуть: шари йдуть `base < extract < lang < check < map < features < tui < cli`. Ядро мови не залежить від карти, екстрактора і `web-tree-sitter`. Перевірка теж. TUI від екстрактора не залежить. Фіксований набір модулів — точки входу. У графі імпортів немає циклів.

## `layers`

```markdown
- layers domain < application < presentation
  - infrastructure
```

Лівий бік нижчий. Потреба може вказувати вниз. Presentation може імпортувати application. Application може імпортувати domain. Domain, що імпортує application, — K101.

Шари, вкладені під пункт, плюс `external` і `unassigned`, не в лінії вгору-вниз. Потреба *в* них вільна, доки `deny` не заборонить. Потреба *з* них в упорядкований шар потребує `allow`, інакше K101.

Кілька рядків `layers` — один порядок. `a < b` і `b < c` разом забороняють `a` → `c`. `a < b` і `c < d` нічого не кажуть про `a` і `d`. Рядок, що суперечить попередньому, повторює шар або має id з крапкою, — K005 і не перевіряється.

Кожен рядок має свою відповідь. `ok`, коли жодна потреба не ламає порядок і в області немає дірки. `unverified`, коли дірка є. `fail` (K101), коли розв'язане ребро вказує не туди. Повідомлення вказує на рядок джерела ребра.

## `allow` і `deny`

```markdown
- allow infrastructure presentation
- deny domain infrastructure
- deny lang external.web-tree-sitter
```

Обидва беруть джерело і одну або кілька цілей. Id — шари, модулі (клас рахується модулем свого файла) або префікси. Id функції, типу, події або прізвиська залежності — K005. Ребра правил — між модулями. Таке правило нічого б не перевірило.

Коли два правила можна порівняти, перемагає вужче. Глибина — число сегментів, не довжина рядка.

У крамниці `deny app.x domain` (2 + 1) і `allow app domain.storefront` (1 + 2) порівняти не можна: одне вужче за джерелом, інше за ціллю. Суми рівні, тож перемагає `deny`, і K106 немає.

`allow app.x.y domain` (3 + 1) і `deny app domain.storefront` (1 + 2) теж порівняти не можна. У форматі 1 більша сума віддає перемогу allow, і keylang попереджає K106, доки правило не назве перетин `app.x.y domain.storefront`. Формат 2 віддає перемогу тому deny, і K106 все одно попереджає. Пропустіть `format` — ви на форматі 1. Немає `keylang.json` взагалі — формат 2.

`allow` також знімає K101 для своєї пари. Так `infrastructure → presentation` лишається законним у крамниці.

Одна потреба модуля від модуля дає одну K102, скільки б ребер її не показували. Повідомлення називає ребро і рядок `deny`.

`deny` — `fail`, коли заборонене ребро розв'язане; `unverified`, коли в області дірка і забороненого ребра немає; `ok`, коли область прочитано повністю і ребра немає. Зелений `deny` — твердження про ребра, які keylang записав. Це не доказ, що жодна функція не робить введення-виведення каналом, якого фронтенд не бачить.

## `entry`, `exports`, `no-cycles`

```markdown
- entry
  - infrastructure.server
  - presentation.terminal
- module application.purchase
  - exports buy, cancel
  - no-cycles
```

`entry` перелічує, звідки програмі можна стартувати. Досяжність іде ребрами import, call, type і re-export. Модуль в упорядкованому шарі, до якого не доходить жоден entry, — попередження K103. Дірка в досяжному модулі перетворює це на `unverified`, бо відсутнє ребро могло бути шляхом. Entry, що називає відсутній модуль, — K001, тож видалений worker, якого ви перелічили, лишається видимим. K103 процес не валить.

`exports` порівнює названі імена з публічними експортами того модуля. `export { a as b }` — це `b`. `export default` — `default`. Зайвий публічний експорт — K104. Назване ім'я, якого модуль не експортує, — теж K104. Якщо `export *` іде з непрозорого модуля, правило — `unverified`, а не «ви забули ім'я».

`no-cycles` шукає петлі в графі імпортів і реекспортів. На верху область — весь граф. Під `module <id>` область — той модуль, його підмодулі і модулі, досяжні від них. Цикл — K105. Файл, що імпортує сам себе, — цикл. Дірка без відомого циклу — `unverified`, не `ok`.

## Як читати результат

| Відповідь | Значення |
|---|---|
| `ok` | Твердження трималось, і область покрита |
| `fail` | Порушення показано |
| `unverified` | Порушення не показано, і знімка не досить, щоб твердження пройшло |
| warning | K006, K008, K103, K106, K202. Записано. Не провальний вердикт |

`check` вказує на код для ребра і на специфікацію для поганого рядка. `--explain-edge <a> <b>` друкує ребра між двома id або нерозв'язані конструкції, які могли б їх утворити. Нічого не пише.

`✓` в інтерфейсі означає, що кожен критерій на рядку — `ok`. Рядок, який `ok` за структурою і `unverified` за покриттям, показує `◌`. Підсумок у статусі рахує рядки. `check` рахує кожен результат. Тому інтерфейс може показати 11 пройдених рядків, поки `check` друкує 43 результати `ok`.

## Практичний порядок

1. `keylang init` пише конфіг, карту і baseline. Одразу після `init` baseline не додає нового `fail`. Пізніший імпорт через прогалину — K102, доки ви не додасте `allow` або не запустите `keylang baseline` знову.
2. `keylang draft rules` пропонує рядок `layers` із сьогоднішніх ребер. Пише пропозицію, не специфікацію. Пропозиція, що лише переказує сьогоднішні випадковості, — слабке правило.
3. Додайте рядки `deny`, які маєте на увазі, у рукописний `rules.md`. Краще кілька заборон на рівні шару, ніж заборона на кожну пару файлів.
4. Перелічіть справжні процеси як `entry`: CLI, сервер, воркери, тестові хуки, які хочете лишити.
5. Поставте в CI `keylang check`, `keylang map --check` і `keylang baseline --check`. `--strict` додавайте, лише коли рядки unverified виправлені або прийняті.

Агент не редагує жоден файл правил на місці. Зміна рукописного файла — пропозиція. Baseline має маркер генерації, тож редактор і `apply_diff` його відхиляють. `keylang baseline` переписує його з графа.
