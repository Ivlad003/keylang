# 7. Wiring, інтерфейс і агенти

[Курс](README.md) · [English](../07-tools.md) · **Українською**

Правила і потоки перевіряють код, який уже є. Ще три поверхні сидять на тому самому аналізі: генератор wiring, термінал і браузер, інструменти агента. Жодна не вигадує другий вердикт.

## Wiring

`# wiring` перелічує фабрики. `keylang wire` пише `keylang.gen.ts`: типований `async function wire(env)`, який будує кожну фабрику один раз, залежності спершу. Контейнера немає і пошуку за рядком немає. Контракт — [ADR 0003](../../adr/0003-wiring-lifecycle.md).

```markdown
# wiring

- wire app.purchase.createPurchase
  - store domain.store.Store
- wire domain.store.Store
  - db infra.db.createDb
    - when env.DB = memory → infra.memory-db.createMemoryDb
    - compose infra.logged.logged
```

`wire <id>` — функція, яку кличуть з об'єктом іменованих залежностей, або клас, який конструюють цим об'єктом. Дитина `<псевдонім> <id>` — одна залежність. Id без власного `wire` — лист, зібраний без аргументів. `when env.NAME = value → <id>` обирає іншу реалізацію, коли змінна має саме це значення. Перший збіг перемагає. Сам рядок — запасний варіант. `compose <id>` обгортає значення. Кілька `compose` ідуть у порядку джерела, перший найближче до значення.

Невідомий id — K001. Повторений id `wire` — K002. Цикл між фабриками — K301. K302 — ціль, яку згенерований файл не збере: модуль, тип, Python або Rust, метод екземпляра, ім'я, якого модуль не експортує. Статичний метод дозволений. `deny` між фабрикою і залежністю — K102.

`keylang wire` не перезапише файл без маркера `// keylang:generated` (вихід 1). Будь-яка діагностика секції нічого не пише. `--check` порівнює і не пише. Згенерований файл — звичайний модуль у тому шарі, куди падає його шлях, тож ті самі `deny` діють. Типи перевіряє `tsc`. keylang — ні.

Wiring модулів не ізолює. Рукописний імпорт обходить `wire()`. Такі імпорти ловлять правила. Генерація Rust і час життя на запит спроєктовані і в інструменті їх немає.

## Термінал і браузер

`keylang` без команди відкриває інтерфейс, коли stdin і stdout — термінал, інакше друкує довідку з кодом 2. `keylang web` віддає той самий інтерфейс на `http://127.0.0.1:7070/#t=<token>`. Токен у фрагменті URL. Браузер його на сервер не шле. Типово localhost. Інший `--host` захищений лише токеном. Тунель SSH на localhost — безпечніший віддалений варіант.

Екран — специфікація, жолоб, рядок статусу і дерево. `?` відкриває клавіші:

| `Enter` | Відкрити код для id |

`Enter` на id відкриває переглядач лише для читання, коли `$EDITOR` не заданий, і завжди в `keylang web`. У терміналі замість цього йде `$VISUAL` або `$EDITOR`. `Esc` повертає:

![cli.cli.main, відкритий з тригера](../images/tui-code.png)

Під час редагування `Ctrl+S` записує. `Ctrl+Space` доповнює слова й id. `Ctrl+G` перетворює виділену прозу на рядки `step`, `when` / `then`, `invariant` або `emits`. Модель не кличе. Впізнає лише id, які знімок уже має, плюс кілька слів-підказок (`when`, `if`, `коли`, `якщо`).

`keylang lsp` говорить ті самі діагностики через stdio. Клієнт у `editors/vscode/` — тонка обгортка. Його немає в Marketplace і в пакеті npm.

## Агенти

keylang агента не запускає. `init` і `keylang agents` пишуть короткий блок і, де знаходять Claude, Codex, Cursor чи opencode, сервер MCP і skill. Які теки рахуються, сказано в [уроці 2](02-install-and-check.md). Код пише агент своїми інструментами. Вирішує й далі `check`.

Файл фічі — звичайна специфікація. `keylang feature <slug>` готовий, коли кожен `planned` реалізовано, кожен крок — static `ok` і не лишилось `fail` правил. Тести й trace не блокують.

Claude і Codex також ставлять хук Stop. `keylang hook stop` запускає перевірку змін. Новий `fail` відповідає `decision: block`. Немає нового `fail`, або та сама подія з `stop_hook_active: true`, відповідає `{}`. Обидві відповіді — JSON і код виходу 0. Рядок unverified не блокує. Cursor користується хуками Claude. opencode хука Stop не отримує.

Рукописні правила змінюються лише пропозицією. `apply_diff` зберігає новий текст і лишає файл, доки ви не зіллєте. Згенерований файл відхиляє.

| Команда | Що пропонує | Чого не зробить |
|---|---|---|
| `draft flow <trigger>` | Потік у `.keylang/proposals/` | Специфікацію не редагує. `--mode algo` іде за розв'язаними викликами, глибина 4 |
| `draft rules` | Правила, які код уже виконує, або правила моделі з мітками `agree`, `conflict`, `llm-only` | Не ослабить ваш `deny`, доки ви не зіллєте той шматок |
| `draft map` | Нічого. Друкує розкладку | Файл змінюється, лише коли ви його редагуєте |
| `code-to-spec <file:line>` | Потоки для функції або для кожної експортованої | `--since <git-ref>` обмежує чернетку функціями, яких торкається diff |
| `spec-to-code <id>` | Заготовку і падаючі тести для `planned fn` | `--apply` пише файли. Типово — ні |
| `explain <id> --llm` | `keylang/explain/<id>.md` | Вердикт ніколи не змінює |

`keylang mcp` віддає search, node, code, flows, check, explain, context, `validate_spec`, `scaffold`, `feature_status` і `apply_diff`. Пише лише `apply_diff`, і лише пропозицію.

В інтерфейсі `m` відкриває diff. `a` приймає шматок, `r` відхиляє, `w` записує прийняті. Шматок, якого ви не вирішили, не застосовується.

`Ctrl+Space` у режимі перегляду, на потоці з тригером, просить у моделі чернетку і відкриває злиття. Потрібен `agent` у `keylang.json`. Після злиття `check` оцінює нові кроки як будь-які інші. Рядок, якого знімок не підтримує, стає `unverified` або `fail`, не `ok`.

Текст-привид — один запропонований рядок у кінці свіжої кулі `- `. `Tab` вставляє його. Голос (`Ctrl+R` під час редагування) необов'язковий. `keylang doctor` каже, який рушій заданий. Самі вони файл не пишуть.

Нехай інструмент пропонує. Прочитайте шматок. Прийміть ті, що кажуть те, що ви мали на увазі. Вірте `check`, не коментарю, що рядок написала модель.
