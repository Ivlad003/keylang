# 2. Слова

[Підготовчий курс](README.md) · [English](../02-the-words.md) · **Українською**

Слова, які ви набираєте, англійські, бо така мова. Ідеї — крамниця з [частини 1](01-the-shop.md). Слова, якого тут немає, на старті не потрібне.

## Частини

**Шар.** Названа група з однією роботою. У крамниці: `domain`, `application`, `presentation`, `infrastructure`. Назви ви обираєте в `keylang.json`. Інструмент роботи не вигадує.

**Модуль.** Шматок усередині шару, на який можна показати. `purchase` — модуль. `orderAggregate` — модуль. Зазвичай це один файл. Може бути тека, якщо так сказано в конфігу.

**Функція (`fn`).** Названа дія. `buy`, `create`, `save`.

**Тип (`type`).** Названий вид значення. У крамниці `OutOfStock` — тип на `purchase`. Його можна згадати в сценарії без теорії типів.

**Id.** Ім'я через крапки, від шару вниз: `application.purchase.buy`. Специфікації користуються id, не номерами рядків. Порожній рядок id не змінює. Перейменування змінює, і тоді специфікацію оновлюють навмисно.

**Псевдонім.** Місцеве прізвисько. У `purchase` рядок `order domain.orderAggregate` означає: «тут я зву це `order`, а маю на увазі `domain.orderAggregate`». Прізвисько — для читача. Id — справжнє вказування.

## Три документи

Тримайте їх окремо. Плутанина між ними — звична причина, чому інструмент здається прискіпливим.

**Карта.** Малюнок коду сьогодні: шари, модулі, функції і потреби, які інструмент побачив. Пише її `keylang map`. Руками не редагують. Наступна генерація затре правку. Файл, що втратив позначку «згенеровано», блокує запис. Малюнок — не обіцянка.

**Правила.** Обіцянка, написана людиною. «Правила замовлення не потребують бази.» Код може зламати обіцянку. Для цього й перевірка. Карта себе не ламає, бо її намалювали з коду.

**Потік.** Один сценарій, теж написаний людиною, коротким списком id. Абзац — для людини. Інструмент його не судить. Оформлення покупки в крамниці:

1. Починається в терміналі. Цей старт — **тригер**.
2. Оформлення в терміналі потребує `application.purchase.buy`. Це **крок**.
3. Усередині `buy` замовлення створюють, потім зберігають. Крок *під* іншим кроком означає «це відбувається всередині батька». Два кроки з тим самим відступом означають «спочатку це, потім те».

Потік — один шлях, який можна розповісти колезі. Це не вся крамниця.

## Обіцянки, які ви напишете

**`layers a < b`.** Читайте `<` як «нижче». `domain < application` означає: домен знизу, і application може потребувати домен. Домен не може потребувати application. Потреба вказує **вниз**. У крамниці: `domain < application < presentation`. Екран може потребувати завдання. Завдання може потребувати замовлення. Замовлення не може потребувати екран.

**Шар збоку.** `infrastructure` написано *під* рядком `layers`, не всередині ланцюга `<`. Його немає в лінії вгору-вниз. Потреба *в* нього вільна, доки ви її не забороните. Потреба *з* нього в групу, яка в лінії, потребує явного дозволу. Крамниця дає цей дозвіл: сервер живе в infrastructure і отримує API, а API — це presentation. Дозвіл — це **`allow`**.

**`deny`.** Речення, через яке має впасти збірка. `deny domain infrastructure` означає: «правила замовлення не потребують бази, логера і нічого іншого з тієї групи». Зелений результат означає: інструмент подивився на потреби, які бачить, і забороненої не знайшов. Це не «я довів, що введення-виведення немає ніде».

**`allow`.** Дозвіл, який лінія вгору-вниз інакше відхилила б. Запишіть виняток, який маєте на увазі. Незаписаний виняток — так лінія тихо помирає.

**`entry`.** Звідки програмі дозволено стартувати: сервер, термінал, воркер. Код, до якого з цих стартів не дійти, варто побачити. Інструмент попереджає. Через це попередження запуск не падає.

**`exports`.** Публічні імена одного модуля. «Ззовні `purchase` можна кликати `buy` і `cancel`.» Зайва публічна функція або назване ім'я, якого немає серед публічних, ламає обіцянку.

**Цикл.** A потребує B, і B потребує A, можливо довшим колом. Жоден шматок не зрозуміти окремо. `no-cycles` каже, що такого кола ви не хочете для названих модулів.

**`planned`.** Ім'я, яке ви маєте на увазі, а коду ще немає. `planned fn application.purchase.refund …` означає: «refund буде; це не одрук». Посилання на нього — незавершеність, не поломка. Коли функція з'являється, інструмент каже, що рядок `planned` можна прибрати.

## Три відповіді

Кожна перевірка відповідає на одне твердження одним із трьох слів.

| Відповідь | Простою мовою |
|---|---|
| `ok` | Подивились там, де твердження діє, і воно тримається |
| `fail` | Подивились, і воно не тримається. Хибний id. Потреба в хибний бік. Потреба, яку ви заборонили |
| `unverified` | Подивились недостатньо, щоб сказати. Не успіх і не поломка |

`unverified` рятує від хибного спокою. У прикладі крамниці поруч із Markdown немає вихідного коду, тож обіцянки про справжні імпорти перевірити не можна. Інструмент каже `no snapshot` і не вдає, що правила пройшли. **Знімок** — це погляд інструмента на код в одну мить. Немає коду — немає погляду.

Запуск може закінчитись кодом 0, поки частина тверджень — `unverified`. Код 0 означає «нічого з того, що ми змогли перевірити, не зламано». Це не «усе доведено». Основний курс показує `--strict`: «не змогли подивитись» стає проваленим запуском. Прапорець поки не потрібен. Перестаньте читати тихий результат як доказ.

## Слова, які можуть почекати

| Слово | Один рядок |
|---|---|
| Ребро | Одна побачена потреба: імпорт, виклик, згадка типу або реекспорт |
| Покриття | Місця, куди погляд не зазирнув. Дірка там перетворює обіцянку на `unverified` |
| Жолоб | Позначки біля рядка в терміналі. `✓` лише коли кожна відповідь на рядку — `ok` |
| Wiring | Необов'язкова згенерована функція, яка збирає об'єкти по черзі. Правил не замінює |
| Пропозиція | Текст, який агент хоче покласти в специфікацію. Його там немає, доки людина не прийме |
| Baseline | Рамка `deny`, яку `init` пише з сьогоднішніх залежностей. Пізніший імпорт через прогалину падає, доки ви не дозволите або не перегенеруєте |
| Фіча | Файл, який каже, коли шматок роботи зроблено |
| Карта з поясненнями | Та сама карта з короткою нотаткою під вузлом. Перевірка її не читає |
