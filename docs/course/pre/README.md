# Pre-course

[Course](../README.md) · **English** · [Українською](uk/README.md)

Read this before the [course](../README.md) if you write code but have never had to draw an architecture. It does not teach the command line. It teaches the few ideas the language is about, using the shop in [`examples/shop`](../../../examples/shop).

You do not need patterns, diagrams, or a catalogue of architecture styles. keylang checks one kind of decision: which part of the program may know which other part, and whether a scenario you named still matches the code.

| Part | What happens |
|---|---|
| [1. A shop](01-the-shop.md) | One program grows, and the split into four jobs appears before any term does |
| [2. The words](02-the-words.md) | Each word the language uses, said against that shop |
| [3. The principles](03-principles.md) | The decisions you are actually making, and when to open lesson 1 |
| [4. What to read](04-reading.md) | A path from zero, with the free sources and the terms they give you |

After part 3 you can start [lesson 1](../01-what-it-is.md). Part 4 is the reading that makes the same ideas sturdy. It does not block the course.
