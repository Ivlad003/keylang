# 0015. PHP: імпорт називає оголошення, а не файл

**Дата:** 2026-10-05 · **Статус:** прийнято · **Джерело:** запит користувача 2026-10-05 «підключи нову мову програмування php»; рішення: ID класу — файл-модуль із класом-членом, у першу версію входять ребра `type`, `spec-to-code` і trace з PHPUnit

## Контекст

У TypeScript, Python і Rust специфікатор імпорту веде до файла: `./order`, `..infra.db`, `crate::domain::order`. Резолвер фронтенду отримує шлях файла й специфікатор і відповідає файлом. Цей контракт описує `src/frontends.ts`: «adding one means a frontend here».

PHP так не працює. `use App\Domain\Order;` називає клас `Order` простору імен `App\Domain`. Який файл його оголошує, вирішує автозавантажувач під час виконання: PSR-4, PSR-0, class map чи `require`. Клас свого простору імен код пише взагалі без `use`. Функцію без кваліфікації PHP шукає спершу у своєму просторі імен, потім у глобальному. Тож за самим специфікатором файла не знайти. Потрібні оголошення всіх проаналізованих файлів.

## Рішення

1. **Факти несуть повні імена.** `FileFacts.symbols` перелічує оголошення верхнього рівня файла з повним іменем і таблицею PHP: `class` (зокрема інтерфейси, трейти, enum), `function`, `const`. Поле необов'язкове: інші мови його не заповнюють.
2. **Резолвер бачить факти.** `Frontend.resolver(root, sources, files)` отримує факти файлів аналізу. Резолвер PHP будує з них індекс «повне ім'я → файл», як class map composer, і не читає `autoload`. Інші резолвери новий аргумент ігнорують.
3. **Ім'я без `use` — необов'язковий імпорт.** Екстрактор розв'язує кожне вжите ім'я класу чи функції за правилами PHP і записує його як імпорт там, де ім'я вжито вперше, з `optional`: ребро є, коли файл оголошує це ім'я, інакше нічого.
4. **Ім'я поза репозиторієм.** Ім'я, якого не оголошує жоден файл, належить пакету composer, коли `composer.lock` (або `vendor/composer/installed.json`) заявляє його простір імен. Глобальне ім'я — стандартна бібліотека PHP. Решта імен з `use` — нерозв'язаний імпорт.
5. **ID лишається файловим.** Модуль — файл, клас — його член, як в інших мовах: `Domain.Order.Order.place`. Ім'я класу повторюється в ID, зате граф не має окремого правила для PHP, і ID не змінюється, коли у файл додають другий клас.

## Наслідки

- Граф, знімок і перевірки для PHP ті самі, що для інших мов. Змінилися лише сигнатура фабрики резолверів і необов'язкове поле фактів.
- Резолвер PHP залежить від усіх фактів аналізу. Файл, який аналіз не бачить (виключений, у `vendor/`), імені не оголошує, тож посилання на нього стає пакетом, стандартною бібліотекою або діркою.
- Тексти `composer.lock` і `installed.json` входять у `snapshotId`: від них залежить, які ребра ведуть у пакети.
- Регістр: PHP порівнює імена класів і функцій без регістру, резолвер теж. Член класу keylang шукає з регістром, тож `$order->Total()` при методі `total` — дірка `dynamic-call`, а не ребро.
