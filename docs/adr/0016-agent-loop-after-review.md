# 0016. Цикл агента після рев'ю: хук, готовність фічі, пропозиції без TUI, локальний кеш

**Дата:** 2026-10-05 · **Статус:** прийнято, реалізовано 2026-10-05; п. 1 і п. 2 змінено [поправкою 2026-10-06](#поправка-2026-10-06) · **Джерело:** [рев'ю 2026-10-05](../review-2026-10-05.md), «Головне» 4, 7, 8, 9; уточнює п. 2 і п. 4 ADR [0005](0005-harness-integration.md)

## Контекст

Наскрізна проба на чужому репозиторії показала чотири місця, де цикл «агент пише код, keylang звіряє» обривався:

- `hook stop` без git або з некоректним stdin виходив з кодом 2 без JSON. Claude Code вважає код 2 хука Stop блокувальною помилкою, тож агент отримував повідомлення, на яке не міг відповісти. `llm.txt` при цьому обіцяв «JSON і код 0 завжди».
- `feature` рахував кожен `fail` правил у репозиторії, навіть успадкований і не пов'язаний із фічею. Тож на brownfield-репозиторії з одним старим порушенням жодна фіча не ставала `done`. ADR 0005 п. 2 вимагає лише відсутності *нових* порушень.
- Пропозицію (MCP `apply_diff`, `draft`, `spec-to-code`) приймала лише клавіша `m` у TUI. Сесії без TTY (Claude Code у браузері, SSH, CI) не могли прийняти зміну правил, яку агент лише пропонує.
- Кеш фактів писали тільки `map` і `init`. Хук Stop після кожної правки коду розбирав усі файли знову: на keylang це 5,5 с проти 1,4 с із кешем.

## Рішення

1. **`hook stop` завжди відповідає JSON і кодом 0**, щойно стартував. Хід, який не вдалося перевірити (немає git, stdin не JSON, зламаний `keylang.json`, помилка аналізу), дає `{}` і одну строку в stderr: `this turn was not checked`. Код 2 лишається тільки для неправильного виклику самої команди. `check --changed` коди не змінює.
2. **Фіча блокується лише `fail` своєї зміни.** `fail` правила належить зміні, коли зачіпає файл, змінений від базового коміту (той самий фільтр, що в `check --changed`), або коли кінець його ребра — ID, який називає файл фічі. Старіший `fail` деінде — підказка `rule` і запис `info.rules`. Без git (база `unavailable`) блокує кожен `fail`, як раніше.
3. **`keylang proposals [show|accept|reject] <ціль>` — для людини.** Прийняття пише повний текст пропозиції через ту саму браму, що MERGE (правила цілі, протокол запису `safe-write`). Агент пропозицій не приймає й не відхиляє. Для Claude `keylang agents` додає `Bash(* proposals accept *)` і `Bash(* proposals reject *)` у `permissions.deny`. Для інших харнесів правило записано в `AGENTS.md` і skill.
4. **Команди, що будують знімок, оновлюють локальний кеш фактів** `.keylang/cache/facts.json`: `check` (зокрема `--changed`), `feature`, `hook stop`, MCP. Запис best-effort і лише коли факти змінилися: помилка запису мовчазна й не змінює код виходу. Режими `--check` кеш не пишуть. Специфікацій, карти й індексу ці команди, як і раніше, не пишуть. Тож п. 4 ADR 0005 («MCP лише читає, крім `apply_diff`») читається так: MCP не пише нічого, крім пропозицій і локального кешу.

## Розглянуті варіанти

- **Хук: блокувати хід із причиною збою.** Агент дізнався б про збій, але середовище без git блокувало б кожен хід удруге. Відхилено. Варіант на майбутнє: поле `systemMessage` у JSON, яке Claude Code показує людині.
- **Фіча: порівнювати з порушеннями базового коміту.** Точніше, але потребує повного аналізу коду на базовому коміті. Фільтр `--changed` уже є і застосовується однаково в хуку й у фічі.
- **Пропозиції: приймати по шматках у CLI.** MERGE по шматках лишається в TUI. CLI приймає пропозицію цілком, а `show` показує, що саме.
- **Кеш: лише в пам'яті процесу.** Не допомагає CLI і хуку: кожен виклик — новий процес.

## Наслідки

- Агент, що зламав середовище, не блокується хуком. Людина бачить причину лише в stderr хука.
- Фіча, яка сама внесла порушення й уже закомітила його, при базі `HEAD` вважає його успадкованим. Щоб оцінити закомічену роботу, потрібен `--since <ref до неї>`.
- `Bash(* proposals accept *)` збігає й рядки на кшталт `echo "… proposals accept …"`. Заборона ширша, ніж треба, і це прийнятно.
- `.keylang/` з'являється навіть після `check`. `init` дописує `.keylang/` у `.gitignore`.

## Поправка 2026-10-06

Рішення автора 2026-10-06 змінюють два пункти рішення. Решта ADR чинна.

1. **Неперевірений хід — `systemMessage` замість `{}`.** Хід, який хук не зміг перевірити, дає в stdout `{"systemMessage":"keylang: this turn was not checked: <причина>"}` (один JSON-об'єкт і перевід рядка) і той самий рядок у stderr, код 0. Причина: Claude Code пише stderr хука Stop з кодом 0 лише в debug-лог, тож за п. 1 людина збою не бачила (перший наслідок вище). Поле `systemMessage` — «варіант на майбутнє» з розглянутих вище: і Claude Code (code.claude.com/docs/en/hooks: «Warning message shown to the user»), і Codex (learn.chatgpt.com/docs/hooks: «Surfaced as a warning in the UI») показують його людині й агента не блокують. Решта контракту п. 1 без змін: `stop_hook_active: true` і хід без нових `fail` — `{}`, нові `fail` — `{"decision":"block","reason":…}`, неправильний виклик — код 2.
2. **Типова база фічі — merge-base з основною гілкою, а не `HEAD`.** З базою `HEAD` порушення, яке фіча внесла й уже закомітила на своїй гілці, ставало успадкованою підказкою, і фіча — `done` з кодом 0 (другий наслідок вище). Тепер без `--since` база — `git merge-base HEAD <основна>`, де основна — та, на яку вказує `refs/remotes/origin/HEAD`, інакше локальна `main`, `master`, інакше `origin/main`, `origin/master`. Немає основної гілки, merge-base не знайдено або він дорівнює `HEAD` — база `HEAD`, як раніше; git недоступний — `unavailable`, як раніше. Зміна фічі — файли, змінені від бази (як `check --changed --since <база>`). План порівнюється і з базою, і з `HEAD`, коли вони різні, а знахідки об'єднуються: файл, якого на базі немає (нова фіча на гілці), як і раніше не можна послабити до коміту. Звіт називає базу: `info.base` зберігає `ref` і `state` і додає `source` (`since`, `merge-base`, `HEAD`) і `main` (основна гілка); підказка `inherited` і прогалина `spec` пишуть `merge-base <коміт> with <гілка>`. `--since` і `check --changed` поводяться як раніше. Наслідок: на локальній основній гілці з незапушеними комітами при `origin/HEAD` база — merge-base з віддаленою гілкою, тож незапушені коміти теж зміна фічі.
