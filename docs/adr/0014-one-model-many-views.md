# 0014. Одна модель — багато представлень

**Дата:** 2026-10-04 · **Статус:** прийнято · **Джерело:** `.scratch/c4-zoom/spec.md` (Р1, §4.3), тікет c4-zoom/02; [research-c4-zoom-literature.md](../archive/research-c4-zoom-literature.md) §4 (Structurizr: `model` і `views`)

## Контекст

keylang уже показує той самий репозиторій кількома способами: карта, карта з поясненнями, панелі TUI, контекст для агента. Фіча c4-zoom додає ще три: екран зуму в TUI, накладання шляху потоку на рівні зуму й експорт у C4-PlantUML і Mermaid. Вона ж додає рівень «система» C4, тобто сам репозиторій, а шар отримує документ із власної теки.

Structurizr DSL розводить те саме двома блоками: `model` описує елементи й зв'язки один раз, а `views` вибирають із моделі, що показати. Без такого принципу кожне нове подання ризикує стати другим джерелом фактів або вимагати від мови нових ID лише заради картинки.

## Рішення

1. **Знімок — єдина модель фактів.** Вузли, ребра, експорти, покриття й тексти, які репозиторій пише про себе (`doc` вузла, поле `system`), живуть у знімку ([snapshot.md](../snapshot.md) §11).
2. **Представлення обчислюються.** Карта, карта з поясненнями, екран зуму, накладання потоку, експорт C4 і панель контексту обчислюються зі знімка, специфікацій і збережених пояснень (`<dir>/explain/`). Ті самі входи дають той самий текст.
3. **Модель — лише за явною командою.** Жодне представлення не питає модель саме. Brief-и й пояснення пишуть команди з `--llm` і дії TUI, що їх запускають. Текст моделі завжди показує походження: модель, дату, `stale`.
4. **Представлення не є фактом.** `check` не читає жодного представлення: його вердикт спирається на знімок, специфікації й докази. Для карти з поясненнями це вже записано в ADR 0004.
5. **Корінь — вузол представлення.** Репозиторій (`@system`) є в карті з поясненнями й на екрані зуму, але не є ID мови. Його не називають `rules`, `flow` чи `planned`, і SpecIR про нього не знає. `@` не починає сегмент ID, тож збережений brief `@system.md` не ділить файл із шаром `system`. Шари лишаються ID мови, як і були.

## Наслідки

- Нове представлення — це нова функція над знімком, а не новий формат даних. Зміни граматики чи SpecIR воно не потребує.
- Помилка в представленні не змінює вердикт `check`.
- Рівень «система» отримує текст без моделі, з README чи маніфесту. Модель питають лише там, де ці тексти мовчать (тікет c4-zoom/01).
- Якщо корінь колись стане ID мови, наприклад для кроку потоку до системи чи правила про неї, це окреме рішення з новим ADR. Файли, написані до того, не зламаються.

## Розглянуті альтернативи

- **Корінь як ID мови з обмеженим вжитком:** `explain @system`, крок потоку до шару. Дає більше, але змінює граматику до заморожування v1.
- **Шари й корінь як повні вузли знімка** з власними ребрами, правилами й доказами. Найбагатша модель, але вона змінює семантику `rules` і потребує окремої фічі після v1.
