# 0005. keylang як специфікація для зовнішніх харнесів: харнес пише код, keylang дає рамки й звіряє

**Дата:** 2026-09-28 · **Статус:** прийнято 2026-09-28, реалізовано 2026-09-28, крім наскрізної перевірки на чужих репозиторіях (тікет 11 у `.scratch/harness-integration/`); п. 1 уточнено ADR [0012](0012-agent-cli-provider.md); п. 2 і п. 4 уточнено ADR [0016](0016-agent-loop-after-review.md) · **Джерело:** design §7.3 «Зовнішні агенти через MCP», §7.6; рішення користувача 2026-09-28. Уточнює роль `apply_diff` і пропозицій для зовнішніх агентів.

## Контекст

Після `init` репозиторій має карту, але харнес (Claude Code, Codex, opencode, Cursor) про keylang не знає. `init` не пише ні інструкцій, ні реєстрації MCP, ні хуків. Щоб агент додав фічу чи інтеграцію за описом, бракує чотирьох речей: місця для наміру фічі, інструментів циклу «опис → код», рамок, які агент не може тихо послабити, і зворотного зв'язку в кінці ходу. Цільовий сценарій — чужий репозиторій із першого запуску, без ручного опису.

## Рішення

1. **Роль.** keylang — специфікація й контроль, а не оркестратор. Людина чи агент описує фічу через `planned`, потоки й правила. Харнес пише код своїми інструментами. keylang дає контекст і звіряє намір із кодом. Сам keylang харнес не запускає — хіба як текстову модель вбудованого агента, без запису файлів (ADR [0012](0012-agent-cli-provider.md)).
2. **Критерій готовності фічі.** Фіча реалізована, коли виконано три умови. Кожен `planned` фічі реалізовано (K202, без K201). Кожен крок її потоків має static `ok`. Нових порушень правил і baseline немає. Тести й trace — інформація, не блокер.
3. **Спільні стандарти плюс тонкі адаптери.** Ядро — `AGENTS.md`, MCP і CLI. Адаптер під конкретний харнес додається лише там, де без нього немає зворотного зв'язку чи захисту: `@AGENTS.md` у `CLAUDE.md`, MCP-конфіг кожного харнеса, хук `Stop`, deny на файли правил.
4. **Хто пише файли.** Харнес — єдиний, хто записує код і специфікації фіч: зі своїм diff, підтвердженням і відкатом. MCP лишається read-only, крім наявного `apply_diff`. `scaffold` повертає текст, а не пише.
5. **Правила агент сам не послаблює.** `keylang/rules.md` і `keylang/rules.baseline.md` агент змінює лише через пропозицію. Там, де харнес уміє deny, це закріплено в його дозволах. Інакше — інструкцією. `check` git-стан не читає.
6. **Рамки з першої хвилини.** `init` генерує `keylang/rules.baseline.md`: нова залежність між шарами, якої немає в поточному графі, — порушення. Виражається наявною граматикою (`deny` + точкові `allow`).
7. **Зовнішні системи.** Нового виду вузла немає. Використовуються наявні `external.<pkg>` і `planned module external.<pkg>` для інтеграції, якої ще немає.

## Розглянуті варіанти

- **keylang як оркестратор**: розбиває фічу, запускає харнес, приймає результат. Відхилено: окремий продукт, суперечить «terminal first» і мінімальним залежностям.
- **Лише контекст і перевірка правил, без наміру**: відхилено. Агент не має цілі, яку можна звірити, тож «готово» не визначене.
- **Усі зміни специфікації через пропозиції й MERGE**: відхилено для файлів фіч. Харнес уже має власне підтвердження правок, і друге ставило б людину в TUI на кожен крок. Для правил — прийнято, див. п. 5.
- **Діагностика `check` на зміну правил відносно `HEAD`**: відхилено. `check` має лишатися перевіркою коду проти специфікації, незалежною від git.
- **Новий вид вузла `external` із контрактом**: відхилено для v1. Синтетичний шар `external` з вузлами пакетів уже є, і правила їх називають.
- **Структуровані контракти (типи, помилки, assertions)**: відкладено (design §10, п. 9). Критерій п. 2 звіряє вузли, ребра й потоки, не поведінку.

## Наслідки

- `init` пише файли поза `keylang/`: `AGENTS.md`, `CLAUDE.md`, MCP-конфіги, skill, налаштування хуків. Чужий текст не змінюється. Блоки keylang стоять між маркерами, ідемпотентні й перевіряються `--check`.
- MCP-конфіги фіксують версію keylang, що їх згенерувала (`npx -y keylang@<версія> mcp`). Перший запуск MCP потребує мережі. Перевірки лишаються офлайн.
- Codex читає `.codex/` лише в trusted-проєктах, і кожен хук там схвалюється окремо. Тому інструкція в `AGENTS.md` лишається запасним шляхом зворотного зв'язку. opencode у v1 отримує лише інструкцію, без хука: API плагінів V1 і V2 несумісні.
- Хук `Stop` залежить від швидкості `check`. Звідси `check --changed` (design §7.5).
- Baseline на чужому репо настільки ж точний, наскільки точні шари `guessLayout`. Шумні шари дають шумний baseline, тож рівень baseline — шари, не модулі.
