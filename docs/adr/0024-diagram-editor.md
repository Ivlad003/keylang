# 0024. Клієнт діаграм: maxGraph, vanilla TypeScript, збірка esbuild

**Дата:** 2026-10-08 · **Статус:** прийнято · **Джерело:** `.scratch/business-flows/spec.md` §3a («Редактор діаграм — maxGraph; розкладка — `keylang/diagrams/` у git») і §9 №5; тікети business-flows/33 (збірка й каркас), 21 (перегляд), 23 (редактор); [ADR 0002](0002-dependencies-by-value-ws.md) (залежності за користю); [ADR 0014](0014-one-model-many-views.md) (діаграма — представлення)

## Контекст

`keylang web` досі віддавав одну inline-сторінку з вшитим xterm.js: `copy-web.mjs` копіює готові файли пакетів у `dist/web/`, бандлера немає. Діаграми бізнес-флоу (модель — `src/diagram.ts`, API — `/api/views`, `/api/diagram`) потребують справжнього графічного полотна, а згодом редактора у стилі diagrams.net: фігури, з'єднання з точками прив'язки, контейнери-доріжки, перетягування, zoom/pan, undo/redo. Такий рушій — це десятки тисяч рядків, писати його не варто. Рушій у вигляді ESM на сотні файлів не можна просто скопіювати, як xterm, тож потрібна збірка. Пакет при цьому має й далі ставитися без компіляції та без нових runtime-залежностей у дереві користувача.

## Рішення

1. **Рушій — maxGraph (`@maxgraph/core`, Apache-2.0).** Це open-source наступник mxGraph, рушія самого draw.io, і він без залежностей. Звичну поведінку diagrams.net (swimlane-контейнери, порти, напрямні, мультивибір, undo/redo, гарячі клавіші) він дає з коробки, і та сама модель комірок знадобиться для експорту в draw.io (тікет 28). Каркас (33) малює лише для читання: `graph.setEnabled(false)`, вершина на `x/y/w/h` вузла моделі, ребро, `swimlane` на групу, колір за вердиктом. Розкладку рахує сервер; клієнт її не змінює.
2. **Без фреймворку: vanilla TypeScript** у `web/src/` (`diagrams.ts`, `api.ts`, `diagrams.css`). maxGraph сам керує своїм DOM. Сторінці потрібні список із пошуком і, далі, панель властивостей. React чи Vue додали б ще одну модель стану поверх моделі комірок maxGraph і ще один рантайм у бандлі, а виграшу не дали б. Типи перевіряє власний `web/tsconfig.json` (DOM, `moduleResolution: bundler`) у складі `npm run typecheck`.
3. **Збірка — esbuild** (`scripts/build-web.mjs`): один IIFE-скрипт `dist/web/diagrams.js` плюс `diagrams.css`. Збірка мініфікована, працює без мережі й без CDN, займає близько секунди. Ліцензію кожного пакета, що потрапив у бандл, скрипт визначає з metafile esbuild і копіює поруч як `<пакет>.LICENSE`, як це зроблено для xterm. `prepack` запускає збірку після `copy-web.mjs`. У чекауті `keylang web` збирає клієнт на першому запиті, якщо бандла немає або він старший за `web/src/**`. Опублікований пакет `web/src` не має і нічого не збирає.
4. **Залежності за ADR 0002: `esbuild` і `@maxgraph/core` — devDependencies.** Пакет несе лише зібрані файли, тож `npm ls --omit=dev` не змінюється і в дереві користувача немає ні native-бінарника esbuild, ні maxGraph.
5. **Доступ — той самий токен.** Сторінка `/diagrams` статична, не має inline-скрипта і віддається з `script-src 'self'`. Токен приходить у фрагменті (`/diagrams#t=…`, посилання «Діаграми» на сторінці терміналу), переходить у `sessionStorage` і йде в API як `Authorization: Bearer`. Перевірки `Host`/`Origin` ті самі, що й для WebSocket.

## Відкинуті варіанти

- **xyflow (React Flow / Svelte Flow).** Добре підходить для вузлів-компонентів, але тягне React чи Svelte і не має моделі draw.io. Доріжки-контейнери, порти, ортогональну маршрутизацію ребер, undo/redo, буфер обміну й експорт у формат draw.io довелося б писати самим. Автор обрав maxGraph (§3a). Від xyflow беремо лише ідею: вузли несуть ID моделі, а не власну правду.
- **Вбудований draw.io (iframe `embed.diagrams.net` або самостійно розгорнутий webapp).** Публічний embed — це CDN і чужий origin: дані репозиторію пішли б у сторонню вкладку, а CSP і робота без мережі зламалися б. Самостійно розгорнутий draw.io — це десятки мегабайт статики й власний формат, який довелося б синхронізувати з моделлю keylang через postMessage. Фігури keylang (ID, вердикти, `planned`) у ньому залишилися б чужими. maxGraph — той самий рушій, але як бібліотека під нашим контролем.
- **Без бандлера, ESM-файли maxGraph через import map.** Це сотні запитів, `script-src` довелося б розширювати на модулі, а ліцензії й версії в пакеті розходилися б із тим, що реально завантажено.

## Наслідки

- Бандл каркаса на 2026-10-08: `diagrams.js` близько 397 КіБ мініфікованого коду (близько 110 КіБ gzip), майже весь — maxGraph `Graph` з типовими плагінами. Перехід на `BaseGraph` із вибраними плагінами (tree-shaking) — можлива оптимізація для тікетів 21 і 23. Тікет 21 це зробив: `BaseGraph` з плагіном панорамування, лише потрібні фігури й маркери, `Outline` без власних типових плагінів (плагін esbuild `lean-outline` у `scripts/build-web.mjs`) — близько 267 КіБ (81 КіБ gzip) разом із переглядом.
- `npm install` у чекауті ставить native-бінарник esbuild як optional-залежність. Його `postinstall` лише перевіряє бінарник: якщо npm не дозволить install-скрипти, збірка однаково працює.
- Браузерні e2e (Playwright, `npm run test:web`) поза `npm test` додадуть тікети 21 і 23. У `tests/web.test.ts` перевіряються сторінка, віддача бандла, 403 без токена і збірка в тимчасову теку без CDN-імпортів.
- Редактор (23) розширює цей самий бандл. Розкладка зберігається в `keylang/diagrams/` (24), зміст змінюється лише через пропозиції.
- Редактор (23, 2026-10-08) має власний `BaseGraph` із вибраними плагінами — `SelectionCellsHandler`, `ConnectionHandler`, `SelectionHandler`, `RubberBandHandler`, `PanningHandler` — і `UndoManager`, `ImageExport`, `SvgCanvas2D`; без `CellEditorHandler`, `TooltipHandler`, `PopupMenuHandler` (підписи редагує панель властивостей, контекстного меню немає). Клавіші draw.io обробляє сам редактор, а не `KeyHandler` maxGraph: потрібні Ctrl/Cmd-комбінації, Shift-стрілки й відмова у полях вводу. Бандл — близько 463 КіБ (127 КіБ gzip). Стан полотна живе в пам'яті й у `sessionStorage` вкладки; позиції — через `web/src/layout-store.ts`, який тікет 24 підкріпить файлом розкладки.
- Тікет 24 (2026-10-08): `FileLayoutStore` пише розкладку в `keylang/diagrams/<вид>.layout.json` через `GET`/`PUT /api/layout` (ключі — те, що фігура каже в специфікації, детермінований JSON; `check` теку не читає), а «Запропонувати зміни» шле `currentModel()` на `POST /api/diagram-proposal` — зміст змінюється лише пропозиціями (`src/diagram-proposal.ts`, `src/operations/diagram-propose.ts`, той самий шлях, що `keylang diagram propose`).
