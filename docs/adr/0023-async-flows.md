# 0023. Асинхронні потоки: події, паралельні групи, асинхронні тригери, таймери

**Дата:** 2026-10-07 · **Статус:** прийнято · **Джерело:** `.scratch/business-flows/spec.md` §3a, тікет business-flows/02; [ADR 0009](0009-flow-properties-ltlf.md) («поза обсягом»: паралельні групи, дедлайни); [ADR 0022](0022-framework-facts.md) (події й точки входу як факти)

## Контекст

Потік сьогодні — синхронне дерево викликів: `trigger` → вкладені `step`, де сусідні кроки означають порядок, а `when`/`then` — гілку. Бізнес-процес магазину здебільшого асинхронний: після оплати паралельно йдуть резерв, лист і відправка в ERP; підтвердження платежу приходить вебхуком через хвилини; неоплачене замовлення скасовує cron; на подію `order.created` реагує невідома кількість observers. Сьогодні все це — проза `invariant`/`emits` без доказів, а при міграції губиться саме воно.

Повна BPMN (компенсації, ескалації, таймери між подіями) не потрібна і суперечить межам мови ([research-pl](../archive/research-pl.md) §6). Потрібні чотири форми, які автор потоку пише одним рядком і які keylang може перевірити або чесно назвати неперевіреними.

## Рішення

Усі форми — контекстні слова всередині `# flow`. Сьогодні вони дають K004, тож зміна додавальна й нової редакції формату не потребує ([ADR 0007](0007-format-editions.md)). Усі форми однакові для кожної мови, яку keylang читає: тригери й події беруться з фактів будь-якого адаптера ([ADR 0022](0022-framework-facts.md)).

1. **Події.**
   - `- emits event <id>` під кроком перевіряється статично: у піддереві кроку є `dispatch` з цим літералом → `static ok`; повністю прочитана область без `dispatch` → `fail` (absence); нелітеральна назва або дірка на шляху → `unverified`.
   - `- trigger event <id>` — потік підписника: подія існує у знімку (ID), вердикт перелічує підписників; кроки під ним перевіряються від fn підписника.
2. **Паралельні групи.** `- parallel` з вкладеними `step`: кожен крок має відбутися, порядок між ними не перевіряється. Static: кожен крок досяжний від батька групи. Trace: усі span під батьком, перекриття в часі дозволене; відсутній крок — за правилами завершеного запуску. Сусіди групи впорядковані відносно групи цілком: наступний крок починається після завершення всіх кроків групи.
3. **Асинхронні тригери.** `- trigger route <id>`, `- trigger cron <id>`, `- trigger consumer <id>`, `- trigger webhook <id>`: `<id>` — ID fn точки входу зі списку `entries` знімка; вид має збігатися (інакше K-код специфікації), мітка точки входу (`POST /V1/carts/mine/order`, розклад cron) — у вердикті. Шлях маршруту в тексті потоку не пишеться: він не є ID і змінюється частіше за fn.
4. **Продовження.** `- continues <flow>` на верху потоку: цей потік продовжує інший (вебхук оплати продовжує `place-order`). Перевіряється існування обох потоків; наскрізний trace між запитами — `unverified (crosses requests)` з причиною. Форма `wait` всередині одного потоку не вводиться: кожна точка входу — свій потік.
5. **Таймери.** `- after <тривалість>` і `- every <розклад>` під кроком чи на верху потоку — твердження, яке перевіряє лише вкладений `test`; статично для `every` — розклад cron-точки входу збігається з записаним, якщо адаптер його бачить; інакше `unverified`.

Вердикти рядків — звичайні три значення; жодна форма не підвищує доказ до `ok` без факту знімка, звіту тестів або trace.

## Відображення в BPMN (для діаграм і експорту)

| Форма keylang | Елемент BPMN |
|---|---|
| шар | доріжка (lane) |
| `trigger` fn / `route` / `cron` / `consumer` / `webhook` | стартова подія: звичайна / повідомлення / таймер / повідомлення / повідомлення |
| `step` | задача |
| `when` / `then` | ексклюзивний шлюз і його гілки |
| `parallel` | паралельний шлюз (розгалуження й злиття) |
| `emits event` / `trigger event` | проміжна подія-кидок / стартова подія-сигнал |
| `continues` | потік повідомлень між пулами |
| `after` / `every` | проміжна таймерна подія |
| зовнішній пакет, інтеграція | зовнішній пул |
| дірка | задача з позначкою `?` і причиною |

## Поза обсягом

Компенсації, ескалації, межові події, дані процесу й умови на даних, статична перевірка `never`/`at-most` ([ADR 0009](0009-flow-properties-ltlf.md) лишається окремим рішенням), виконання процесів.
