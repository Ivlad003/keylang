# 0001. TUI без Ink: власний рендерер, WebSocket і Markdown

**Дата:** 2026-09-27 · **Статус:** прийнято; бюджет залежностей і рішення 2 замінено [0002](0002-dependencies-by-value-ws.md) · **Тікети:** 29, 30, 31 (M4)

## Контекст

design.md §7.1 і §7.4 називали для TUI Ink 7 + React, для браузера — `ws`, для режиму читання — `marked` + `marked-terminal`. Під час M4 це звірено з обмеженнями, які вже діють у проєкті:

- **Бюджет залежностей.** `npm ls --omit=dev` ядра — не більше ~30 пакетів (§7.4). Ink 7.1 має 25 прямих залежностей (`yoga-layout`, `react-reconciler`, `chalk`, `ws`, …) плюс `react`; разом із транзитивними це перевищує весь бюджет. `marked-terminal` тягне `cli-highlight`, `cli-table3`, `node-emoji` та інші.
- **Запуск TS напряму.** У розробці Node виконує `.ts` через type stripping (`erasableSyntaxOnly`); JSX так не виконується. Ink без JSX — `createElement` вручну, або окремий крок збірки для розробки.
- **Прецедент.** `keylang lsp` уже говорить підмножину протоколу без `vscode-languageserver` з тієї ж причини.
- **Що потрібно TUI.** Жолоб і hit-testing мишки вимагають точних координат клітинок; Ink віддає layout через Yoga й не показує позицій елементів, тож SGR-мишку однаково довелося б зіставляти вручну. Тест без TTY має читати кадр як текст.

## Рішення

1. **Рендерер — власний.** `src/tui/screen.ts`: сітка клітинок (графеми, ширина East Asian Wide та emoji, OSC 8), кадр → ANSI лише для змінених рядків. `src/tui/view.ts` — чиста функція `State → Grid`, `src/tui/app.ts` — сесія, `src/tui/input.ts` — декодер клавіш, SGR-мишки й bracketed paste. Тест читає `Grid.lines()` або вивід через віртуальний термінал (`tests/vt.ts`) — еквівалент `ink-testing-library`.
2. ~~**WebSocket — власний** (`src/tui/websocket.ts`).~~ Замінено [0002](0002-dependencies-by-value-ws.md): WebSocket — пакет `ws`.
3. **xterm.js і addon-fit — devDependencies**, їхні файли копіює `scripts/copy-web.mjs` у `dist/web/` на `prepack`: браузеру потрібні готові файли, а не пакет у `node_modules`.
4. **Markdown для `v` — власний малий рендерер** (`src/tui/markdown.ts`) для підмножини, яку пишуть у специфікаціях.
5. **Знімок у TUI будує worker** (`src/tui/background.ts`), бо `generateMap` — синхронна CPU-робота; `analyze({ generate })` лишає решту конвеєра спільною з CLI і LSP.

## Наслідки

- Tarball 568 КБ (4.2 МБ розпаковано, з них xterm.js 489 КБ). Після 0002 `npm ls --omit=dev` — 3 пакети (`ws`); ліміт у ~30 пакетів 0002 скасував, поточний склад залежностей — у «Наслідках» 0002.
- Перенесення компонентів на Ink/OpenTUI, коли Node 26 стане базовим (§7.2), — це переписування `view.ts`, а не всієї сесії: стан, вхід, аналіз і транспорт від рендерера не залежать.
- Компроміси: немає flexbox-розкладки (панелі фіксованої ширини), таблиці в режимі читання спрощені, підсвітка коду лексична, а не з `highlights.scm`. Ширина рідкісних символів може розійтися з терміналом — зсувається лише цей рядок.
