# 0017. `assume`: імпорт файла, якого keylang свідомо не читає

**Дата:** 2026-10-05 · **Статус:** прийнято, реалізовано 2026-10-05 · **Джерело:** [рев'ю 2026-10-05](../review-2026-10-05.md), «Правила, потоки» п. 4; поруч з ADR [0011](0011-outside-architecture.md)

## Контекст

Код архітектури іноді імпортує файл, якого немає в репозиторії або який не варто аналізувати: конфігурацію поза git (`src/config.ts` у `.gitignore`), згенерований код (`src/generated/**`). Наявні засоби дають три різні хибні відповіді:

- без запису в `keylang.json` відсутній файл — прогалина `unresolved import`. Правила стають `unverified` у CI, де файла немає. Локально, де він є, файл потрапляє в `unassigned`, і baseline дає K102;
- `outside` (ADR 0011) на присутній файл — K107 для кожного імпортера, бо код архітектури не має залежати від коду поза нею;
- `exclude` робить файл непрозорим модулем `unassigned` — прогалиною і K102 від baseline.

Результат залежить від того, чи лежить файл на диску. Тож CI і локальний запуск розходяться.

## Рішення

Нове поле `keylang.json` `assume` — глоби файлів, які архітектура імпортує, а keylang не читає й не вимагає.

1. Файл, що збігає `assume`, ніколи не індексується, навіть коли він є.
2. Імпорт, чия ціль збігає `assume`, — ні ребро, ні прогалина. Ціль може бути присутньою чи відсутньою: для відносного специфікатора й шляху з `paths`/`baseUrl`/`#imports` береться шлях, який він назвав би з тими самими кандидатами розширень. Такий імпорт дає запис покриття `assumed-import`, і правила його діркою не рахують.
3. Пріоритет: вбудований список (тести, оголошення) > `assume` > `outside` > `exclude`.
4. `assume` входить у конфігурацію знімка, тож його зміна змінює `snapshotId`. `init` і `draft map` його не пишуть: це рішення людини.

## Розглянуті варіанти

- **Розширити `outside`.** Змінило б значення наявного поля: `outside` — код, від якого архітектура не має залежати.
- **Тихо пропускати нерозв'язані імпорти `.gitignore`.** Перетворило б справжню помилку (забутий файл) на мовчання.

## Наслідки

- CI і локальний запуск дають той самий вердикт для такого імпорту.
- Що всередині прийнятого файла, keylang не знає. Помилка в ньому не дасть ні `fail`, ні `unverified`, тож поле варто тримати вузьким.
- Для Python, Rust і PHP `assume` діє лише на присутній файл: шлях відсутнього модуля з імпорту там не виводиться.
