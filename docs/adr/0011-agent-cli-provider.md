# 0011. Агент-CLI як провайдер моделі: харнес відповідає текстом, пише лише keylang

**Дата:** 2026-10-04 · **Статус:** прийнято, реалізовано 2026-10-04 · **Джерело:** `.scratch/agent-completion` (plan.md крок 2, C1–C8; design/design-agent-cli.md; рішення Q1). Уточнює п. 1 ADR [0005](0005-harness-integration.md).

## Контекст

Ghost-текст, `Ctrl+Space`, `explain --llm`, `draft` і `code-to-spec` питають модель через `agent` у `keylang.json`. Досі це були лише API: `anthropic:` і `openrouter:` з ключем. Користувачі частіше мають підписку на Claude Code, Codex, opencode чи Cursor, а не API-ключ, і без ключа ці функції мовчать. ADR 0005 п. 1 казав, що keylang харнес не запускає.

## Рішення

1. **Харнес як текстова модель.** `agent` приймає `cli:<name>[:<model>]`. keylang запускає CLI лише як модель: один запит — один запуск, одна фінальна відповідь. Харнес як редактор файлів keylang і далі не запускає (п. 1 ADR 0005 у цьому сенсі лишається).
2. **«Лише відповідь».** Пресети `claude`, `codex`, `opencode`, `cursor` запускаються з вимкненими інструментами запису (read-only sandbox, режим `ask`, набір правил `deny`), без хуків, MCP, інструкцій і сесій проєкту там, де CLI це дозволяє. Інакше Stop-hook keylang (`keylang agents`) заблокував би вкладений хід. Прапорці перевірено з `--help` встановлених версій, версії записано в `docs/tools.md`.
3. **Відповідь перевіряється як відповідь API:** розбір ghost-рядка, звірка draft зі знімком, перевірка ID у поясненні.
4. **Пише лише keylang** — пропозиціями, MERGE чи `--apply`. П. 4 ADR 0005 не змінюється.
5. **Вибір агента.** `KEYLANG_AGENT` > `~/.config/keylang/agents.json` `"use"` > `keylang.json` `agent`. `cli:` у `keylang.json` діє (рішення Q1): спільна конфігурація може вибрати CLI. Наслідок для безпеки: відкрити TUI зі склонованим репозиторієм може запустити CLI користувача й витратити квоту. Тому `doctor` показує джерело значення, змінна й agents.json його перекривають, Cursor запускається без `--trust`, а власні команди задаються лише в agents.json, ніколи в `keylang.json` (команда в репозиторії була б кодом, що виконується від відкриття TUI).
6. **Процес.** Масив аргументів без shell, окрема група процесів, `cwd = PWD = корінь`, `KEYLANG_NESTED=1`. Під `KEYLANG_NESTED` `cli:*` недоступний — рекурсії немає. Рання відповідь, скасування й таймаут вбивають групу (SIGTERM, потім SIGKILL); вихід keylang вбиває всі живі групи.
7. **Модель у конфігу** не починається з `-` і не містить `--`, `<`, `>` і пробілів: вона йде окремим аргументом після `--model` і в заголовок `<!-- keylang:explain agent=… -->`.
8. **Тести** — фейкові CLI на PATH (`tests/fixtures/fake-agent.mjs`); справжні CLI — ручна перевірка для кожної нової версії.

## Розглянуті варіанти

- **Харнес редагує файли сам.** Ламає MERGE і п. 4 ADR 0005: зміна обходила б пропозиції.
- **Інтерактивний TUI харнеса через PTY.** Потребує native-коду (`node-pty`) і крихкий до змін інтерфейсу.
- **Claude Agent SDK.** Один вендор і важка залежність; не дає Codex, opencode, Cursor.
- **ACP** (`agent acp`, `opencode acp`). Єдиний протокол, але це протокол сесій із ширшим обсягом. Повернутися пізніше.
- **Вибір `cli:` лише на рівні користувача** (review H2). Відхилено рішенням Q1: значення з `keylang.json` діє, ризик закрито джерелом у `doctor`, перекриттям і пресетами без запису.

## Наслідки

- Секунди затримки на запит: типовий `ghost.delay` для CLI — 1500 мс, `explain --jobs` — 2.
- Квота підписки витрачається на ghost; новий ghost-запит вбиває попередній процес.
- Прапорці CLI змінюються між версіями: версії в `docs/tools.md` і `doctor`, помилки показують кінець stderr.
- Власний CLI keylang не обмежує; вкладений агент читає репозиторій і може прочитати секрети. Записано в `docs/tools.md`.
- Windows `.cmd`-обгортки без shell не запускаються; v1 — POSIX.
