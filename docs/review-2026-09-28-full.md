# keylang — повне рев'ю проєкту (M0–M7)

Дата: 2026-09-28. Охоплення: весь код на коміті `7cce8c2` (M5–M7), архітектурні рішення (design.md, ADR 0001–0003), специфікація (format.md) і документація. Метод: сім рецензентів по зонах (ядро мови; аналізатор TS/JS; Rust і Python; правила, потоки й докази; wiring і LLM; MCP, голос, LSP, пакування; TUI і web) плюс наскрізна перевірка ведучим. Кожну знахідку нижче відтворено на тимчасовій копії або скриптом; ті, що відтворив і ведучий, позначено ✔. Репозиторій не змінювався. Базовий стан: `npm run typecheck` — 0; `npm test` — 222/223 (1 пропущено: whisper без моделі); `keylang map --check` — 0; `keylang check --strict` — 0 fail, 0 unverified, 63 ok.

**P1** — хибний `ok`/`fail` основної перевірки, запис поза дозволеними цілями, падіння процесу на валідному вводі, непрацездатний артефакт. **P2** — хибний результат окремого правила чи функції, розбіжність із контрактом. **P3** — якість, шум, документація.

## Головне

1. **Соундність `static fail` порушено для Rust і Python.** Виклики через поле чи вираз (`self.db.save()`, `Order::new().total()`, `super().m()`, `f().m()`) не стають ні ребром, ні діркою `coverage`, тож `closure.complete` лишається `true`, а крок отримує `fail: absence` замість `unverified`. Для TS те саме дають `new ns.X()` і злиття `interface Foo` + `class Foo`. Контракт §4.2 («`fail` має бути надійним, за сумніву — `unverified`») не виконується.
2. **Trace-матчер жадібний.** Береться перший span тригера без бектрекінгу; будь-який ранній `return` перед «справжнім» викликом у `@flow`-тесті дає хибний `trace fail: missing step`.
3. **Хибний `ok` для `deny`:** вбудовані імена Node (`constants`, `events`, `util`, …) перемагають `tsconfig` `paths`/`baseUrl`; `lib.rs` + `main.rs` ділять один корінь; `deny` з ID функцій мовчки вакуумний.
4. **`spec-to-code --apply` пише поза репозиторієм** (через `..`, symlink чи абсолютний шлях у `test <file>`), бо перевірка `codeProposalProblem` виконується лише для пропозицій.
5. **npm-пакет не вміє Rust і Python:** `copy-wasm.mjs` копіює лише три граматики, а `treesitter.ts` після цього шукає всі граматики в `dist/wasm`.
6. **`keylang wire` генерує файл, що не компілюється** у трьох випадках: `.js.js`/`.mts→.js` під `nodenext`, колізія ID `a-b` / `a_b`, `compose` на модуль чи тип.
7. **`exports` порівнює з експортами всіх модулів-нащадків за префіксом ID**, тому `purchase.ts` поруч із `purchase/buy.ts` дає і хибний `fail`, і хибний `ok`; `export default <вираз>`, `export namespace`, `export =` не потрапляють у таблицю експортів.

## Архітектурні спостереження

1. **Інваріант «кожен виклик — ребро або дірка» ніде не закріплено.** У трьох extractor-ах `callOf` повертає `null` для незнайомої форми отримувача, і виклик зникає без сліду; `closure.complete` і `static fail` на цьому будуються. Один структурний fallback («форма невідома → `dynamic-call`») у кожному frontend закриває весь клас P1 у Rust/Python і `new ns.X()` у TS.
2. **Клас у знімку — «модуль, оголошений у файлі батька».** Евристику скопійовано тричі (`assess.ts`, `wire-gen.ts`, `explain-node.ts`), і вона ламається в `module: "dir"`; ім'я конструктора (`constructor`/`__init__`) зашито для JS у `flows.ts` і `graph.ts`. `kind: "class"` у вузлі знімка та ім'я конструктора в `Frontend` прибрали б обидва класи проблем.
3. **Класифікація голих специфікаторів — упорядкований ланцюжок if** (generated → relative → `#` → built-in → paths → baseUrl → package), а TS робить paths (найдовший префікс) → baseUrl → built-in/package. Через це вбудовані імена «з'їдають» аліаси.
4. **Зарезервовані імена не зарезервовано.** `external`, `unassigned`, ключові слова секцій і санітизація `layerName` (`foo.bar.ts` vs `foo_bar.ts`, `2fa` vs `_2fa`) аліасяться мовчки; колізії ID лікуються злиттям із попередженням, а не помилкою.
5. **Специфічність правил — сума довжин рядків**, не глибина сегментів: `deny app.purchase domain` (18) перемагає `allow app domain.store` (15) через кількість символів. `layers` і `entry` ніколи не дають `ok`, тож файл лише з ними показує `0 ok` і порожній жолоб.
6. **Рекурсивні обходи дерева в `extract/ts.ts`** (п'ять окремих повних проходів на файл) — і продуктивність, і падіння всього прогону на одному патологічному файлі. Ітеративний `TreeCursor` або guard `RangeError` → `opaque` для файла.
7. **Записи з CLI не атомарні.** `spec-to-code --apply`, `wire`, `writeProposal`, `stats.json` — прямий `writeFileSync`; лише MERGE у TUI робить tmp + rename і зберігає права та закінчення рядків.
8. **`hybrid`-звіряння чернетки — регекс по рядках**, не парсер: звідси лапки навколо ID, проза як тіло потоку, відсутній `trigger`. Спершу `parse`, потім звіряння на IR.
9. **Python `deny` майже ніколи не `ok`:** будь-який невідомий декоратор — `unsupported`, а `unsupported` входить у `DEPENDENCY_HOLES`, тож кожне `deny` над модулем із `@router.get` — `unverified`. Це чесно, але робить правила залежностей для FastAPI-репозиторіїв некорисними; варто відділити «декоратор може підмінити функцію» (дірка викликів) від дірок імпортів.
10. **MCP перебудовує повний аналіз на кожен виклик**, включно зі звітами й trace; на 900 файлів — ~2 с на виклик. Знімок, ключований manifest-хешами, зберіг би гарантію свіжості дешевше.
11. **`src/tui/app.ts` — 2 014 рядків, 87 методів**: редактор, MERGE специфікацій і коду, голос, ghost, панель контексту, палітра — в одному класі. Поділ «view — чиста функція» вдалий, сесія — god object.
12. **Опційні нативні модулі:** `optional()` вважає відсутнім лише `MODULE_NOT_FOUND`; будь-яка інша помилка завантаження валить `doctor` і `Ctrl+R`. Політика «будь-який збій завантаження — недоступно з причиною» закриває три знахідки разом.
13. **Граматики в двох списках** (`Grammar` у `treesitter.ts` і `copy-wasm.mjs`) розійшлися, щойно додали Rust/Python; тест tarball не запускає `map` на Rust/Python-фікстурах.
14. **TUI: `draw()` не знає, що екран не його.** Транспорт термінала має від'єднувати `surface` (або ставити прапорець) на час `$EDITOR` і SIGTSTP — один шов закриває весь клас «кадри поверх редактора».
15. **Асинхронні завершення (ghost, голос, чернетка) захоплюють `buffer`/`line`, а пишуть у `this.buffer()` на момент завершення.** Один guard «той самий буфер, режим, покоління» покриває три знахідки. Пропозиція не має ідентичності: MERGE, `u` і `Ctrl+Space` вважають `.keylang/proposals/<шлях>` «тією самою» — хеш вмісту, зафіксований на `m`, закриває перезапис і відкат не тієї версії. У `writeMerge` порядок побічних ефектів «запис → видалення пропозиції → метрики → стан» треба перевернути: метрики останніми й best-effort.
16. **Робота на клавішу пропорційна довжині рядка** (`keepVisible`, `drawRuns`, `columnAt` пересегментують рядок цілком); кешований масив графем/ширин на рядок, інвалідований на правці, робить довгі рядки лінійними.
