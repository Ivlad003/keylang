# keylang

[English](README.md) · **Українською**

![Ключ до розробки і розуміння проектів](docs/course/images/banner.png)

Мова опису архітектури, що живе в репозиторії як звичайний Markdown: згенерована карта шарів і модулів, написані вручну правила залежностей і потоки логіки, перевірені відносно коду. Навчальний посібник — [курс](docs/course/uk/README.md) ([English](docs/course/README.md)). Нормативна граматика — [`docs/format.md`](docs/format.md). Цільовий дизайн — [`docs/design.md`](docs/design.md); огляд статей — [`docs/research.md`](docs/research.md).

Стек: Node.js ≥ 22.18 і TypeScript. У цьому чекауті Node виконує `.ts` напряму (`node bin/keylang.js`). Перед публікацією `prepack` компілює `src/` у `dist/` і переписує відносні імпорти `.ts` на `.js`. Встановлений пакет завантажує цей JavaScript і нічого не компілює в користувача. Дистрибуція — npm / npx. Компіляції native-коду немає.

## Для якої задачі

Структура в репозиторії вже є. Зазвичай бракує короткого тексту, який рев'юять як код і який каже, який шар від якого може залежати, та перевірки, що падає, коли код розходиться з цим текстом. keylang — це цей текст разом із перевіркою.

| Задача | Як це робить keylang |
|---|---|
| Побачити репозиторій | `keylang map` пише `keylang/map/<шар>.md`: шари, модулі, функції, імпорти й виклики, з посиланнями на рядки коду |
| Прочитати, що робить кожен вузол | З `"explain": {"map": true}` у `keylang.json` `keylang map` пише ще й `keylang/map-explained/`: те саме дерево з поясненням в одне-два речення під кожним вузлом — з коментаря документації або збереженого brief від моделі з позначкою моделі й дати |
| Заборонити залежність | Ручний `keylang/rules.md` (`layers`, `allow`, `deny`, `entry`, `exports`, `no-cycles`) рахується на поточному знімку |
| Назвати сценарій | `# flow` перелічує тригер і кроки стабільними ID. Кожен крок звітує `ID`, `static`, `tests` і `trace` окремо |
| Тримати карту чесною в CI | `keylang map --check` дає код 1, коли закомічена карта застаріла. `keylang check` дає код 1 на порушенні |
| Дати агенту чернетку, а не перезапис | `draft`, `code-to-spec`, `spec-to-code` і MCP-інструмент `apply_diff` пишуть пропозицію в `.keylang/proposals/`. Людина зливає її по шматках |
| Перейти від імені до функції | Той самий аналіз обслуговує CLI, термінал, `keylang web`, LSP і MCP |

ID має вигляд `application.purchase.buy`. Це крапковий шлях від шару, а не номер рядка, тож специфікація переживає правки, які лише зсувають рядки.

## Чого він не робить

keylang перевіряє твердження про структуру і про докази, які ви до нього доклали. Він не вирішує, чи програма правильна, безпечна або закінчена.

- Опис під вузлом — проза. Його зберігають і форматують. Його не доводять. Перевірка «проза застаріла» спроєктована і не реалізована.
- Динамічний виклик, невідомий декоратор чи атрибут-макрос, `eval` або модуль, який frontend не прочитав, — дірка покриття. Вердикт — `unverified`: це не успіх і не порушення. Саме `--strict` перетворює `unverified` на код виходу 1.
- Frontend-и Rust і Python записують імпорти, виклики й реекспорти. Ребер типів вони не записують. Виклик, отримувача якого keylang не може назвати, лишається діркою.
- Wiring генерує TypeScript-функцію `wire()`. Він не генерує Rust і не забороняє решті програми імпортувати що завгодно. Це мають ловити правила залежностей.
- Пояснення LLM або накинутий потік — походження, не доказ. `check` не трактує їх як свідчення.
- keylang читає звіти тестів і trace. Він не замінює тест-ранер, перевірку типів чи рев'ю безпеки.
- Мови поза TypeScript, JavaScript, Python і Rust не індексуються. Файл іншою мовою відсутній у знімку, і це не доказ, що в нього немає залежностей.

## Сильні сторони і ціна

**Сильні сторони**

- Специфікації — це Markdown. GitHub їх показує, а рев'ю — звичайний diff.
- Згенерована карта і ручні специфікації — різні файли. `keylang map` не перезапише файл без маркера `keylang:generated`.
- Один аналіз (`analyze()`) годує CLI, LSP, термінал, браузер і MCP, тож позначка в жолобі й рядок у CI — той самий вердикт.
- Брак доказів лишається `unverified`. Інструмент не підвищує прогалину до «ok».
- Записи агента лежать у `.keylang/proposals/`, доки людина не прийме шматок.
- Встановлення не компілює native-код. Голос опційний.

**Ціна**

- Граматика — вузький зріз Markdown. Ключові слова значать різне залежно від батьківського рядка. Повне вкладення CommonMark (code fence усередині елемента списку) не підтримується.
- ID доводиться оновлювати самому, коли модуль перейменовують або переносять між шарами.
- Карта — це вигляд «модулі й залежності». Вона не описує розгортання, форми даних і причини рішення. Це місце прози або ADR.
- Корисний доказ потоку понад «цей ID існує і до нього є статичний шлях викликів» потребує звіту тестів і trace з того самого знімка. Застарілий trace — це `unverified`, як на знімках нижче.
- Чотири мови, кожна з явними сліпими зонами. Інші мови поза обсягом.
- Код виходу 0 означає «немає блокувальної знахідки». Без `--strict` він усе ще дозволяє `unverified`.

## Знімки

Знято з цього репозиторію командою `node bin/keylang.js web` 2026-09-28 і CLI на `examples/shop`. Trace і звіт `node:test` у `.keylang/` були старіші за знімок, тому докази trace і тестів — `unverified`. Це очікуваний результат. Рядок стану рахує рядки (найгірша позначка рядка). `keylang check` рахує кожен результат доказу, тож той самий запуск друкує `0 fail, 22 unverified, 43 ok`, а інтерфейс показує `✗ 0  ◌ 22  ✓ 11`.

Правила цього репозиторію з пройденим жолобом. Ядро мови (`lang`, `base`) і перевірка не мають залежати від екстрактора чи від tree-sitter:

![Правила з пройденим жолобом і деревом шарів](docs/course/images/tui-rules.png)

Потік `check`. Рядок курсора розгортається в окремі позначки `ID`, `static`, `tests` і `trace`. Тут ID точний, статичного батька для доведення немає, а файл trace від старішого знімка:

![Потік check із жолобом доказів](docs/course/images/tui-flow.png)

`K` (або наведення мишею) показує сигнатуру, файл, докази і кілька рядків оголошення:

![Hover на cli.cli.main](docs/course/images/tui-hover.png)

Приклад зі слайдів навмисно тримає хибний ID. Знімка коду немає, тож потік теж не доводиться. Код виходу — 1:

![check examples/shop повідомляє K001](docs/course/images/cli-shop-k001.png)

Решта знімків (довідка, згенерована карта, режим читання, переглядач коду, палітра, список файлів, `explain`) — у [уроці 8](docs/course/uk/08-use-cases.md).

## Встановлення і перший запуск

Достатньо Node.js ≥ 22.18.

```sh
npx keylang init .      # вгадати шари, записати keylang.json, зібрати карту
npx keylang check       # ID і правила в keylang/
npm i -g keylang        # далі просто `keylang …`
```

З цього чекауту:

```sh
npm install
node bin/keylang.js init path/to/repo
node bin/keylang.js map                  # переписати keylang/map/*.md і .keylang/index.json
node bin/keylang.js map --check          # CI: код 1, якщо карта застаріла
node bin/keylang.js check                # ID, правила й потоки; нічого не пише
node bin/keylang.js check --strict       # unverified стає порушенням
node bin/keylang.js explain K001         # що означає код і як виправити
node bin/keylang.js explain cli.cli.main # що знімок каже про ID
node bin/keylang.js                      # TUI в терміналі (? — клавіші, q — вихід)
node bin/keylang.js web                  # той самий UI в браузері; відкрийте надрукований URL
```

Коди виходу: `0` — немає блокувальної знахідки, `1` — порушення (або застаріла карта з `--check`, або будь-який `unverified` з `--strict`), `2` — хибний виклик або I/O. `parse --json` пише в stdout лише JSON. `check` пише знахідки в stdout, а підсумок — у stderr.

`examples/shop` — приклад зі слайдів із хибним ID `domain.aggregate`. `examples/shop-fixed` його виправляє. У жодній теці немає названого там TypeScript, тож правила там `unverified` (`no snapshot`), і перевірка з виправленим ID все одно завершується кодом 0:

![shop-fixed завершується кодом 0 з unverified](docs/course/images/cli-shop-fixed.png)

Курс проводить через мову, правила, потоки й ці команди разом зі знімками: [docs/course/uk](docs/course/uk/README.md).

## Що реалізовано

Деталі етапів — у [`docs/design.md`](docs/design.md) §9, нормативна поведінка — у [`docs/format.md`](docs/format.md). Коротко:

- **M0.** Формат, парсер Markdown → IR з позиціями, резолвінг ID між файлами, діагностики K001–K006, `keylang fmt`. Публічний API — `src/index.ts`. Ядро мови не імпортує tree-sitter.
- **M1.** Карта й перевірка правил для TypeScript і JavaScript (ESM і CommonJS). Факти беруться з `web-tree-sitter` і wasm-граматик `@vscode/tree-sitter-wasm`. Резолвінг імпортів покриває відносні шляхи, `tsconfig` `paths` / `baseUrl` / `extends`, `package.json` `imports`, пакети й вбудовані модулі Node. Правила дають K101–K105. Цей репозиторій описує себе в `keylang.json` і `keylang/`; `keylang check` у корені не має порушень.
- **M2–M3.** `# flow` з окремими доказами `ID`, `static`, `tests` і `trace`, три вердикти (`ok`, `fail`, `unverified`), вузли `planned` (K201/K202). `analyze()` спільний для CLI, LSP, MCP і TUI, з кешем фактів у `.keylang/`. `keylang lsp` і тонкий клієнт VS Code в `editors/vscode/` (у Marketplace не опублікований і в npm-пакет не входить).
- **M4.** TUI в терміналі й `keylang web` (xterm.js через WebSocket, токен доступу, перепідключення). Сирий Markdown із жолобом, hover мишею і `K`, перехід у код, редагування з доповненням, `Ctrl+G` text → spec, злиття пропозицій по шматках.
- **M5.** Rust (крейти, `use`, `pub use`) і Python (пакети, `__all__`) на тому самому графі, з явними межами. Trace-адаптери в `adapters/python` і `adapters/rust`. `keylang trace-plan <flow>` друкує, що інструментувати.
- **M6.** `# wiring` і `keylang wire`: типізований `wire()` у `keylang.gen.ts`, що будує кожну фабрику раз, залежності першими, з async init/dispose і відмовою на циклах ([ADR 0003](docs/adr/0003-wiring-lifecycle.md)).
- **M7.** `draft`, `code-to-spec`, `spec-to-code`, `explain <id> --llm` як пропозиції. `keylang mcp` для агентів (`apply_diff` пише лише пропозицію). Опційний голос (`Ctrl+R`). `keylang doctor` звітує мови, облікові дані агента й голос і нічого не змінює.

`bench/` ганяє інструмент на восьми репозиторіях; числа — у [`bench/results.md`](bench/results.md).

## Тести

```sh
npm test            # node:test, наскрізні тести CLI
npm run typecheck   # tsc --noEmit
```

TUI перевіряється без TTY (`tests/tui.test.ts`). `keylang web` — через справжній CLI і WebSocket (`tests/web.test.ts`).

Публікація з чистого чекауту: `npm test && npm run typecheck`, далі `npm version patch` (або minor/major) і `npm publish`. `prepack` збирає `dist/`. Перед публікацією перевірте архів через `npm pack`.
